# Atlas 每日巡检协议（duty-review）

维护者当前投入在 atlas 上的时间很少；大量 issue 由 AI 提出、AI 评审、再按 AI 自己的推荐拍板，闭环里没有「人拍板」这个环节。时间一长会积出四类病：

1. **同阶段问题反复出现**（同类缺陷改了又改、始终不收敛）；
2. **前后决议打架**（新改动悄悄覆盖旧行上已定的裁决）；
3. **已决案被反复重开**（已否决 / 已收窄的方案换个措辞再上桌）；
4. **建议被静默吸收**（没人反对就默认按推荐走了）。

本协议定义一个**每日巡检器**：每天自动跑一次，只读收集信号，把满足「拍板判据」的极少数条目写进 `duty-review/QUEUE.md` 递给维护者；其余一律不进拍板面。想随时手动跑一次，直接说「巡检」即可（按本协议深看）。

## 1. 角色与边界（硬）

巡检器（无人值守，定时或闲时跑）：

- **只读分析**。可写文件仅限两个：`duty-review/QUEUE.md`（待拍板 / 观察室 / 归档与废案三区增删）与 `duty-review/bugs.md`（存量 bug 库）。**不写巡检记录日志**（2026-10-16 维护者定：不看存档）——运行状态只在 QUEUE 文件尾留一行 `<!-- 机器状态行 -->`（时间戳，给下次运行算 since 用），不占人读面。
- 不修改代码 / 契约 / 文档 / issue / 知识库；**不跑任何会写盘的生成器**（`refresh_structure --apply`、`gen_e2e_scripts --apply`、图谱通道等——它们都会往仓库或项目根落文件）；不 `git commit` / `push`；不创建或关闭 GitHub issue；不铸造新编号；不创建或修改自动化任务。
- 本协议**不改变**「缺漏当场修，不请示」的交互会话常规（有人在场时照旧）——巡检器只是「无人代行」边界的固化：**你不在场时，没人替你改任何东西**。
- 巡检器发现本协议自身有洞 ⇒ 只在 QUEUE.md 观察室记一行「协议改正建议」，不自己改协议（协议只由交互会话改）。

## 2. 拍板判据（DR1–DR5）

满足**任一条**的候选才进「待拍板」区，并注明命中哪条：

- **DR1 重案**：想推翻 / 重新解释一条已落地的裁决（`DESIGN.md` §12 决策行、其行内 ④「不采」、收窄注记）——必须同时给旧行号 + **新证据**；缺一进废案区。
- **DR2 语义**：要定契约语义（新增 / 删除门，gates 或环契约的条款面，范围归属）而现有证据与惯例不足以自决。
- **DR3 取舍**：两个方向都合理且代价可感（发版节奏、门档位、产品边界类取舍）。
- **DR4 复发**：同类问题 30 天内复发 ≥3 次（输入 = fix 类提交聚焦同一文件 / 目录 ≥3 条，或同一失败形态多次出现）——需要立机器门或契约条款才能收敛。**操作化口径 A（2026-10-17，建议②拍板落地）**：聚类单元 = **fix 类提交触达的文件路径**，30 天内同路径 fix ≥3 条即达标（信号脚本已按 fix/修/红/回归 词过滤，见 §4）；「同一失败形态」的形态级升判仍留人。**口径 B（段级族规模，2026-10-17 维护者拍板「B」落地）**：聚类单元 = `bugs.md` 的**段 + 段首「同根归纳」行**；计数 = 段内出现的 `#NN` **去重数**（**上界近似**：含条目、归纳行、交叉引用——判据只问「够不够 3」，精确分案归人）；**升室判据 = 同根归纳在案 ∧ 案数（上界）≥3 ∧ 段内最近日期落在近 30 天**（= 这族**近来还在长**）；三项齐 ⇒ QUEUE 观察室一行（段名 / 计数 / 最近日期），由维护者按「立机器门 / 改契约 / 判单修可接受」拍板。**只满足前两项（无日期取证 / 超窗）⇒ 记「族已静默」不升室**——同一族已清算完却天天喊，就是把红灯训练成噪声（本仓旧教训，故设活跃窗）。**与口径 A 的关系**：A 判**复发速率**（30 天窗口内同一路径被反复改 = 既有修法没收敛），B 判**族规模**（同一病根已积几案）——互补，不互相替代。**明示盲区**：① **跨段同族机器串不起来**（靠条目里手写的「同族复发」交叉引用，且必须在**被指段落也留一行**，否则机器看不见）；② 段是人工按环分的，分段漂 ⇒ 计数跟着漂；③ `bugs.md` 无日期字段（**2026-10-26 D154 收窄**：新条目可带 `〔日期 …〕` 字段，见下「条目字段制式」；无字段旧条目的日期取证 = 行内散文，仍在盲区面）。**D155 再收窄一层，同时留一条新的显式盲区**：带字段条目已校「日历合法性 + 不晚于当日」（越界 ⇒ WARN + 回退），但**无字段条目的行内散文日期仍不校这两关**——真实库实测（2026-10-26）日历非法 0 条 / 未来日期 0 条 ⇒ 不翻存量判据，故本批不扩面；**升档条件** = 库内出现一条**因散文非法 / 未来日期而判面翻错**的实例（可 grep + `families.py` 输出复算），届时按 DR2 另批落刀，不静默扩大语义。

**条目字段制式（2026-10-26，D154，维护者拍「A」照 `proposals/RFC-20261026-04` v2 落刀；独立评审 = `proposals/REVIEW-20261026-07`「修后通过」）**：新条目行尾**必带**尾缀块 `〔…〕`——键以 `｜` 分隔，闭集键 = `日期`（必填，落账当天）/ `状态`（`开放`｜`已修·待复验`｜`已出库`）/ `族`（跨段同根族标识，**只解析记录、不参与判据**——升档条件 = 库内出现第 2 个跨段同族同名实例）/ `证`（D131 证明件锚；优先级 = `DESIGN.md` D 决策行 > M 变异号/钉名 > 留档路径辅注——`.atlas-run/` 留证会被 Playwright 起跑清空，留档路径只作辅助）。坏形状（未知键/重复键/值空/值域外/日期形态非法/**日期日历非法**/**日期晚于当日（越界）**/缺日期/尾缀不闭合）⇒ `duty-review/families.py` **运行面 WARN** + 按无字段回退，不静默。**「形态过正则」不等于「是可用日期」**：`2026-13-40` / `2027-01-01` 满足 `20\d\d-\d\d-\d\d` 却会静默抬活跃窗（未来日期 ⇒ 该段永久「升室候选」），故形态之外再加日历关与未来关（2026-10-26，D155，`proposals/RFC-20261026-05`）。活跃窗日期来源**分层**：带字段条目 = 字段日期；无字段条目行 = 行内散文日期；**段头/归纳行/收尾说明等其余行不再抬窗**。**判据三项与「案数上界」计量基准原样**（上界含条目/归纳行/交叉引用——README:28 原拍板；上界 ⇄ 精确的重议 = DR1 另案，旧行号 = 本行 + `DESIGN.md` D102）；`render` 增「精确病案数」展示列（只对带字段条目计，不参与判据）。机器面 = `duty-review/families.py` 单源 + `tests/test_duty_bug_families.py` **19 条**（形状/真值表 4 + D154 字段制式 7 + D155 日期越界 7 + D156 指针行 1；变异 M91 承前 + M157a/M157b + M158a/M158b/M158c）。

**系统性修复的闭族三态（2026-10-26，D156，`RFC-20261026-03` Phase 1）**：`闭族` = 子族锚在案 ∧ 系统性修复已落 ∧ 留出验证通过（pre-fix 红 → post-fix 绿）∧ 反面包红；`未闭族` = 留出失败（如实记录；子族仍在库中则保持观察）；`单案修复（无留出集）` = 允许，但须独立评审确认「确无可行留出集」+ QUEUE 观察室一行 owner / 补验期限（默认下一次相关变更前）+ 残留风险写进那份 RFC §4.5，**不得宣称闭族**。**留出独立性三条**（缺一按「同夹具变体」驳回，独立评审当场重放、不由作者自证）= ①判据输出翻转 ②变异增量杀伤 ③结构不可达（正文 = `shared/gates.md` §2.5 本行 + `proposals/README.md` §2）。**唯一判定记录 = 那份 RFC §4.5 + 其 REVIEW**（不新增台账）；`bugs.md` 指针行格式 = `- 留出验证：RFC-… / REVIEW-…`——**无状态 / 无日期 / 无 `#NN`**（指针行不污染段级信号；形状钉 = `tests/test_duty_bug_families.py` 19 条里的指针钉）。
- **DR5 人手**：需要维护者的操作 / 资源（拉起应用、授权、外部资产）。

不满足任一判据 ⇒ **不进待拍板区**：机械 bug 留给下一次交互会话跟进；可当场判断的观察项进观察室；其余什么都不留。

**待拍板容量 ≤ 5 条**；超出按信号强度排序，后进观察室。

- **逃逸缺陷追问与评测闭环（2026-10-21，D131）**：每个确认的逃逸缺陷，若属于“某道门本该接住却没接住”，在 `bugs.md` 必须标明 `[逃逸: 哪一道门未接住与根因]`，并在关闭出库前必须同时补齐：
  1. 一条能稳定复现原问题的 E2E 回归用例（红→绿闭环）；
  2. 若对应某道门禁或校验器，一条 M 系列变异钉（证明脏数据下门会报红），将现场事故转化为永久评测集。

## 3. QUEUE.md 的形态

- 文件尾机器状态行（`<!-- … -->` 注释，人不读）：只更新时间戳等运行参数，无叙述性日志。QUEUE 三区的既有条目**不删**（归纳 = 移动 + 标日期）；**bugs.md 例外：按出库条件删除是正常动作**——维护者已明示「完全确认修好即清除，库我不看」。
- 三区：**待拍板** / **观察室**（够不上判据但值得盯：一行一条，必须带「升室→出室」条件）/ **归档与废案**（含重开请求被拒时的原话）。
- 待拍板条目固定六件套：
  1. **判定**：DRx；
  2. **现象与证据**：file:line / commit / issue，全部带出处；
  3. **关联存量**：已落裁决（`DESIGN.md` §12 行号）或存量 issue（#号）——若有，给号 + 现行结论一句话；
  4. **AI 建议**：默认动作是什么；
  5. **反方声音**：为什么可能不该这么办（每条必写，哪怕短）；
  6. **你的选项**：A / B / …，并标出「默认（不回也不动）」。
- 结案只有两条路：(a) 维护者拍了（**原话入档**）；(b) 仓内证据自己出面（指名具体 commit / 行号说明该案已被另一批落地）。**你不回 = 保持现状**——任何建议都不会因为沉默自动落地。
- **留出验证指针与「单案修复」观察行（2026-10-26，D156）**：`bugs.md` 的「留出验证」指针行只按 §2 格式挂（无状态 / 无日期 / 无 `#NN`）；QUEUE 观察室只为「单案修复（无留出集）」留一行**案号指针**（owner + 补验期限），不复述闭族状态（唯一判定 = 那份 RFC §4.5 + 其 REVIEW）。
- 每案落地说明「生效会写到哪」（`DESIGN.md` §12 新决策行 / `shared/gates.md` 登记行 / 哪份契约）——沿既有口径：**条款必须指名载体**，没有机器判据的就如实登记为纪律与盲区面，不假装是门（2026-10-15 v2 抽取口径）。
- **回执状态（2026-10-24，设计优化 v2 WS-C 收窄版）**：巡检只在机器状态行记一行事实计数「最久未回执案情：案 N，已呈 M 天」；**沉默 = 维持现状**（本节上文契约），不点名催办、不立 ack 义务——「未读」机器不可知，诚实叫法 = **未回执**（「断言无证 = 失职」同源纪律）。

## 4. 信号源（铁则：全部只读）

跑 `bash scripts/duty_signals.sh "<上次巡检日期>"`（或按其命令清单手工取数）；脚本不落任何文件：

- 新增 commit（自上次巡检）、当前脏文件；
- 30 天 **fix 类**提交触达文件清单（DR4 复发聚类的输入；按 fix / 修 / 红 / 回归 词过滤——2026-10-17 建议③落地）；
- `bugs.md` **同根段聚类**（**DR4 口径 B** 输入，2026-10-17）：实现 = `duty-review/families.py`（口径 B 的**单源**；`duty_signals.sh` 调它，形状钉在 `tests/test_duty_bug_families.py`）。逐段出「同根归纳有无 / 案数（上界）/ 最近日期 / 判定」，**升室三项**见 §2 DR4 口径 B。
- GitHub issue 监视面 = **open 全列 + closed 全索引 + closed 近 14 天有动静的条目**（一次 `state=all` 调用，gh 缺席走公开 API）。**closed issue = 存量 bug 库**：每轮新信号（新 issue、新 fix 提交、新失败形态）都要与它比对——比对是必做动作，不限于 issue 对 issue。命中三种定性：① **同病重报 / 复发**（旧修法没堵住或回归）⇒ 计入 DR4 复发计数；② **新修法与旧案修法或旧裁决矛盾** ⇒ DR1 重案候选（旧行号 + 新证据）；③ 无命中 ⇒ 正常流。closed 条目自身的动静（重开 / 关后新评论，updated_at 晚于上次巡检）= 直接升室信号，点进去看最后一条评论再定性。死寂条目不逐条重读正文（防结案史变噪声），但**作为对照库逐轮在场**（全索引常驻输出）；重开旧案仍受 DR1 约束（旧行号 + 新证据）。
- `DESIGN.md` §12 尾部新增决策行、§13/§14 未决清单变化、`shared/gates.md` 新增 / 变动登记行、`CHANGELOG.md` 新批次段（脚本会指出哪些台账文件被动过，正文由巡检器直接读）；
- 存量产物（如采纳项目的 `.atlas-run/` 报告、`_support/reviews/`）——**存在才读，不跑生成器**。

深浅节律：无新增信号 ⇒ 只刷新 QUEUE 文件尾机器状态行，报告一行「今日无事」；信号量大（≥20 新提交 / 有新 open issue / 首见同型复发）⇒ 深看全文。

**新 bug 的入路与出库（2026-10-16 按「bug 越来越多、按环分类」定）**：发现新 bug 先按环归入 `bugs.md` 对应分类（structure 逆向 / E2E / 安装与装配 / 图谱 / 自感知上报…），再与**同环存量**比对——只跟同环的比，跨环不同病（跨环比对 = 噪声）；同环多案同根 ⇒ 段首留一行「同根归纳」当比对锚。出库 = **完全确认修复后当场删除**：机器面缺陷（文本 / 解析 / 门）= 全量测试绿 + 变异即红还原一致即算确认；运行面缺陷 = 下一轮真跑或等价实测复验通过才算确认。库是工作面不是台账——正式记录永远在 `DESIGN.md` §12 / `shared/gates.md` / CHANGELOG，出库不抹史。
- **条目字段落账（2026-10-26，D154）**：新案行尾必带 `〔日期 YYYY-MM-DD｜…〕` 尾缀（制式 = §2「条目字段制式」；`证` 锚优先级 = D 决策行 > M 变异号/钉名 > 留档路径辅注）。**本节 = 巡检 automation prompt 的仓内裁决面**——ZCode 侧 prompt 文本不在仓内，改写纪律以本节为准。

## 5. 报告格式（每次运行的最终输出）

**只讲需要你的人的事**：待拍板区有变化（新增 / 结案 / 改判）才说话——逐条列标题 + 一句判定 + 选项；无变化就一行「今日无事」。不输出信号摘要、库的存取流水——那些自己落在 QUEUE / bugs.md，不用人看。QUEUE 与 bugs.md 的日常写盘是预授权的，不再逐次报备。

## 6. 术语与出处纪律

- 人话优先；术语第一次出现随行解释（仓内既定纪律）。
- 每句结论必须带出处（file:line / commit / issue）。断言「已修复 / 已决定」必须给出编号或 commit；无证断言 = 失职。
- 巡检器不发明编号体系；引用一律用仓内已有号（D / F / M / R / issue #）。队列条目用「案 1 / 案 2…」是给答话用的临时标记，不是台账编号，不进 ledger。

## 7. 本协议怎么改

协议与信号收集脚本只由交互会话修改。巡检器的协议改正建议 = 观察室一行；维护者拍板后由交互会话改并登记。
