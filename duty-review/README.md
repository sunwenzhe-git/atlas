# Atlas 每日巡检协议（duty-review）

维护者当前投入在 atlas 上的时间很少；大量 issue 由 AI 提出、AI 评审、再按 AI 自己的推荐拍板，闭环里没有「人拍板」这个环节。时间一长会积出四类病：

1. **同阶段问题反复出现**（同类缺陷改了又改、始终不收敛）；
2. **前后决议打架**（新改动悄悄覆盖旧行上已定的裁决）；
3. **已决案被反复重开**（已否决 / 已收窄的方案换个措辞再上桌）；
4. **建议被静默吸收**（没人反对就默认按推荐走了）。

本协议定义一个**每日巡检器**：每天自动跑一次，只读收集信号，把满足「拍板判据」的极少数条目写进 `duty-review/QUEUE.md` 递给维护者；其余一律不进拍板面。想随时手动跑一次，直接说「巡检」即可（按本协议深看）。

## 1. 角色与边界（硬）

巡检器（无人值守，定时或闲时跑）：

- **只读分析**。可写文件仅限两个：`duty-review/QUEUE.md`（待拍板 / 观察室 / 归档与废案三区增删）与 `duty-review/bugs.md`（存量 bug 库）。**不写巡检记录日志**（2026-10-16 维护者定：不看存档）——运行状态只在 QUEUE 文件尾留一行 `<!-- 机器状态行 -->`（时间戳，给下次运行算 since 用），不占人读面。
- 不修改代码 / 契约 / 文档 / issue / 知识库；**不跑任何会写盘的生成器**（`refresh_structure --apply`、`gen_e2e_scripts --apply`、图谱通道等——它们都会往仓库或项目根落文件）；不 `git commit` / `push`；不创建或关闭 GitHub issue；不铸造新编号；不创建或修改自动化任务。
- 本协议**不改变**「缺漏当场修，不请示」的交互会话常规（有人在场时照旧）——巡检器只是「无人代行」边界的固化：**你不在场时，没人替你改任何东西**。
- 巡检器发现本协议自身有洞 ⇒ 只在 QUEUE.md 观察室记一行「协议改正建议」，不自己改协议（协议只由交互会话改）。

## 2. 拍板判据（DR1–DR5）

满足**任一条**的候选才进「待拍板」区，并注明命中哪条：

- **DR1 重案**：想推翻 / 重新解释一条已落地的裁决（`DESIGN.md` §12 决策行、其行内 ④「不采」、收窄注记）——必须同时给旧行号 + **新证据**；缺一进废案区。
- **DR2 语义**：要定契约语义（新增 / 删除门，gates 或环契约的条款面，范围归属）而现有证据与惯例不足以自决。
- **DR3 取舍**：两个方向都合理且代价可感（发版节奏、门档位、产品边界类取舍）。
- **DR4 复发**：同类问题 30 天内复发 ≥3 次（输入 = fix 类提交聚焦同一文件 / 目录 ≥3 条，或同一失败形态多次出现）——需要立机器门或契约条款才能收敛。**操作化口径（2026-10-17，建议②拍板落地）**：聚类单元 = **fix 类提交触达的文件路径**，30 天内同路径 fix ≥3 条即达标（信号脚本已按 fix/修/红/回归 词过滤，见 §4）；「同一失败形态」的形态级升判仍留人。
- **DR5 人手**：需要维护者的操作 / 资源（拉起应用、授权、外部资产）。

不满足任一判据 ⇒ **不进待拍板区**：机械 bug 留给下一次交互会话跟进；可当场判断的观察项进观察室；其余什么都不留。

**待拍板容量 ≤ 5 条**；超出按信号强度排序，后进观察室。

## 3. QUEUE.md 的形态

- 文件尾机器状态行（`<!-- … -->` 注释，人不读）：只更新时间戳等运行参数，无叙述性日志。QUEUE 三区的既有条目**不删**（归纳 = 移动 + 标日期）；**bugs.md 例外：按出库条件删除是正常动作**——维护者已明示「完全确认修好即清除，库我不看」。
- 三区：**待拍板** / **观察室**（够不上判据但值得盯：一行一条，必须带「升室→出室」条件）/ **归档与废案**（含重开请求被拒时的原话）。
- 待拍板条目固定六件套：
  1. **判定**：DRx；
  2. **现象与证据**：file:line / commit / issue，全部带出处；
  3. **关联存量**：已落裁决（`DESIGN.md` §12 行号）或存量 issue（#号）——若有，给号 + 现行结论一句话；
  4. **AI 建议**：默认动作是什么；
  5. **反方声音**：为什么可能不该这么办（每条必写，哪怕短）；
  6. **你的选项**：A / B / …，并标出「默认（不回也不动）」。
- 结案只有两条路：(a) 维护者拍了（**原话入档**）；(b) 仓内证据自己出面（指名具体 commit / 行号说明该案已被另一批落地）。**你不回 = 保持现状**——任何建议都不会因为沉默自动落地。
- 每案落地说明「生效会写到哪」（`DESIGN.md` §12 新决策行 / `shared/gates.md` 登记行 / 哪份契约）——沿既有口径：**条款必须指名载体**，没有机器判据的就如实登记为纪律与盲区面，不假装是门（2026-10-15 v2 抽取口径）。

## 4. 信号源（铁则：全部只读）

跑 `bash scripts/duty_signals.sh "<上次巡检日期>"`（或按其命令清单手工取数）；脚本不落任何文件：

- 新增 commit（自上次巡检）、当前脏文件；
- 30 天 **fix 类**提交触达文件清单（DR4 复发聚类的输入；按 fix / 修 / 红 / 回归 词过滤——2026-10-17 建议③落地）；
- GitHub issue 监视面 = **open 全列 + closed 全索引 + closed 近 14 天有动静的条目**（一次 `state=all` 调用，gh 缺席走公开 API）。**closed issue = 存量 bug 库**：每轮新信号（新 issue、新 fix 提交、新失败形态）都要与它比对——比对是必做动作，不限于 issue 对 issue。命中三种定性：① **同病重报 / 复发**（旧修法没堵住或回归）⇒ 计入 DR4 复发计数；② **新修法与旧案修法或旧裁决矛盾** ⇒ DR1 重案候选（旧行号 + 新证据）；③ 无命中 ⇒ 正常流。closed 条目自身的动静（重开 / 关后新评论，updated_at 晚于上次巡检）= 直接升室信号，点进去看最后一条评论再定性。死寂条目不逐条重读正文（防结案史变噪声），但**作为对照库逐轮在场**（全索引常驻输出）；重开旧案仍受 DR1 约束（旧行号 + 新证据）。
- `DESIGN.md` §12 尾部新增决策行、§13/§14 未决清单变化、`shared/gates.md` 新增 / 变动登记行、`CHANGELOG.md` 新批次段（脚本会指出哪些台账文件被动过，正文由巡检器直接读）；
- 存量产物（如采纳项目的 `.atlas-run/` 报告、`_support/reviews/`）——**存在才读，不跑生成器**。

深浅节律：无新增信号 ⇒ 只刷新 QUEUE 文件尾机器状态行，报告一行「今日无事」；信号量大（≥20 新提交 / 有新 open issue / 首见同型复发）⇒ 深看全文。

**新 bug 的入路与出库（2026-10-16 按「bug 越来越多、按环分类」定）**：发现新 bug 先按环归入 `bugs.md` 对应分类（structure 逆向 / E2E / 安装与装配 / 图谱 / 自感知上报…），再与**同环存量**比对——只跟同环的比，跨环不同病（跨环比对 = 噪声）；同环多案同根 ⇒ 段首留一行「同根归纳」当比对锚。出库 = **完全确认修复后当场删除**：机器面缺陷（文本 / 解析 / 门）= 全量测试绿 + 变异即红还原一致即算确认；运行面缺陷 = 下一轮真跑或等价实测复验通过才算确认。库是工作面不是台账——正式记录永远在 `DESIGN.md` §12 / `shared/gates.md` / CHANGELOG，出库不抹史。

## 5. 报告格式（每次运行的最终输出）

**只讲需要你的人的事**：待拍板区有变化（新增 / 结案 / 改判）才说话——逐条列标题 + 一句判定 + 选项；无变化就一行「今日无事」。不输出信号摘要、库的存取流水——那些自己落在 QUEUE / bugs.md，不用人看。QUEUE 与 bugs.md 的日常写盘是预授权的，不再逐次报备。

## 6. 术语与出处纪律

- 人话优先；术语第一次出现随行解释（仓内既定纪律）。
- 每句结论必须带出处（file:line / commit / issue）。断言「已修复 / 已决定」必须给出编号或 commit；无证断言 = 失职。
- 巡检器不发明编号体系；引用一律用仓内已有号（D / F / M / R / issue #）。队列条目用「案 1 / 案 2…」是给答话用的临时标记，不是台账编号，不进 ledger。

## 7. 本协议怎么改

协议与信号收集脚本只由交互会话修改。巡检器的协议改正建议 = 观察室一行；维护者拍板后由交互会话改并登记。
