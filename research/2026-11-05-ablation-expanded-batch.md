## 1. 载体与协议

### 1.1 为什么用副本

- 7 条内联行没有独立校验器文件，摘除必须改 `.atlas/scripts/atlas_check.py`。直接改主快照被运行策略拒绝（目标仓「严禁任何 git 写操作」为硬边界，且原始任务对本段指定的载体是 `/tmp` 整树副本）。
- 因此主快照**只做只读核验**；所有摘除/投放/还原都在副本。副本是一次 `rsync` 复制，业务组与 `.atlas` 组哈希与主快照逐组相同（§8.2），差异仅在于「无 `.git`、无 `node_modules`、路径前缀」。

```
rsync -a --exclude node_modules --exclude .git <主快照>/ <副本>/
# ⇒ 40 MB；product / src / .trellis/spec/conventions / .atlas/{validators,scripts,tests}
#    组哈希与主快照逐组相同
```

### 1.2 摘除方式（手工 sha256 协议）

对每条行，取其所在函数，注释掉该函数内**全部** `rows.add(...)` 语句并在原位置补 `pass`（否则 `if/elif` 空块会 SyntaxError）。副作用代码（生成器调用、报告解析、claim 扫描等）保持执行，只有「行」被摘掉。

```
cp inline/I-0N.py <副本>/.atlas/scripts/atlas_check.py   # 投放
python3 .atlas/scripts/atlas_check.py --root . --fast --json > I-0N.json
cp base/atlas_check.py.bak <副本>/.atlas/scripts/atlas_check.py   # 还原
shasum -a 256 .atlas/scripts/atlas_check.py              # 与基线 90d0cdec… 比对
shasum -a 256 .atlas/validators/*.py                     # 与装后基线逐文件比对
```

每轮实跑输出（`rounds.txt`）：

```
I-01 … I-07：run-rc=0 rows=16 restore: atlas_check=IDENTICAL validators=IDENTICAL
```
