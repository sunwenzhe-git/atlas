# 弱点留出盲区盘点：「触发靠自述可被逃」

> **性质**：`research/` 工作留痕，非 canonical、不进装配、不作执行契约。
> **日期**：2026-11-01。**对象**：`D156` 系统性修复的留出验证触发 (b)（`DESIGN.md:631`、`shared/gates.md` §2.5、`shared/closeout.md` 步骤 3、`shared/independent-review.md` §9）。
> **结论先行**：**不新增机器判据/硬门**；把取证从「作者自述结论」硬化为「原始命令输出 + 评审自行复跑并留原文」。语义映射仍归人判，维持 D156「不假装是门」的口径。

## 1. 机制现状（D156 触发 (b)）

触发 (b)：改门 / 校验器 / 契约判据，且 `git diff --name-only` 落在 DR4 段级锚路径族。命中 ⇒ RFC §4.5 必须走留出验证三态（`闭族` / `未闭族` / `单案修复（无留出集）`）。现有控制：

| 侧 | 落点 | 形态 | 能否证明触发没被逃 |
|---|---|---|---|
| 作者 | `proposals/TEMPLATE.md` §4.5 | 要求记「锚 → 路径族」映射与误报 | 否：可写「不适用 / 无命中」而不附命令 |
| 作者/收口 | `shared/closeout.md` 步骤 3 | 定档必须附交叉检查结论 | 否：结论可自述 |
| 评审 | `shared/independent-review.md` §9 | 审查者必须手工对照 | 部分：依赖审查者主动重跑；文本未要求留原始输出 |
| 评审清单 | `proposals/README.md` | 「触发是否被逃」检查项 | 否：清单是纪律，不是取证 |
| 流程门 | `shared/gates.md` §2.5 | `[语义]`，**无机器判据** | 否：刻意如此（D156） |
| 机器 | `tests/test_duty_bug_families.py` 指针行钉 | 只钉 `bugs.md` 指针行形状 | 否：与触发无关 |

## 2. 谁能逃、怎么逃（按可发现性排序）

| ID | 逃法 | 具体形态 | 现有控制能否发现 | 备注 |
|---|---|---|---|---|
| E1 | **作者省略交叉检查** | §4.5 只写「不适用」或「无命中」，不附 `git diff --name-only` / `closeout_derive.py` 输出 | 只有当评审主动重跑才能发现 | 最高频、最低成本 |
| E2 | **路径族盲区** | diff 触及 `_support/`、`templates/`、`patches/`、`apply/` 等表外路径，作者按「不是门」处理 | 依赖评审对路径族的记忆 | 新文件/新目录最容易漏 |
| E3 | **语义改名** | 改了契约判据，却把 RFC 写成「文档/重构/测试」；或反过来把门改动塞进 `shared/*.md` 的文案里 | 依赖评审逐文件看 diff | 没有文件级分类器 |
| E4 | **伪造结论** | 写「锚 → 路径族映射：无命中」，但不附原始输出；或贴被截断/改写的输出 | 无机器判据；只能靠评审重跑 | 本次要硬化的主目标 |
| E5 | **评审只引作者** | 评审 §9 写「已核对作者 §4.5」，自己不跑命令 | 无 | 评审纪律面 |
| E6 | **触发 (a) 低报** | ≥3 条独立 finding 被拆成 2 条；或 §1 族锚被略去 | 依赖评审回放 | 与 (b) 同族 |
| E7 | **diff 基线选择** | 用较晚的 base 或排除未跟踪文件，让门改动不出现在 `git diff --name-only` | `closeout_derive.py` 已含未跟踪文件；base 仍可自选 | 需要评审核对 base |

## 3. 哪些能机判、哪些不能

**能机判（但只到形状层）：**
- 门路径 diff 是否存在；
- RFC/closeout 是否出现「触发面核对」/§4.5 段；
- 是否粘贴了命令与输出（可检查代码块/关键字）；
- 声明的改动文件集与实际 diff 是否一致（需要新增字段）。

**不能机判（语义层）：**
- 「这个路径族是否真的对应某个弱点族」——映射表本身是人工归纳；
- 「这个留出集是否未参与挖弱点」——D156 的第二条盲区；
- 「作者贴的输出是否被截断/改写」——只能靠评审复跑；
- 「无命中」是否成立——需要人读 diff 与族锚。

⇒ 一个纯存在性检查只能抓 E1/E4 的最粗形态，抓不到 E2/E3/E6/E7，且会制造「有段落=合规」的新假绿。按 D156 的既定口径（语义项、不假装是门），不新建机器判据。

## 4. 决定

**D1（做）**：把 E1/E4/E5 的取证硬化写进契约与模板：
- 作者侧 §4.5 / closeout 定档必须粘贴 `git diff --name-only` 与 `closeout_derive.py` 的**原始输出**（命令 + 输出，可复算），不得只写结论；
- 评审侧 §9 必须**自行重跑**两条命令并留原文，不得只引作者 §4.5；
- 映射与误报仍由人写，保留 D156 的语义判定。

**D2（不做）**：不新增 `validate_heldout` 之类的机器门 / 不把存在性检查塞进 `atlas_check`；不引入 LLM 自动分类。原因见 §3：语义不可机判，存在性检查会制造新的「有段落=合规」假绿，且与 D156「不假装是门」冲突。

**D3（观察触发）**：出现以下任一情况再评估 WARN 观测面（仍不升 FAIL）：
- 一次经证实的 E1/E4 逃逸事故（作者自述无命中、实际命中）；
- 连续两份触及门路径的 RFC 没有原始输出（可由评审抽样发现）；
- `closeout_derive.py` 的路径族表发生结构性变化。

- 仍可伪造原始输出；唯一对策是评审自行复跑（E5 已写成硬性文本，但仍是纪律）。
