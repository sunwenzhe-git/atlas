# `validate_testids` 判据级消融 — 成本与逃逸

> **性质**：`research/` 非 canonical 证据存档；不进装配、不作为执行契约。
> **日期**：2026-10-23。**证据等级**：E2「受控消融」——真实采用方项目的隔离副本，不是真实任务自然发生。
> **对象**：`validate_testids`（真实项目装配副本；实验基线是**修复前**源包，sha256 `f6a3beef…`；P5-A 修复后的源包 hash 以 D141 / M137 复核为准）。
> **安全**：只在 `/tmp/atlas-testids-copy` 改；真实项目未动；副本已删除；本文不含产品名、绝对路径、业务 case ID。

## 1. 基线

- 真实项目副本上跑 `validate_testids`（5 轮交错，取中位）：**796.5ms**（首轮冷缓存 1015ms，后 4 轮 789–797ms）。
- 输出：**2 条 WARN，0 FAIL**——「分页双向集合相等」（页面级缺失/多余差集）与「应然落点」（未实现页落点先行待落地）。其余 PASS / N/A。
- 这与真实批次 01 的事件行 `validate_testids` 中位 845ms 同量级，可作为成本实验的可信基线。

## 2. Profile：钱花在提取器，不在判据

`cProfile` 热点（cumtime）：

| 位置 | 累计耗时 | 说明 |
|---|---|---|
| `collect_testids_expanded` | **1.085s / 1.141s（约 95%）** | 扫 1611 个源文件、抽 testid |
| `file_testid_decls` | 0.340s（1611 次） | 每个文件一次 |
| `strip_comments` | 0.238s（3167 次） | **约 2×1611（不是精确 2×；差额来自少扫描/额外调用）** |
| `re.findall` | 0.366s（23855 次） | 正则抽取 |
| `pathlib.relative_to` / `is_relative_to` | 0.264s / 0.161s | 路径对象开销 |

**关键发现：后置判据不是成本大头。** 页面集合、落点、命名、唯一性这些检查都是集合运算；真正的钱在共享提取器：读 1611 个文件、每文件约两次 `strip_comments`（3167/1611）、多轮正则与 pathlib 调用。

## 3. 消融矩阵（5 轮交错，中位）

| 变体 | 中位耗时 | Δ vs 基线 | 输出变化 | 读数 |
|---|---|---|---|---|
| 基线 | 796.5ms | — | 2 WARN | — |
| **提取器复用**：第二次 `strip_comments` 改为复用第一次结果 | **686.4ms** | **-110.1ms（-13.8%）** | **无**（状态与全文均一致） | 纯浪费，最佳成本杠杆 |
| 摘「分页双向集合相等」的 WARN 构造 | 796.6ms | +0.1ms | 该判据 WARN → PASS | 判据本身几乎免费；删它省不到时间 |
| 摘「应然落点」整块 | 746.6ms | -49.8ms（-6.3%） | 该判据 WARN → PASS | 约 50ms 买一条 WARN |

**补充：** 「分页双向集合相等」的**比较循环**没有单独隔离（它和 `shard_ids` 的计算共享）；上表只隔离了最终 WARN 构造。从 profile 看，这个循环不是热点，成本远小于提取器。

## 4. 这组数据的结论

1. **「删判据省时间」在本门基本不成立。** 页面集合判据的告警构造约 0ms；落点判据约 50ms；两者都不是 796ms 的主要来源。
2. **真正的成本是共享提取器的重复工作。** 每文件两次 `strip_comments` 是纯浪费：复用第一次结果即可省 **约 110ms（14%）**，输出逐字不变。
3. **判据级消融的价值在「逃逸」而不在「省钱」。** 摘页面集合判据会少一条页面差集 WARN；摘落点判据会少一条落点 WARN；这两条 WARN 在真实项目里都存在，说明它们不是空转。
4. **优化候选优先于删除候选。** 如果目标是降 `validate_testids` 的 845ms，先做提取器复用；删判据既省不了时间，又会丢信号。

## 5. 落地结果

**P5-A：提取器复用 `strip_comments` — 已落地（D141 / M137，2026-10-23）**

- 改动：`collect_testids_expanded` 第一次循环就把 `strip_comments(text)` 的结果存进 `texts`，第二次循环直接复用；不再二次调用。
- 实测收益：约 **-110ms / -14%**（本副本 5 轮交错中位），输出逐字不变。
- 钉：`test_validate_testids_strip_comments_once_per_file` 数调用次数 = 文件数（修复前 2×）；`tests/test_validators.py` 139 → **140 条**。
- 变异 **M137**：还原二次调用 ⇒ 调用次数钉红（140 → 1 failed/139 passed）→ 还原 sha256 一致 → 140 passed；注入 diff 见 [research/2026-10-23-ablation-p5a-mutation.md](2026-10-23-ablation-p5a-mutation.md)。
- 全量：**614 passed / 4 skipped**。

**候选 P5-B：保留两条 WARN 判据**

- 本快照中「分页双向集合相等」与「应然落点」都在真实项目里各报一条 WARN；没有证据支持删除它们。
- 若未来要做判据级删除，必须先证明：① 该 WARN 长期无人处置；② 有另一道门覆盖同一坏输入；③ 失败模式可逆或低严重度（首跑报告 §4.4 的五条护栏）。

## 6. 限制

- 单一真实项目副本；1611 个源文件与项目规模相关，换项目数字会变。
- 5 轮交错只能压低缓存/热噪声；页面集合与落点判据的差异仍在几十毫秒量级，不能当精确常数。
- 副本排除了 `node_modules` / `dist` / `.git`；真实项目若扫描根包含这些目录，提取器成本会更高，优化收益也可能更大。
- P5-A 已落地（D141 / M137）；本文的成本实验在隔离副本完成，源包改动与变异证据见 D141 / M137 报告。
- 副本与临时 profile 输出已删除；本文只保留抽象后的耗时与判据名。
