## 1. 执行与还原

- **编排器**：用当前源包 `scripts/atlas_check.py --root <快照根> --fast --json`（源包 HEAD）；校验器仍由编排器按既有约定取**项目已装配副本**（`<快照>/.atlas/validators/`），⇒ 本轮测的是**各项目实际在跑的校验器**，不是源包最新版。
- **三个快照都是 10 个校验器文件**（批次 01 时是 9 个、`validate_walkthrough` SKIP）；三者的 `.atlas/VERSION` 摘要互不相同 ⇒ 三种不同装配态。
- **影子**：`research/shadow_pilot.py --gate validate_e2e_index --label <快照>-r<轮> --out <临时目录>`；账本不写项目。
- **快照/还原**：跑前快照 `.atlas/runs/` 全部运行文件 + `git status --porcelain` + 受保护树哈希（`product` / `specs` / `docs` / `.trellis/spec/conventions`）；跑后把新增事件行复制出来、把 `check-events.jsonl` 截断回跑前行数、按快照逐字节还原其余运行文件，再复核。
- **结果**：三快照 `git status` 前后一致；受保护树**零漂移**；`.atlas/runs` 还原校验（逐文件 sha256 等于快照）全为真。事后独立复核：三快照 `check-events.jsonl` 行数停在 11 / 899 / 2，未留下本批新增行。
- **过程缺陷（不掩饰）**：首轮驱动把证据按快照根目录名命名，三快照同名 ⇒ 两个文件被覆盖。已给每轮加显式标签重跑，被污染的两份产物隔离在临时目录、未用于本文任何数值。

## 7. 这批能说明 / 不能说明

**能说明：**

1. 事件行 + 影子在三个真实快照 × 3 轮上稳定可用：16 行、逐门耗时、状态一致，且运行态可完整还原（`git` 一致 / 零漂移 / 行数停在跑前）。
2. 成本集中是真实现象，且**占比**比**绝对值**可靠：`validate_testids` 在 9/9 轮占已计时门总和 61–66%。
3. P5-A 的净收益在真实数据上方向与幅度都复现（-10.7% / -12.4%，16 对逐轮全部同向，绝对量 290–330ms），并顺带确立了配对交错的测量法；同时确证 P5-A 已在这三个真实快照生效。
4. 影子门至今（12 次）没有独立拦截信号——这是「尚无证据」，不是「无用」；按铁律不得据此删门。

**不能说明：**

- 不能算真实误拦率 / 阻塞率：9 次运行 0 FAIL，分母仍为 0。
- 不能跨批次比绝对 ms，也不能据此判断产品规模效应（三快照工作量近似，浮动来自环境）。
- 不能证明 WARN 都是噪声：本批没采处置面数据；6–7 行 WARN 的人读成本仍未量化。
- 三个快照不是三个**时间序**批次：它们是同族三个并行分支，装配态也不同（A/B/C 三种摘要），因此只支持「同一门在不同快照上的稳定性」，不支持趋势判断。
