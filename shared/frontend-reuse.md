# atlas 共享契约 — 前端复用优先（执行期）

> **定位**：**非门、非真相源**。它只规定**执行期**如何查找、复用和记录既有前端能力；实现事实的真相源仍是代码，需求/验收的真相源仍是 PRD/AC。Atlas 不消费本文件，也不持有复用记录或组件索引。
>
> **适用范围**：新增前端模块、已有前端模块重构（含整体重写）、新增前端源码文件。普通修复、样式调整、只读调查**不强制**；用户明确要求时按本契约执行。
>
> **记录 owner**：复用决策只在当前 Trellis 任务的 Plan / Design 中保留一份；其他阶段引用，不另建报告或第二份计划（真相源登记见 `shared/single-source.md`）。

## 1. 适用性与执行顺序

| frontend scope | 复用调查 | 新模块目录确认 |
|---|---|---|
| `new-module` | required | Plan 阶段一次性确认 |
| `refactor` | required | 不新增首次确认；改变已批准目录/职责时展示差异 |
| `new-files` | required | 不新增首次确认；遵守已批准结构 |
| `not-applicable` | not-required | 不要求 |

执行顺序：

项目规范与工程定位 → 当前模块交互清点 → 四层查找 → 决策表 → 实现 → 验证并更新记录。

- 先读目标项目规范与现有 Plan/Design，确认真实前端工程、工作区/包边界、别名、导出和注册方式。
- 不预设 `components/`、`hooks/`、`common/` 等目录；业务组件与公共组件是职责层级，不是固定路径。
- 已有调查仍然有效时只补查变化或缺口，不重复全仓搜索。

## 2. 交互清点（先于组件查找）

对本次涉及的**当前模块**，先列出已有交互，再决定新增还是复用。至少覆盖：

| 类别 | 要核对的行为 |
|---|---|
| 单条与批量 | 单个删除/关闭、批量选择、清空全部、撤销/重试 |
| 状态 | 只读/禁用/权限、加载、空、错误、重试 |
| 数据回显 | 刷新后回显、计数/占位、选中态、未保存改动 |
| 数据控件 | 搜索、筛选、分页、排序、展开/折叠 |
| 反馈 | 成功/失败提示、二次确认、禁用理由 |

同一能力出现在多个 **surface**（如浮层面板内与外层控件、列表行与详情区）时，逐 surface 记录；不得只复用其中一个。

## 3. 四层查找

按顺序查找，某层满足即停止；跳层必须写具体缺口和已查范围。

| 顺序 | 来源 | 必须核实 |
|---|---|---|
| 1 | 同一模块/同一面板的同类实现（sibling） | 实现与调用点、交互、数据流、权限、状态处理；优先直接复用现有处理函数、组件或流程 |
| 2 | 已定位的业务组件 | 接口与真实使用示例，以及已封装的业务行为 |
| 3 | 已定位的公共组件 / 组合逻辑 / 工具 | 组件接口、事件、组合与扩展方式、数据约定 |
| 4 | 项目实际使用的组件库 | 从依赖清单/锁文件确认版本；用项目认可的文档、工具接口或源码核实原生能力 |

- 先用项目已有索引或路由/目录事实定位候选，再读真实实现和调用点；**文件名或一次导入命中不算完成调查**。
- 不保留组件外壳却重写其完整展示、状态和交互；能通过接口、事件或组合方式完成时，不新增包装层。
- 旧实现与当前需求/规范冲突时只复用适用部分，写明差异，不照搬缺陷。
- 项目指定了组件库知识入口时先查该入口；不可用则记录事实，按项目允许的源码、类型或同版本文档核实，不猜 API。

## 4. 复用决策表

在任务 Plan / Design 中保留一份表，覆盖本次所有适用能力：

| Capability（含 surface） | Reference | Reuse Decision | Gap / Deviation | Verification |
|---|---|---|---|---|
| 具体能力 + 所在 surface | 已读实现路径 + 调用点 | 直接复用 / 组合扩展 / 最小新增 | 缺口、搜索范围、跳层原因 | 对应验收检查或真实交互场景 |

- 上层已满足需求时，不为凑齐四层重复搜索低层。
- 没有缺口写「无」；跳层写实际搜索范围和具体不适用原因；**空白与「评估过为无」不得同形**。
- 新增最小实现必须落在现有职责层，并保留需求范围内的权限、输入/展示、筛选、分页、校验、异步、错误处理和只读态。

## 5. 新模块的目录确认（执行侧）

仅从零新增前端模块时：在任务 Plan 中一次性展示完整目录树、逐文件职责、`[新增]` / `[现有·复用]` / `[现有·修改]` 标记及接入点，与计划批准合并确认；确认后实施不逐文件重问。

已有模块内重构或新增文件不触发新的目录审批；改变已批准目录或职责时才展示差异。

本确认由 Trellis Plan 承担；Atlas 不产目录审批文件，也不新增用户确认门。

## 6. 验证与证据

- 实现后按决策表逐项核对：实际改动 ↔ 复用决定，确认没有重复实现、没有绕过原生能力、没有丢失既有交互。
- 可行时在真实运行页面验证受影响的交互；静态检查、单测、类型检查不能替代真实交互验证。
- 网络打桩与 E2E 证据的边界按 `.atlas/rings/e2e/reference.md` §5.8 判定；交付说明不得把临时本地打桩写成 E2E 通过。
- 新增/补齐用户可见交互入口的 testid / 用例更新按 `.atlas/rings/e2e/reference.md` §4 / §6.2 判定；同一能力的不同 surface 都在该契约的适用范围内。

## 7. 可选的项目侧索引

项目可维护一份前端能力索引（能力/同义词、层级、路径/导出、输入输出、真实调用点、限制、核验状态）作为**导航缓存**：

- 只用于定位候选，不证明实现存在；使用前必须回源核实。
- 允许不完整、允许过期；只刷新受影响条目（依赖/接口/目录/别名变化），不以一次提交判定全量失效。
- 由项目/Trellis 执行侧持有；**Atlas 不生成、不读取、不校验**，也不把它变成结构事实或门禁输入。

## 8. 反模式（硬）

- 在已有同类实现旁另写一套，只因为「没看到」或「文件名不同」。
- 只复用组件外壳，在内部重写展示、状态、校验、清空、分页和错误处理。
- 用「组件库没有」代替查证；用「项目没有惯例目录」代替查找职责层。
- 把临时网络打桩的本地验证写成 E2E 通过。
- 为复用新建 Atlas 组件清单、第二份决策文档或额外审批门。
