# Obsidian 决策中枢哲学

> **“代码库只记录现在的真相（What），知识库沉淀为什么这么做（Why）。”**

在常规软件开发中，最难传承的往往不是“代码怎么写”，而是“当初为什么不采用更简单的方案 A，而花了三倍代价选了方案 B”。

Atlas 支持将 **Obsidian（配合卡片盒知识库后端）** 作为可选的外部决策大脑。

---

## 优雅降级设计 (Optional Graceful Degradation)

* **纯 Git 模式（开箱即用）**：
  若项目中未配置 `product/stack-profile.yaml` 的 `knowledge:` 段，知识库契约**整体自动降级为跳过（SKIP）**，所有 280+ 自动化门禁与三环流程 **100% 正常绿灯通过**，绝不阻断任何开源用户。
* **外脑模式（进阶增强）**：
  若配置了 Obsidian Vault，Atlas 自动启用跨会话长期记忆中枢。

---

## 代码库与知识库的清晰分工

```
┌─────────────────────────────────┐       ┌─────────────────────────────────┐
│     Git 仓库（单一代码真相源）    │       │     Obsidian Vault（决策中枢）   │
│                                 │       │                                 │
│  • 当前事实：现在的代码长什么样    │ ◄───► │  • 时间轴纪要 (3508)：为什么这么做 │
│  • 现在的 PRD 与验收用例         │ 对账门 │  • 决策结论 (3507)：拍板定案归档   │
│  • 纯正向陈述，不留历史纠葛      │       │  • 未决台账 (3509)：跨会话开放问题 │
└─────────────────────────────────┘       └─────────────────────────────────┘
```

1. **Git 仓库存“现在的实然与应然”（What）**：
   * 代码库是单一真相源（SSOT）；
   * 遵循 §14 落笔纪律，只写正向终态，不记录反复推翻重来的心路历程。
2. **Obsidian 存“为什么这么定”（Why）**：
   * 记录跨越数周、涉及多次大模型上下文重置的决策背景；
   * 记录历史上被否决方案的深刻教训，防止后来的 Agent 重新踩坑；
   * 记录跨领域的开放问题台账。

---

## 三卷合一长期记忆体系

在 Atlas 的 Obsidian 设计目录中，知识库被严密划分为三套活页卷系：

* **3508 讨论纪要卷（时间轴 / 为什么）**：
  * 按轮次记录每一次关键纠偏、上下文事实与技术论证；
  * 新 Agent 进场时，读一遍纪要卷最新一轮，**一秒完成接盘**。
* **3507 决策记录卷（结论 / 拍板定案）**：
  * 记录所有不可逆重大架构抉择的终局结论与依据；
  * 作为方案设计的定海神针。
* **3509 未决问题卷（开放项 / 缺陷台账）**：
  * 跟踪跨需求的开放缺陷、待治理技术债务与演进方向；
  * 每一个条目都由机器校验器跟踪生命周期，闭环即移卷归档。
