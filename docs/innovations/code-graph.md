# 技术纵深：代码图谱 (Code Graph) 逆向分析

传统静态代码分析工具（如常规 AST 解析器或正则扫描器）的一个惯常盲区：**只能看见单文件内的语法树**，跨文件调用关系要靠人肉逐文件倒查。

Atlas 集成了**图谱后端隔离层（`adapters/_graph.py`）**，利用 **CodeGraphContext (cgc / FalkorDB 知识图谱后端)** 做跨文件调用拓扑查询。**能力边界先讲清楚（2026-10-15 实测收窄）**：

* **看得见**：函数级**调用边**——改一个后端函数，`callers` 可反查「谁调它」（分组保的 Service/Controller 链可对账）；文件枚举通道有基准可对账。
* **看不见**：ORM / 属性访问边、反射与框架入口、**以及 JSX 组件的渲染引用**（实测 cgc 0.6.13：`element: <Comp />` 形态不产生任何调用边，改组件报不出「哪些页面用到它」——atlas 侧消费层只认 `CALLS` 边）。所以**纯前端栈上图谱近乎买不到东西**：atlas 按栈门控，纯前端项目在确认画像时**不会提议**启用它（`shared/stack-profile.md` §2）。

## 全仓拓扑架构

```
  Git 仓库代码 (FastAPI/React/...)
               │
               ▼  cgc 建索引（用前现刷，见下）
  ┌──────────────────────────────────────────────┐
  │         全仓代码知识图谱 (Code Graph)          │
  │  File ──► Class ──► Function ──► Caller/Callee │
  └──────────────────────┬───────────────────────┘
                         │
        ┌────────────────┴────────────────┐
        ▼                                 ▼
  routes 适配器的文件枚举通道           影响面基准 (impact_report)
  • 只换「哪些文件参与识别」            • 需求前置推导受影响符号与调用方
  • 解析逻辑与正则通道同一份            • 与 git diff 对账（advisory 基准）
```

**它不做的事**：图谱不做业务域聚类（域由 structure 环按路由簇 / 目录簇 / 模型命名簇 / 接口前缀簇多信号投票得出，`rings/structure/reference.md` §2.1）；也不替代任何适配器的解析层——枚举出来的文件照样要过同一套解析逻辑。段未声明或后端不可用 ⇒ 消费者显式降级（适配器 `WARN` + 回退正则、报告器 `not_ready`），其余流程不受影响。

## 图优化的四大工程设计

### 1. 薄后端、厚自有
* 图谱引擎（cgc / FalkorDB）只作为“哑索引与高速 Cypher 查询接口”；
* 所有核心智能逻辑（影响面分层、业务域聚类、AC 映射规则）均由 Atlas 自有 Python 模块实现；
* 后端即使未来升级或替换，上层业务契约稳如泰山。

### 2. 用前现刷，拒绝陈旧 (Freshness Guarantee)
* 图谱没有常驻的后台轮询守护进程；
* 每一个消费者在查询前强制调用 `ensure_index()`，自动比对当前 `git HEAD + 脏文件集` 的哈希摘要；
* 哈希一旦不一致，立刻按需全量重建索引（受控实验定形走 `index --force` 全量，约 17 秒——增量 update 语义不可信，见 `adapters/_graph.py`），**过期状态在消费时构造性不存在**。

### 3. 确定性查询 (Deterministic Ordering)
* 图谱层的所有 Cypher/SQL 查询结果**强制追加 `ORDER BY`**；
* 保证在同一代码状态下跑出的图谱关系绝对确定，这是上层结构资产可做 `git diff` 与机器双向对账的前提。

### 4. 优雅降级与 Fail-Open 保护
* 若目标环境未安装 cgc 命令行，隔离层自动探测并显式降级为文件系统遍历 + 正则模式（stderr WARN，不静默）；
* 伴随显式 `WARN` 告警，绝不破坏基础工程的正常运转。
