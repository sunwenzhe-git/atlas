# 技术纵深：代码图谱 (Code Graph) 逆向分析

传统静态代码分析工具（如常规 AST 解析器或正则扫描器）存在致命缺陷：**只能看见单文件内的语法树，看不懂跨文件的全仓调用拓扑与隐式级联依赖**。

在复杂全栈工程中，底层修改一个数据模型字段，传统工具根本无法精准判断：
* 哪些 API 端点受到了级联影响？
* 前端哪些页面路由的请求依赖被悄悄破坏了？

Atlas 深度集成了**图谱后端隔离层（`adapters/_graph.py`）**，利用 **CodeGraphContext (cgc / FalkorDB 知识图谱后端)** 实现了全仓拓扑逆向抽取。

---

## 全仓拓扑架构

```
  Git 仓库代码 (FastAPI/React/...)
               │
               ▼  cgc 逆向索引 (FalkorDB)
  ┌──────────────────────────────────────────────┐
  │         全仓代码知识图谱 (Code Graph)          │
  │  File ──► Class ──► Function ──► Caller/Callee │
  └──────────────────────┬───────────────────────┘
                         │
        ┌────────────────┴────────────────┐
        ▼                                 ▼
 结构事实抽取器 (adapters)          精准影响面推导器 (impact_report)
 • 跨文件端点到模型映射             • 需求前置推导影响域
 • 级联依赖自动归域                 • 结合 git diff 深度校验
```

---

## 图优化的四大工程设计

### 1. 薄后端、厚自有
* 图谱引擎（cgc / FalkorDB）只作为“哑索引与高速 Cypher 查询接口”；
* 所有核心智能逻辑（影响面分层、业务域聚类、AC 映射规则）均由 Atlas 自有 Python 模块实现；
* 后端即使未来升级或替换，上层业务契约稳如泰山。

### 2. 用前现刷，拒绝陈旧 (Freshness Guarantee)
* 图谱没有常驻的后台轮询守护进程；
* 每一个消费者在查询前强制调用 `ensure_index()`，自动比对当前 `git HEAD + 脏文件集` 的哈希摘要；
* 哈希一旦不一致，立刻触发秒级全量重构索引，**过期状态在消费时构造性不存在**。

### 3. 确定性查询 (Deterministic Ordering)
* 图谱层的所有 Cypher/SQL 查询结果**强制追加 `ORDER BY`**；
* 保证在同一代码状态下跑出的图谱关系绝对确定，这是上层结构资产可做 `git diff` 与机器双向对账的前提。

### 4. 优雅降级与 Fail-Open 保护
* 若目标环境未安装 cgc 命令行，隔离层自动探测并优雅回退为纯 AST/正则模式；
* 伴随显式 `WARN` 告警，绝不破坏基础工程的正常运转。
