# 防线淬炼：变异证明 (Mutation Proving)

> **“门禁写完不是胜利；证明门禁在脏数据下会咬人，才是真正的防线。”**

很多项目里的自动化门禁或 CI 检查存在一个巨大的假象：**门禁永远显示 PASS，人以为自己很安全，实际上规则可能因为代码漏写了判断分支、正则表达式缺少边界锚点，导致即使传入错误数据也静默通过！**

Atlas 坚决推行**变异证明（Mutation Proving / M 系列变异钉子测试）**，作为所有门禁的入网准则。

---

## 一、什么是 M 系列变异钉子？

在 Atlas 的测试套件中（`atlas/tests/`），除了测试正常的正例之外，每一条校验器规则必须配套一组**故意注入脏数据的变异用例（Mutation Cases）**：

| 变异编号 | 所在门 | 注入的脏数据 | 预期检验器反应 |
|---|---|---|---|
| `validate_ledger` **M1** | 台账（未决 ⇔ 已办）× 编号空间 | 两卷出现同一个台账号 | 撞号门报红并指名 |
| `validate_ledger` **M11** | 同上（纪要卷滚动阈值） | 纪要卷堆到 31 轮（阈值 30） | 阈值门报 WARN「当轮拆卷」 |
| `validate_stack_profile` **M27** | 门总账 ⇔ 校验器清单 | 从 `VALIDATORS` 摘掉本门 | 自洽门判据与逐器一行测试双红 |
| `gen_e2e_scripts` **M28** | 用例分片 ⇔ 运行器脚本 | 摘掉 skip 发射 | blocked 用例被真跑成红（假红复活被抓） |
| `impact_reconcile` **M39** | 影响面预测 ⇔ 收口 `git diff` | 摘掉差集检测 | 预测集与实际改动错位不再被指名 |
| `validate_design_exemptions` **M43** | 设计档案豁免 ⇔ `.impeccable/config.json` | 摘掉双向差集判据 | 两侧漂移钉子双红 |

> **编号口径**：M 系列编号在**各自测试文件内**自成序列，同一号码在不同门含义不同（例如 M1 既是台账跨卷撞号，也是装配自检的一个判据）；当前最大编号为 **M43**。具体某号的语义以该门所在的测试文件与 `shared/gates.md` 门总账为准。

## 二、自洽门与双向红灯验证

```
                         [ 新校验规则代码 ]
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
         [ 正常应然数据 ]                [ 恶意变异数据 (M-Series) ]
                 │                               │
                 ▼                               ▼
            ✅ 必须 PASS                    ❌ 必须 FAIL
                 │                               │
                 └───────────────┬───────────────┘
                                 │
                         双向皆通过，方可合入！
```

* **出厂守卫**：全部 M 系列钉子常驻在全量出厂测试（`python3 -m pytest atlas/tests/`）里；
* **拒绝摆设**：只有当一条规则在正常数据下 PASS、同时在对应的 M 系列变异数据下 **100% 响亮咬住报红**，该规则才算真正具备效力。
* 这套严苛的自洽测试体系，确保了 Atlas 的每一道门禁都是真正有牙齿的防线。
