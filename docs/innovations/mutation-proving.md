# 防线淬炼：变异证明 (Mutation Proving)

> **“门禁写完不是胜利；证明门禁在脏数据下会咬人，才是真正的防线。”**

很多项目里的自动化门禁或 CI 检查存在一个巨大的假象：**门禁永远显示 PASS，人以为自己很安全，实际上规则可能因为代码漏写了判断分支、正则表达式缺少边界锚点，导致即使传入错误数据也静默通过！**

Atlas 坚决推行**变异证明（Mutation Proving / M 系列变异钉子测试）**，作为所有门禁的入网准则。

---

## 一、什么是 M 系列变异钉子？

在 Atlas 的测试套件中（`atlas/tests/`），除了测试正常的正例之外，每一条校验器规则必须配套一组**故意注入脏数据的变异用例（Mutation Cases）**：

| 变异代号 | 典型脏数据注入场景 | 预期检验器反应 |
|---|---|---|
| **M1–M5** | 故意在 PRD 中删掉必填的验收准则（AC）编号 | 校验器必须报红，拒绝通过 |
| **M6–M12** | 故意在 E2E 分片中伪造不存在的前端 `data-testid` | 双向对账门必须报红，指出实然差集 |
| **M13–M20** | 故意在跨环引用中拼写错误或引用退役环契约 | 路径可达门必须报红，拒绝静默忽略 |
| **M21–M35** | 故意制造实审文件数小于应审文件数（静默少审） | 实例 ⑤ 独立审查门必须一票否决 |
| **M36–M43** | 故意在设计档案声明豁免但不同步机器配置 | 设计档案对账门必须报红双向指出差集 |

## 二、自洽门与双向红灯验证

```
                         [ 新校验规则代码 ]
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
         [ 正常应然数据 ]                [ 恶意变异数据 (M-Series) ]
                 │                               │
                 ▼                               ▼
            ✅ 必须 PASS                    ❌ 必须 FAIL
                 │                               │
                 └───────────────┬───────────────┘
                                 │
                         双向皆通过，方可合入！
```

* **出厂守卫**：目前 Atlas 源码中常驻 **288 项出厂级自动化测试**；
* **拒绝摆设**：只有当一条规则在正常数据下 PASS、同时在对应的 M 系列变异数据下 **100% 响亮咬住报红**，该规则才算真正具备效力。
* 这套严苛的自洽测试体系，确保了 Atlas 的每一道门禁都是真正有牙齿的防线。
