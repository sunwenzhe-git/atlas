# 流水线自感知上报（atlas report）

> **“遇到过不去的规则，不许偷偷把它注释掉。”**

一套在真实工程里被反复使用的流水线，一定会遇到**规则与业务正面冲突**的时刻。此时模型有三种选择：静默绕过、偷偷放宽规则、假装完成 —— 三者都会让规则体系在几轮之内烂掉。Atlas 给出的第四条路是：**结构化提炼现场，自动上报到云端设计池**。

---

## 1. 它解决的是什么

绝大多数门禁体系的失效方式不是「规则写错了」，而是**规则遇到例外时被就地静默掉**：注释一行、加个 `--no-verify`、把 FAIL 降级成 WARN。事后没人知道为什么这条规则变成了空文。

Atlas 的处置是把这件事变成**显式产物**：冲突被记成结构化记录，进云端池排队、定案、再回填契约 —— 规则只会**变准**，不会**变空**。

---

## 2. 四类触发场景

不只是异常崩溃，更多是**设计冲突**：

| 类别 | 场景 |
|---|---|
| **结构性冲突** | 业务形态完全合情合理（长业务累加链测试、特殊合法路由嵌套），但既有规则或提取器发生机械性冲突 |
| **人机体感别扭** | 某流程导致用户反复重复操作、产生决策疲劳，或提示词诱导模型与人类来回扯皮 |
| **底层假设破产** | 底层依赖工具（AST 解析器 / 代码图谱 / 浏览器运行器）在真实环境下的语义与既有契约假设不符 |
| **用户显式纠偏** | 用户在会话中明确指出「这里的流程 / 设计 / 规则不合理」 |

---

## 3. Agent 的自动执行协议

1. **结构化提炼三要素**：设计缺陷本体 / 触发形态（抽象）/ 建议解耦方向与备选方案 —— 业务背景只在会话内用来定位，落盘时抽象成形态；
2. **调用上报命令**（下一节的 `atlas report`）；
3. **向用户说明**已沉淀现场，并给出当前阶段的最优临时推进方案 —— 既不停工，也不假装没有冲突。

### 3.1 它靠什么触发（三处交付面）

规则写进契约不等于会被想起来：流程中段的摩擦，等不到「开工前读契约」那个时点。所以 §15 的提醒落在三处**交付面**上：

| 交付面 | 落点 | 时点 |
|---|---|---|
| **项目指针段** | 目标仓库 `AGENTS.md` 的 atlas 段（源 = `patches/project-wiring/agent-pointer.md`） | 会话内**常在上下文** |
| **宿主撞门提示** | `extensions/pi.ts` 的 `turn_end`：机器门报非零时同段提示 | 门真红的那一刻 |
| **收口扫描** | `shared/closeout.md` 触发表「开发流程/宿主适配摩擦」行 | 每次收口 |

三处之外没有机器门：**「这算不算流水线缺陷」是语义判断**，机器只能保证提醒出现在正确的时点。用户主动说「把这个上报一下」= 前两处漏认的信号，而 §15 的价值恰恰在**上游**——冲突被就地绕过之前就沉淀下来。

## 4. 命令行

**上报只写设计问题**（§15 零业务上下文）：不上传产品名 / 业务名词 / 真实数据 / 业务代码；业务背景在会话里用来定位，落盘前一律抽象成形态。

```bash
atlas report \
  --title "多步串行链与每用例播种的结构性冲突" \
  --kind design-conflict \
  --conflict "e2e 生成器把 seed 声明同时当运行期重置发射，累加链用例在第 2 步被抹掉前置数据" \
  --shape "多步串行链：每步产出物是下一步的输入" \
  --proposal "声明与发射解耦：seed 行只参与静态对账，不发射运行期重置" \
  --evidence "<校验器报错 / 用例 ID / 生成器文件行>"
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `--title` | ✅ | 问题简述标题 |
| `--conflict` | ✅ | 设计缺陷本体：哪条规则 / 哪个提取器 / 哪一步流程，在什么条件下冲突 |
| `--kind` | — | 问题类别闭集，缺省 `design-conflict` |
| `--shape` / `--proposal` / `--evidence` | — | 触发形态（抽象） / 建议方案与权衡 / atlas 侧客观输出（报错 · 规则 ID · 文件行） |
| `--trigger` | — | `auto`（缺省：模型自己认出来的）/ `user`（用户要求上报 = §15 类别 4）。池子里的来源分布就是这条契约的体检表 |

`--kind` 闭集：`design-conflict`（设计冲突）、`rule-friction`（规则摩擦）、`tool-semantic`（工具语义与假设不符）、`bug`（缺陷）。

直接调脚本亦可：`python3 .atlas/scripts/atlas_report.py --title "..." --conflict "..."`。凭据依次从 `ATLAS_REPORT_TOKEN` / `GITHUB_TOKEN` / `GH_TOKEN` / git credential 探测，纯标准库、零外部依赖。

---

## 5. 从云端池回到契约

上报不是终点，闭环才是：

```text
Agent 感知冲突 ──► atlas report ──► 云端设计池（GitHub Issues，标签 pipeline-rfc）
                        │
                        ▼
              架构师集中定案、排期、升级契约
                        │
                        ▼
```

* **云端设计池**：所有上报进同一个中心池，架构师一眼看到跨项目的同根问题；
* **定案产物回填契约**：结论落成契约正文 + 出厂测试（含变异钉子），下一次同类冲突会被机器直接判掉；
