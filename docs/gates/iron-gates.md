# 铁血门禁系统 (The Iron Gates)

在 Atlas 中，“代码写完了”从来不是靠开发者或 Agent 的自述，而是取决于一套**不讲情面的机器对账门禁（Hard Gates）**。

---

## 门禁架构全景图

```
                ┌──────────────────────────────────┐
                │ 走查单确认门 (人侧: UI 旅程拍板)   │
                └─────────────────┬────────────────┘
                                  ▼
                ┌──────────────────────────────────┐
                │ 环间独立审查门 (机器: 拦截 Critical)│
                └─────────────────┬────────────────┘
                                  ▼
   [实现阶段] ──► ┌──────────────────────────────────┐
                │ 实例 ⑤ 实现审查门 (只读进程 diff 审查)│
                └─────────────────┬────────────────┘
                                  ▼
                ┌──────────────────────────────────┐
                │ 双向对账门 (testid 实然 ⇔ 应然集合) │
                └─────────────────┬────────────────┘
                                  ▼
                ┌──────────────────────────────────┐
                │ impact 对账门 (预测影响面 ⇔ git diff)│
                └─────────────────┬────────────────┘
                                  ▼
                             [收口归档]
```

## 核心对账门禁详解

### 1. `testid` 双向集合对账门 (`validate_testids.py`)
* **断言**：用例分片中声明的应然 `testid:` 清单，与前端源码中真实扫描出的 `data-testid` **按页面双向集合严格相等**；
* 前端代码漏写了必要埋点 ──► **FAIL**；
* 前端代码多写了无用埋点 ──► **FAIL**；
* 只有集合完全相等才允许放行，杜绝测试代码与前端实现脱节。

### 2. 实例 ⑤：实现代码独立审查门（防偷工减料）
* **运行机制**：需求实现完成后、归档收口前，由独立的外部只读进程执行 `git diff` 审查（Fresh Context 隔离）；
* **应审 N / 实审 M 严格对账**：
  * 实测证明：大模型在审查数十个文件的大 Diff 时，会**悄悄跳过文件**（静默少审）；
  * 审查器启动时先提取预审文件数 `N`，审查结束后统计给出 findings 的文件数 `M`。**一旦 `M < N`，不论结论多好一律响亮报红拦截**！
  * 发现任何 `Critical` 级缺陷，一票否决收口。

### 3. `impact` 影响面预测对账门 (`impact_reconcile.py`)
* 在需求规划阶段，模型通过代码图谱和 AST 预测本次改动的影响面文件集合；
* 在任务收口归档时，将该预测集合与真实的 `git diff --name-only` 产生的文件列表进行自动差集比对；
* 持续暴露出模型的盲区，防止漏测边缘修改。

### 4. 设计档案豁免对账门 (`validate_design_exemptions.py`)
* 前端视觉设计若要豁免某条检测规则（例如色彩对比度特殊定制），必须在 `product/design.md` 登记 `detect:<rule-id>`；
* 校验器要求设计档案里的豁免列表与 `.impeccable/config.json` 中的实际忽略规则**双向严格相等**；
* 关掉报警必须有台账，有台账必须改配置，彻底消灭暗箱操作。

### 5. 装配版本完整性门 (`.atlas/VERSION`)
* 目标项目中的装配态与 Atlas 源包内容摘要实时哈希比对；
* 源包升级或本地改动脱节时，自动亮出 `WARN`，防止跨项目版本漂移。
