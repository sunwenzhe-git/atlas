# 自带技能生态 (Skills & Agents)

Atlas 随包完整分发了一套高度自洽的高阶开发、审查与压力测试套件，零外部私有依赖，装配时下发到各平台 skill 目录（`.agents/skills/` 等）。本页为全套技能清单与定位；机制细节见文中链接的概念页。

---

## 1. `atlas-apply` — 唯一跨环编排件

* **定位**：Atlas 全流程**唯一**的编排件，把一条需求编译进项目级应然资产——读 Trellis 需求卡 → 推导影响面 → 按 `prd → e2e` 增量更新 → 跑机器校验并出报告；
* **四种模式**：`apply <需求ID>`（需求增量）、`apply adopt`（存量开户）、`all`（三环全量构建）、`backfill`（反向回流：实现期发现的裁决条目攒批回灌上游）；
* **三问门分流**：① 改动既有能力？② 要人确认 UI？③ 要可重复验收？**三问全否是合法旁路**（只走 structure + Trellis），不硬造空 E2E 用例；
* 四种模式的执行链条与两条合法旁路，见[唯一编排件 (apply)](/concepts/apply)。

---

## 2. 三环资产技能 — `atlas-structure` / `atlas-prd` / `atlas-e2e`

* **`atlas-structure`（结构基线 · 实然）**：读代码逆向产出目录与模块地图、路由与页面清单、接口清单、数据模型清单，落 `.trellis/spec/structure/`（Trellis 路径注入层），并从代码提议候选域（域清单先请用户过目再铺域级文件）；
* **`atlas-prd`（业务应然单源）**：产出全局 `prd.md` + 每个产品功能域一份域级 PRD，含功能架构、范围与处置、Rule Set 与可追溯 AC；
* **`atlas-e2e`（验收应然）**：产出「页面分片 + 总索引」用例资产；`data-testid` 应然（分片）⇔ 实然（前端源码）按页双向集合校验；再从分片生成脚本、在真实应用单段执行；
* 三环如何环环相扣，见[三环资产体系](/concepts/rings)。

## 3. `atlas-grill` → `atlas-design-review` — 决策压测与独立复核

* **思想渊源与工程化**：汲取了 Matt Pocock 等社区先驱在 `grill-me` 中“动手写代码前反向盘问、深挖隐式假设”的做法；但不局限于单次对话 Prompt——固化为具备独立只读 Agent 复核、防选择疲劳与 ADR 机器资产沉淀的工程防线；
* **定位**：重大设计决策定稿前的“红蓝对抗”工具；
* **防选择疲劳**：严禁单屏抛出 4~5 个常识选择题导致用户麻木点击“全选推荐”；
* **单轮严控 1~2 问**：先集中追问一个最关键的卡点，再推进下一步；
* **代价直陈**：模型给出深思熟虑的主选方案，同时**列出该方案的代价与后续不利影响（Trade-off）**，要求用户明确回答是否接受；
* **代码矛盾核验**：方案与既有代码事实矛盾时直接指出，要求用户裁决是否推翻既有架构；
* **锐化模糊用词**：遇到“优化”、“重构”等模糊词，追问出明确边界。

压测提炼出主选方案后，由独立复核收口（`atlas-reviewer` 为专用只读 Agent，工具集不含文件修改与 bash 权限，Fresh Context 进程边界隔离）：

```text
  atlas-grill（刺透隐式假设，提炼核心权衡）
         │
         ▼
    用户拍板关键抉择
         │
         ▼
  atlas-design-review（跨模型/跨厂牌独立复核，一致通过 / 不一致人工终审）
```

* 探索（产出问题）与验证（判定主张）严格分立，严禁审查者越界变成无休止的探索；
* 「独立审查」骨架共四类实例（PRD / E2E 用例 / 设计决策 / 实现代码），见[独立审查：四类实例](/concepts/review)。

## 4. `frontend-design` — 前端品味总监与合规基线

* **两层合一架构**：
  * **第一层（品味总监）**：判读 brief、推断设计语言、调节三个设计旋钮（variance / motion / density）、禁用 AI 味套路；
  * **第二层（合规基线）**：53 份细则文件完整覆盖 WCAG 可访问性、对比度（4.5:1 / 3:1）、焦点与键盘导航、Core Web Vitals、暗色模式规范；
* 交付前由预检闸门强制校验，纯后端项目自动降级忽略。

## 附：产物落笔纪律 — 读者中立与零反刍（随包契约内化，**非技能**）

> 这不是一个 skill，不装入平台 skill 目录——它是随包契约的行为条款，随包分发、全程约束所有交付面的落笔。条款本体见项目内 `.atlas/shared/global-rules.md` §14。

* **读者中立**：所有需求卡、代码注释、Git 提交与 PR 说明，必须按**“读者从未看过会话工作过程”**书写；
* **禁止反刍**：会话中被否决的备选方案、被推翻的提议、中途反复纠正的过程，属于会话控制数据，**严禁反刍进交付产物的正文与命名中**（严禁“此前曾尝试 X 失败，现改为 Y”式的纠葛叙事）；
* 产物只陈述当前敲定的正向目标、既有客观事实与架构不变式。
