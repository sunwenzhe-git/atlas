# 三环资产体系

Atlas 的应然资产治理围绕 **三环（Rings）** 展开，环环相扣，构成完整的工程闭环。

---

## 1. Ring 1: 结构基线 (`atlas-structure`)

* **角色**：**实然代码事实**
* **产物路径**：`.trellis/spec/structure/`
* **底层能力**：
  * 基于代码图谱（Code Graph Context / FalkorDB）与 AST 正则深度逆向扫描；
  * 自动抽取前端路由、后端 API 端点、数据模型（Schemas/Entities）、以及现有自动化测试分布；
  * **事实区与语义区分立**：机器自动抽取的代码事实放在受控区，人类撰写的领域指导原则放在语义区；
  * **双份维护**：支持 `current` 与 `legacy` 分层，精准追踪重构过程中的架构漂移。

---

## 2. Ring 2: 项目级 PRD (`atlas-prd`)

* **角色**：**业务应然单一真相源**
* **产物路径**：`product/prd/`
* **底层契约**：
  * **单源法则**：项目的所有业务规则只有这一份权威，不建平行的 `CONTEXT.md` 或独立的 `ADR` 树；
  * **双向追踪链**：
    ```text
    功能清单 (Features) 
      └──► 业务规则 (Rules) 
             └──► 验收准则 (Acceptance Criteria, AC) 
                    └──► E2E 用例 (E2E Cases)
    ```
  * **纯粹性原则**：PRD 内绝不记录“谁在做、做完了没有”等项目管理状态（状态归执行器管理），保持业务规则的纯粹与恒定。

---

## 3. Ring 3: 验收用例 (`atlas-e2e`)

* **角色**：**验证应然资产**
* **产物路径**：`product/e2e/`
* **底层规则**：
  * **真实靶场单段执行**：直接面向真实运行的后端与前端应用（基于 Playwright 自动化驱动）；
  * **总索引与页面分片**：`e2e-index.md` 汇总全部用例大盘，`cases/<page>.md` 细化每一页的独立用例分片；
  * **`data-testid` 唯一硬锚**：交互定位坚决杜绝脆弱的文本匹配或深度 CSS 类名，必须通过 `data-testid` 锚定；
  * **抗瞬时反馈硬规则**：严禁把 Toast 提示或弹窗关闭当验证，写操作必须刷新页面后跨真相源复断言。
