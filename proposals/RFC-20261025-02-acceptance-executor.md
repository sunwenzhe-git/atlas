# RFC-20261025-02 · 验收执行器(执行层最小立项面)· v2

> **来源链**:R-1 表态(2026-10-25 落库)→ RFC-20261025-01(前置研究,两道闸齐)→ 三张清单(评核修后通过)→ 本立项案 v1 → **独立评审修后通过**(M1-M3/S1-S4 + 四步替代方案采纳;评审记录 `proposals/REVIEW-20261025-02-acceptance-executor.md`)→ 本 v2。
> **立项边界(三清单既定,v2 全部守住)**:最小面 = 验收执行器;新消费面 = 0;零新判据;Execute/状态机/需求卡不替;DDL 承载面明示未解决;impact.json 落点另案;「E1」禁用;变异证明不入判据。
> **状态**:**已拍板并落刀(2026-10-25 维护者「继续」)**——实现批 = `scripts/atlas_verify.py` 四步版 + `tests/test_atlas_verify.py` 七钉 + 变异 MB19/MB20 四段双咬 + gates 2.2/reference §10.1/DESIGN D150 登记;全量测试绿。真跑咬合 = 下一次真跑日经它起跑。

## 1. 现象与取证 (The Problem & Evidence)

- 真跑验收六步是 runbook(`docs/guide/real-run-day.md`,D148)不是机器行为:prepare 调用、结果汇总、留档、失败后的断点续跑全靠纪律,无幂等保证。
- 行为已散在各件无人统一:prepare 在控制台(D110/D121)、真跑+装配校验在 atlas_check、留证在 D108、留档靠手——三清单 P1-1:五面读的物全在库,缺的只是**行为者**;而 runbook 六步里**唯一没有机器承载的恰是「编排 + 统一报告 + 留档」三件事**(v1 评审的建设性判定,v2 采纳为范围)。
- 失败停环语义(apply §7)是条文态,无承载者。

## 2. 决策与权衡 (The Decision & Trade-offs)

### 2.1 核心定案:`scripts/atlas_verify.py` · 四步(v2)

纯标准库、幂等、无独立状态文件。**执行器 = 编排者 + 统一报告者 + 留档者,不重造真跑**(run 步以 `atlas_check` 为执行体——它自带 e2e.reset、可达性探测、pw_runner 三判据、真跑、装配门/manifest 路过,执行器不另起 Playwright):

1. **pre**:调项目自带 `atlas-prepare.mjs`(控制台同通道:`node`、180s 上限、失败/超时如实拒)。**批级 `ATLAS_CASE_ID` 语义(本 RFC 新声明,诚实注记)**:批级调用传显式串 `verify-batch`(非用例 ID;D121 契约是「当前用例 ID」,批级形态此前无既定语义——实现批在 `rings/e2e/reference.md` prepare 契约处补此注记);不读该变量的存量 prepare 脚本行为逐字节不变;逐用例分段准备仍归控制台逐条执行,本执行器不承载。**净场窗口归项目侧**(D110 已把净场机制化进 prepare 脚本;执行器不设独立静置参数、不换用途复用 `ATLAS_REFRESH_SETTLE`)。
2. **run = `atlas_check` 默认模式**(含全量真跑与装配门)——**全批只跑一次真跑**(单次真跑 = 钉;这同时保住 D108 留证不被第二次起跑清空——Playwright 起跑即清空 `.atlas-run`,双跑 = 首跑留证蒸发,gates 2.2 行 2026-10-25 活体事实)。
3. **report**:汇总 atlas_check 行集(stdout + `--json`,沿四态行形态,不造新格式)+ **落盘留档** `product/e2e/reviews/<日期>-verify/`(README 一行 + json 快照;收编 runbook 第 6 步留档)。
4. **backfill:缓行**(v1 评审 S1:回填与 D127/D128 账本语义融合需整轮设计——events.jsonl 进/不进、指纹先取、claim 仲裁、console「预览确认后写」纪律的豁免与否;首批不做 ⇒ **执行器写面零触碰**:不写 e2e-index 状态列、不进 events.jsonl、不取 claim,竞写问题不存在;真跑日后人走控制台提交评审如常)。

**失败停环(复用 apply §7,条文化为行为)**:任一步失败 ⇒ 停该步、结构化报告(哪步/为何/已完步产物清单);下游不静默跳过;重跑按产物存在跳过。失败不写任何 Trellis 状态字段。

### 2.2 步骤 × 产物 × 续跑判定表(v1 评审 M3 要求,v2 落表)

| 步 | 产物 | 续跑判定 | 如实注记 |
|---|---|---|---|
| pre | 无(改的是靶场服务端态) | **恒重跑**(幂等廉价) | 无产物即无可判跳过,不假装置态 |
| run | `.atlas-run/results.json` + `e2e-summary.json` + D108 留证构件 | 产物缺 ⇒ 重跑;**新鲜度依赖 Playwright 起跑清空 `.atlas-run` 的既有行为**(正常中途失败时产物必缺;若产物在 = 上一批成功态,由 report 留档的存在性先行短路,见下) | 清空行为 = Playwright 固有,执行器不新增 |
| report | `product/e2e/reviews/<日期>-verify/` | 留档在 ⇒ 整批短路(已成功的批不重跑) | 唯一的门户型产物 |

### 2.3 被否与不做(v1 表 + v2 增补)

| 备选 | 判 | 理由 |
|---|---|---|
| 执行器自起 Playwright(v1 五步版)+ 再调 atlas_check 验收 | **否(v1 致命伤)** | 双真跑:墙钟翻倍 + 首跑留证被第二跑清空 |
| 回填 e2e-index 状态列 | **缓行** | 第二写手风险 + 账本/指纹/claim 三题未设计;首批写面零触碰 |
| 独立净场步 / 独立静置参数 | 否 | 净场已机制化于 prepare(D110);复用 `ATLAS_REFRESH_SETTLE` = 换用途复用旋钮,违「不做新参数发明」 |
| 独立状态机文件 | 否 | 产物存在性已够;第二状态源 = 死结同族 |
| `--fast` 验收分支 | 否 | 门总览缺「E2E 真跑」行,「验收 = 既有门」落空;四步版根本不需要 |
| 证据跨轮归档 / DDL 承载面 / Execute·状态机·需求卡 / impact 落点迁移 / CLI 子命令(缓行,随发版批顺带)/ 新增验收判据 | 同 v1 | 前置链既定,不重开 |

## 4. 验证与测试结果 (Verification)

- **钉**(v2 七钉):① pre 失败注入 ⇒ 停步、结构化报告、无后续产物;② 批级 `ATLAS_CASE_ID` 值形态(= `verify-batch` 显式串);③ run 失败 ⇒ 报告含既有门行原样 + 留证构件路径;④ report 留档在 ⇒ 整批短路;⑤ 断点语义:pre 恒重跑、run 按产物、report 未产则补;⑥ **全批只跑一次真跑**(执行器进程内真跑子进程计数 = 1——v1 双跑风险的本体钉);⑦ 零变化(**收窄口径**):未调用执行器时,既有测试套件全绿且 atlas_check 行集零新增红(不宣称「全仓逐字节」)。
- **变异**(落刀时定号):摘「留档短路」⇒ ④红;摘「单次真跑」⇒ ⑥红。
- **超时口径**:pre = 180s(控制台同款);run = atlas_check 既有自身口径;report = 无。
- **真跑咬合**:下一次真跑日经执行器起跑(D148 runbook 机器化首用;咬合记录回 gates 2.2)。
- **出库判定**:首轮真跑日经它起跑,**四步各有如实状态**(pre 恒重跑注记在内)+ 单次真跑 + 留证不蒸发 + 留档在 ⇒ 出库。
- **实现批验收线(评审一句话版)**:干净采纳仓首跑全链绿(既有套件零新增红);逐步注入失败后重跑,报告指名失败步、全批只跑一次真跑、留证不蒸发、已完步按产物跳过而 pre 恒重跑如实。


## 附录 B · backfill 写面设计 v1(2026-10-25 起草;**待独立评审通过后才可实现**,本附录零代码)

> 回答 v1 评审 S1 拆出的四题。原则:**执行器永远不是第二真相源**——它写的每一处,既有写手与判据都不动。

### B1 状态列写手 = 复用 console 的 writeback 同一函数(单一来源)

- 执行器批后解析 `.atlas-run/results.json`,逐用例调 `e2e_console.py` 的**既有回写函数**(状态/状态原因两列;`scripts_hash` 白名单同源)——不另写行改写逻辑。
- 状态原因列注 `verify-batch`(机读标记:本行由执行器批写入;人审可分辨机器批与人批)。
- 反方声音:writeback 函数是控制台内部件,被执行器跨模块复用会形成隐式耦合——若嫌耦合,提炼到 `_support/`(提炼本身是 single-source 搬家仪式,另案)。

### B2 账本(events.jsonl)**不进**——裁决 + 理由

- 评审账本是**人工评审载体**(D127/D128:submit 快照、指纹、review_state 全为「人签字」语义);执行器批没有评审语义,写账 = 给账本混入机器行,review_state 复算语义被污染。
- 裁决:**只写索引状态列,永不写 events.jsonl**;「想对机器批做评审」= 人再走 console 对同一批提交(指纹机制天然支持)。

### B3 claim 仲裁 = 回填窗口全程持有 + 竞写窗如实披露

- 执行器回填前 `take`(write_claim.py 既有仲裁,`scripts/` 同款),写完 `release`——与「写面残留」门(`atlas_check` 既有行)对账。
- **如实披露**:console 当前 submit **不走 claim**(历史设计)⇒ 执行器持 claim 期间 console submit 仍可写 ⇒ 竞写窗 = 回填那几秒;缓解 = 执行器回填前读账本尾指纹、写后比对(变了 ⇒ 本次回填作废并报告「与人批撞窗,请重跑」);根治(console submit 也接 claim)= console 侧另案,不塞进本附录。
- D128 兜底:即使撞窗,submit 指纹比对会让陈旧方判 `stale` ⇒ 「需重审」语义天然兜住,不会静默错账。

### B4 预览纪律 = 豁免 + 操作者标记,三条件缺一不可

- console「预览 → 人确认后写」是**人工通道**纪律;执行器是机器通道,`ATLAS_ACTOR_TYPE=agent` 既有声明(D128)已如实自报操作者。
- 豁免条件(全部满足才豁免):① 写的是**既有用例的执行结果**(不新增/不改用例语义);② 状态原因带 `verify-batch`;③ 报告(stdout+留档)完整可溯。缺一 ⇒ 退回人工通道。
- 反方声音:机器批量写 green 可能「把人该看的东西自动签了」——不成立:回填只写**执行结果**,`reviewed` 评审态仍归人(console 提交);两列语义分离是既有设计。

### B5 实现批预览(评审通过后)

改动面:`scripts/atlas_verify.py` +1 步(claim → 回填 → release)、`tests/` +3 钉(B1 复用同函数 / B2 不进账本 / B3 撞窗作废)、`_support/write_claim.py` 复用不改动。验收 = playground 批后索引状态列与 results.json 一致 + 账本零变化 + 撞窗注入测试作废路径。
