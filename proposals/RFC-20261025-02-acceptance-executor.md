## 1. 现象与取证 (The Problem & Evidence)

- 真跑验收六步是 runbook(`docs/guide/real-run-day.md`,D148)不是机器行为:prepare 调用、结果汇总、留档、失败后的断点续跑全靠纪律,无幂等保证。
- 行为已散在各件无人统一:prepare 在控制台(D110/D121)、真跑+装配校验在 atlas_check、留证在 D108、留档靠手——三清单 P1-1:五面读的物全在库,缺的只是**行为者**;而 runbook 六步里**唯一没有机器承载的恰是「编排 + 统一报告 + 留档」三件事**(v1 评审的建设性判定,v2 采纳为范围)。
- 失败停环语义(apply §7)是条文态,无承载者。

## 2. 决策与权衡 (The Decision & Trade-offs)

### 2.1 核心定案:`scripts/atlas_verify.py` · 四步(v2)

纯标准库、幂等、无独立状态文件。**执行器 = 编排者 + 统一报告者 + 留档者,不重造真跑**(run 步以 `atlas_check` 为执行体——它自带 e2e.reset、可达性探测、pw_runner 三判据、真跑、装配门/manifest 路过,执行器不另起 Playwright):

1. **pre**:调项目自带 `atlas-prepare.mjs`(控制台同通道:`node`、180s 上限、失败/超时如实拒)。**批级 `ATLAS_CASE_ID` 语义(本 RFC 新声明,诚实注记)**:批级调用传显式串 `verify-batch`(非用例 ID;D121 契约是「当前用例 ID」,批级形态此前无既定语义——实现批在 `rings/e2e/reference.md` prepare 契约处补此注记);不读该变量的存量 prepare 脚本行为逐字节不变;逐用例分段准备仍归控制台逐条执行,本执行器不承载。**净场窗口归项目侧**(D110 已把净场机制化进 prepare 脚本;执行器不设独立静置参数、不换用途复用 `ATLAS_REFRESH_SETTLE`)。
2. **run = `atlas_check` 默认模式**(含全量真跑与装配门)——**全批只跑一次真跑**(单次真跑 = 钉;这同时保住 D108 留证不被第二次起跑清空——Playwright 起跑即清空 `.atlas-run`,双跑 = 首跑留证蒸发,gates 2.2 行 2026-10-25 活体事实)。
3. **report**:汇总 atlas_check 行集(stdout + `--json`,沿四态行形态,不造新格式)+ **落盘留档** `product/e2e/reviews/<日期>-verify/`(README 一行 + json 快照;收编 runbook 第 6 步留档)。
4. **backfill:缓行**(v1 评审 S1;**附录 B v2 已于 2026-10-26 随 D151 激活**——本条「缓行」语义由附录 B 接管:首批实现时执行器写面零触碰,回填作为独立步随附录 B v2 落刀,步序 = run 后、report 留档前)。

**失败停环(复用 apply §7,条文化为行为)**:任一步失败 ⇒ 停该步、结构化报告(哪步/为何/已完步产物清单);下游不静默跳过;重跑按产物存在跳过。失败不写任何 Trellis 状态字段。

### 2.2 步骤 × 产物 × 续跑判定表(v1 评审 M3 要求,v2 落表)

| 步 | 产物 | 续跑判定 | 如实注记 |
|---|---|---|---|
| pre | 无(改的是靶场服务端态) | **恒重跑**(幂等廉价) | 无产物即无可判跳过,不假装置态 |
| run | `.atlas-run/results.json` + `e2e-summary.json` + D108 留证构件 | 产物缺 ⇒ 重跑;**新鲜度依赖 Playwright 起跑清空 `.atlas-run` 的既有行为**(正常中途失败时产物必缺;若产物在 = 上一批成功态,由 report 留档的存在性先行短路,见下) | 清空行为 = Playwright 固有,执行器不新增 |
| report | `product/e2e/reviews/<日期>-verify/` | 留档在 ⇒ 整批短路(已成功的批不重跑) | 唯一的门户型产物 |

## 4. 验证与测试结果 (Verification)

- **钉**(v2 七钉):① pre 失败注入 ⇒ 停步、结构化报告、无后续产物;② 批级 `ATLAS_CASE_ID` 值形态(= `verify-batch` 显式串);③ run 失败 ⇒ 报告含既有门行原样 + 留证构件路径;④ report 留档在 ⇒ 整批短路;⑤ 断点语义:pre 恒重跑、run 按产物、report 未产则补;⑥ **全批只跑一次真跑**(执行器进程内真跑子进程计数 = 1——v1 双跑风险的本体钉);⑦ 零变化(**收窄口径**):未调用执行器时,既有测试套件全绿且 atlas_check 行集零新增红(不宣称「全仓逐字节」)。
- **变异**(落刀时定号):摘「留档短路」⇒ ④红;摘「单次真跑」⇒ ⑥红。
- **超时口径**:pre = 180s(控制台同款);run = atlas_check 既有自身口径;report = 无。
- **真跑咬合**:下一次真跑日经执行器起跑(D148 runbook 机器化首用;咬合记录回 gates 2.2)。
- **出库判定**:首轮真跑日经它起跑,**四步各有如实状态**(pre 恒重跑注记在内)+ 单次真跑 + 留证不蒸发 + 留档在 ⇒ 出库。
- **实现批验收线(评审一句话版)**:干净采纳仓首跑全链绿(既有套件零新增红);逐步注入失败后重跑,报告指名失败步、全批只跑一次真跑、留证不蒸发、已完步按产物跳过而 pre 恒重跑如实。


## 附录 B · backfill 写面设计 v2(2026-10-25 v1 起草;2026-10-26 独立评审**修后通过**——5 必修全落,评审记录 `proposals/REVIEW-20261026-01-backfill-write-surface.md`;随 `DESIGN.md` D151 落刀)

> 回答 v1 评审 S1 拆出的四题。原则:**执行器永远不是第二真相源**——它写的每一处,既有写手与判据都不动。
> v1→v2 变更(对应必修 1-5):机器标记从「索引状态原因列」改锚到**留档**(v1 锚点与 writeback 硬清空行为、校验器配对规则、词表闭集三方正面互斥,按 v1 措辞条条触发退回,附录整体落空);撞窗处置删「请重跑」(死路:全绿批已留档 ⇒ 重跑被短路,回不到 backfill)改「人工经 console 重提交」;撞窗基线写死为「尾 submit (ts, prov) + 文件字节/行数」并加辨伪(区间漂移);B4 三条件改**写前硬断言**;事实纠错(writeback 只写状态列;`write_claim.py` 在 `scripts/` 非 `_support/`)。

### B1 状态列写手 = 复用 console 的 writeback 同一函数(单一来源)

- 执行器批后解析 `.atlas-run/results.json`(Playwright JSON 报告;`suites[].specs[].title` 首词 = 用例 ID),逐用例调 `e2e_console.py` 的**既有回写函数**——**签名不变**、不改其任何行为。该函数只写 `状态` 一列(cells[6]),对 green/red **清空** `状态原因`(§8.2:原因仅 blocked/skipped 非空)——机器回填与人批回写在**索引内逐字节同形,不可分辨**;**分辨面 = 执行器留档**(report.json 回填章 + README 一行)。
- **机器标记锚点 = 留档,不进索引行**(必修 1):留档逐用例表键集 = 本次索引改动集键集(人审在留档里分辨机器批与人批;索引/校验器词表/配对规则零改动)。若将来要行级机读标记 ⇒ 显式另案(词表 + 配对规则 + writeback 三处同步),不塞本附录。
- **导入契约**(必修 5):`import e2e_console` / `write_claim` 按**装配态同目录**解析(`sys.path[0]` = 脚本所在目录——源包态 `scripts/`、采纳态 `.atlas/scripts/`,与控制台同副本同版本,无安装副本漂移);e2e_console 服务进程在 `__main__` 守卫内、导入不启服,其 `_support` 自举幂等无害;claim 粒度 = 整文件 `product/e2e/e2e-index.md`;claim task 名固定 `verify-backfill`(写面残留行的在办名)。**不提炼 `_support/`**(v1 反方声音裁决:一次 single-source 搬家仪式的价 > 一次 import 的耦合,导入契约入文即可)。
- 注:`verify-batch` 一物两用——批级 `ATLAS_CASE_ID` 值(D121 语义面)与留档批标记——**不是**索引词表值。

### B2 账本(events.jsonl)**不进**——裁决 + 理由

- 评审账本是**人工评审载体**(D127/D128:submit 快照、指纹、review_state 全为「人签字」语义);执行器批没有评审语义,写账 = 给账本混入机器行,review_state 复算语义被污染。
- 裁决:**只写索引状态列,永不写 events.jsonl**。**机器批无账本行;人工评审须经 console 逐条执行解锁——console 没有「导入执行器结果」的通道,人批 = console 逐条重执行;指纹保证的是评审新鲜度,不是结果搬运**(v2 措辞修正:删「指纹机制天然支持人再提交同一批」的不实表述)。

### B3 claim 仲裁 = 回填窗口全程持有 + 撞窗检测(基线写死)

- 执行器回填前 `take`(`scripts/write_claim.py` 既有仲裁;装配态 `.atlas/scripts/write_claim.py`,install.sh:448),写完 `release`——与「写面残留」门(`atlas_check` 既有行)对账;失败路径也 release(不产残留)。
- **撞窗基线(必修 3,机器可判定)**:回填前取 events.jsonl 的 **(字节数, 行数, 最后一条 submit 事件的 (ts, prov))** 三元组;复用 writeback 写完索引后**复检同一三元组**:
  - **尾 submit 变** ⇒ **撞窗**(人批 submit 是唯一写索引的账本事件)⇒ **退出非 0 + 结构化报告**——执行器持写前全文,如实列**覆盖差量**(本次意图改动逐行 + 写后索引现值 vs 意图值,被人批覆盖的行点名);**出路 = 人工经 console 重提交**(v2:删「请重跑」——若回填排在留档后,重跑被留档短路永远回不到 backfill;v2 步序下撞窗批不落档,重跑虽可再入但代价 = 全量真跑,D108 留证被清,故首选人批)。
  - **字节/行数变而尾 submit 不变** ⇒ **区间漂移**(账本有非 submit 事件写入,如控制台单条执行留痕;索引未被竞写)⇒ 报告注记、不阻断。
  - **与 D128 stale 的分工边界**(明写):stale = **渲染期**人审新鲜度(账本内快照 prov ⇔ 当前指纹,推给 UI);本检测 = **批期**活着检测(窗口内尾 submit 是否被人批顶掉)。职责不同,无重复。e2e-index.md 不在 `scripts_hash` 白名单 ⇒ 执行器自写索引不致人审误 stale。
- **竞写窗如实披露**(不变):console 当前 submit **不走 claim**(历史设计)⇒ 执行器持 claim 期间 console submit 仍可写 ⇒ 竞写窗 = 回填那几秒;本检测是**检测不是防损**(缓解);根治(console submit 也接 claim)= console 侧另案,不塞进本附录。D128 兜底不变:即使撞窗,人审新鲜度由 stale 语义兜住,不会静默错账。

### B4 预览纪律 = 写前硬断言(三断言,机器可判定;v1 三条件废除)

- console「预览 → 人确认后写」是**人工通道**纪律;执行器是机器通道,`ATLAS_ACTOR_TYPE=agent` 既有声明(D128)如实自报操作者。v1 的豁免三条件中「状态原因带 verify-batch」**机器不可满足**(必修 1/必修 4 前车),v2 改为**执行器写前硬断言**,断言不过 ⇒ exit 非 0:
  - **断言①**(只写既有用例执行结果):draft 键集 ⊆ 索引行 ID 集——writeback 对 draft 里索引不存在的键**静默丢弃**,故必须执行器自己数;未知 ID ⇒ 拒绝整批回填。
  - **断言②**(留档映射完整):留档逐用例表键集 == 本次索引改动集键集(每条改动可溯)。
  - **断言③**(报告完整可溯):report.json 含本次回填章——**步序保证**(回填排在留档前,见 B5),结构性成立。
  - 「缺一退回人工通道」= **路由建议**(人经 console 重提交),不是可判定条件;可判定的形态就是上面的 exit 非 0。
- 反方声音(机器批量写 green = 把人该看的自动签了)不成立:回填只写**执行结果**,`reviewed` 评审态仍归人(console 提交);两列语义分离是既有设计。

### B5 实现批(v2 落刀面)

- **步序 = pre → run → backfill → report(留档)**——回填插在 run 后、留档前(评审必修 2 的相互作用解):留档 ⇔ 全链绿**含回填成功**;失败批/撞窗批不落档 ⇒ 短路门户语义不变;**历史已留档批被短路 ⇒ 不回填**(索引状态由上批已回填或人批维护)。**红批不回填**(失败停环,回填窗口语义单一:仅全链绿批)。
- 改动面:`scripts/atlas_verify.py` +backfill 步(断言 → claim → 基线 → 复用 `e2e_console.writeback` 同函数回填 → 复检 → release)、`scripts/e2e_console.py::writeback` **零改动**、`scripts/write_claim.py` **零改动**、`tests/test_atlas_verify.py` +3 钉(⑧ B1 同函数:进程内 import 全等 + 记录器证回填走 `e2e_console.writeback` / ⑨ B2 账本零变化:回填前后 events.jsonl 字节不变 / ⑩ B3 撞窗:账本注入伪造 submit ⇒ exit 非 0 + 撞窗报告 + 不落档)。
- 变异:**MB22**(回填退回内联行改写、不走 console 同函数 ⇒ 钉⑧红)/ **MB23**(摘写后复检 ⇒ 钉⑩红),四段协议含注入 diff、还原逐字节一致。
- 验收 = playground 批后索引状态列与 results.json 一致 + 账本零变化(钉⑨)+ 撞窗注入作废路径(钉⑩);真跑咬合 = 下一次真跑日。
