## 1. 现象与取证 (The Problem & Evidence)

### 1.1 触发形态（抽象）

* **规则 / 环节**：D154 条目字段制式的「坏形状」判据（`duty-review/README.md:30` + `duty-review/families.py:81`）。
* **具体行为**：字段 `日期` 只做**形态**校验 `TAIL_DATE_RE = ^20\d\d-\d\d-\d\d$`（[families.py:43](file:///Users/sunwenzhe/Desktop/atlas/duty-review/families.py#L43) / [:81](file:///Users/sunwenzhe/Desktop/atlas/duty-review/families.py#L81)），**不做日历校验、不做未来上限**。于是：
  * `〔日期 2026-13-40〕`（13 月 40 日）被当合法字段日期；

## 2. 决策与权衡 (The Decision & Trade-offs)

### 2.1 核心定案

1. **归入既有坏形状分支，不另造语义**：`日期` 在形态通过后再过两关——
   * **日历关**：`datetime.date.fromisoformat` 解析失败 ⇒ 坏形状，原因「日期日历非法：<值>」；
   * **未来关**：解析出的日期 **晚于当日** ⇒ 坏形状，原因「日期晚于当日（越界）：<值>」；
   * 两者与现有「未知键 / 重复键 / 值空 / 值域外 / 缺日期 / 不闭合」走**同一出口**：运行面 WARN + 按无字段回退参与现行口径。
2. **当日从哪来（不引时钟不确定性）**：`families(text, today=…)` 已有 `day`，把它透传进 `parse_sections(text, today=None)` → `_tail_fields`；
   * `today=None`（直接调 `parse_sections` 的消费者 / CLI 之外的手工调用）⇒ **只校日历、不校未来**；CLI 路径 `main() → families()` 恒有 `day`，未来校验生效；
   * 钉一律显式传 `today=TODAY`，不依赖运行时钟。
3. **契约同步（canonical 是唯一真相源）**：`duty-review/README.md:30` 坏形状枚举把「日期形态非法」改写为「日期形态非法 / **日历非法** / **晚于当日**」，消除与 RFC-04 决策依据的分叉；`families.py` 头注同批改写（同一批，不留陈述漂移）。
4. **钉**：`tests/test_duty_bug_families.py` **+4**（11 → **15**）——
   * G1 日历非法 ⇒ WARN + 回退 ⇒ `族已静默`；
   * G2 未来日期 ⇒ WARN + 回退 ⇒ `族已静默`；
   * **反面包钉**：合法 cutoff 边界日期不被误伤（防「只挡越界」写成恒红判据）；
   * 判别性补强：尾注日期**晚于**字段日期 ⇒ `last_date` 取字段日期（既有钉 #1 咬不住的那个形态，**新增不替换**）；
   * 变异 **M158a**（摘日历关）/ **M158b**（摘未来关），四段协议。
5. **不动**：DR4 判据三项、案数上界计量、`族`/`证` 语义、`duty_signals.sh`（唯一接点 `:30` 只调 `families.py`）、`shared/gates.md` 门册（台账非流水线产物，承 D154 备选 C）。

### 2.2 考虑过的备选方案及否定理由

* **A. 把日历/未来校验也加到无字段条目的散文日期**：改的是 D154 明写的「无字段 = 行内散文日期」既有回退语义，真实库收益 = 0（非法/未来日期 0 条），却可能把存量段判翻面。否 ⇒ 登记为**残留盲区**并给升档条件（§5.1）。
* **B. 未来日期只 WARN 不回退（仍用字段日期抬窗）**：WARN 了但段仍永久活跃——把「响亮」做成了装饰，活跃窗照旧失真。否。
* **C. 给 `families.py` 加「允许 N 天时钟容差」配置键**：无实证需求（没有任何真实条目因跨时区被判越界），多一个可调键 = 投机灵活性。否；升档条件 = 采纳仓真的撞到跨时区落账。
* **D. 新立 `validate_bugs_ledger` 校验门**：D154 备选 C 已否过（台账非流水线产物，不值得上门册），本批不重演。否。
* **E. 直接改 D154 自带钉 #1 的夹具让它变判别**：改已跑绿钉的语义属混入他人批次，且会抹掉「钉 #1 当时在测什么」的历史。否 ⇒ 改为**新增**一条判别钉。

### 2.3 必须警惕的刺痛代价与兼容性影响

| 项 | 影响 |
|---|---|
| 代码量 | `families.py` 约 +6 行（两关 + 透传），无新文件、无新依赖（纯标准库）。 |
| 巡检信号 | 坏值多一条 WARN 行；现行真实库无坏值 ⇒ 日常输出零变化。 |
| 存量判据 | 不动（真实库无非法/未来日期，冻结基线钉守住）。 |
| 采纳项目 | `duty-review/` 不随 npm 包分发；测试文件随包但副本态既有 skipif 跳过。 |
| 人写侧 | 落账写错日期（如 `2026-13-40`）不再静默生效，而是出声 + 回退——行为变化是**更响**，不是更严的判据。 |

### 4.2 留出集（评审后重判：原 L1–L3 不合格，合格留出改走 CLI 巡检轨）

**先按 RFC-03 §2.1.4 自纠**（独立评审判为 blocker，理由成立）：下列三条**不构成**合格留出，已降级为「同类形态复测」——

| 原留出 | 判词 | 为什么不合格 |
|---|---|---|
| L1 `2026-02-30` | ❌ 降级 | 与缺口 G1 `2026-13-40` **同段形、同代码路径，只差日期串** ⇒ 属「同 fixture 改措辞」；且它只区分「月/日谁先校」的实现，而实现明写 `fromisoformat`，增益为零 |
| L2 `2026-09-26`（= cutoff） | ❌ 降级 | 与原矩阵 N3 / 机制演练 N1 同形 |
| L3 `2026-10-26`（= 当日） | ❌ 降级 | 与 D154 自带钉 #1 同形 |

更要命的是**红证来源错位**：§4.1 的 pre-fix 红来自按探针 G1/G2 新写的钉，L1–L3 只有 post 记录——拿「实现后补跑的同类夹具」当留出，正是 RFC-03 要防的「判据可被措辞满足」，只不过这次用在**试点判据自己身上**。

**合格留出 = 换通道，不换日期串**（`RFC-03` §2.1.4 的「另一条运行器轨 / 另一种装配态」）：15 条钉全部在进程内直调 `families()` / `render()`，**没有一条触达 `main()` 的 CLI/stdout 轨**（`duty_signals.sh:30` 即此轨）。夹具 = `/tmp/atlas-pilot/heldout_cli.md`，三段：未来日期 / 日历非法 / 合法对照。

```text
## 留出甲（未来日期 · CLI 轨）
- 同根归纳：同属一族
- #9001 案甲 2026-01-01〔日期 2027-03-14〕
...（留出乙 日历非法 2026-11-31；留出丙 合法 2026-10-05）
```

**pre-fix（D154 版，`python3 families_d154.py heldout_cli.md`）⇒ 红**：

```text

留出乙 … 最近日期=2026-11-31 | 升室候选   <== DR4 口径 B 候选
留出丙 … 最近日期=2026-10-05 | 升室候选

```

**post-fix（D155 版，同一命令）⇒ 绿**：

    WARN 条目字段形状：[留出甲…] 「日期」晚于当日（越界）：2027-03-14（已按无字段回退）
留出乙 … 最近日期=2026-01-01 | 族已静默
    WARN 条目字段形状：[留出乙…] 「日期」日历非法（形态过但非可用日期）：2026-11-31（已按无字段回退）
留出丙 … 最近日期=2026-10-05 | 升室候选（合法对照不受影响）

**这为什么算独立（v2 的说法，已被轮 2 复核部分驳回，见下）**：变化的维度是**通道**（`main()` + 文件读 + stdout 呈现 + 巡检实际消费面），不是把同一个日期串换个写法；pre 在该轨上把两段越界都判成「升室候选」且**不出声**，post 才出声并回退。

**反面包**：留出丙（合法日期）在 pre/post 均为「升室候选」且无 WARN ⇒ 收紧没误伤合法落账。

#### v3：轮 2 驳回「通道 = 留出」，改补两条判据级留出

轮 2 复核算了对方的账后判：**CLI 轨相对进程内钉只新增 `main()` 的 argv / 读文件 / `print` 三件事，两关判据一行都没新增**——同输入下 stdout 结论由 `_tail_fields` 唯一决定，通道给不出钉给不出的判词。它还实测：把 `print` 改成 `sys.stderr.write`，**15 条钉全绿而巡检 stdout 的 WARN 消失**。⇒ 该轨值得钉，但它钉的是**送达**，不是判据。本节上方 v2 的「这为什么算独立」因此只成立一半：**CLI 轨降格为送达钉，留出资格由下面两条承担**。

**新增三条钉（18 = 4 + 7 + 7）：归零路径 = 真判据级留出；`T+1` = 判别性补强（与 G2 同夹具日期串变体——年粒度变异下 G2 绿、唯它与 CLI 钉红）；CLI = 送达钉（轮 3 判词）**：

| 新钉 | 覆盖面 | 为什么是「新增信息」 | pre（D154 实测） | post（D155） |
|---|---|---|---|---|
| `test_all_bad_field_dates_zero_out_window_and_exact` | 段内字段日期**全越界**且零散文日期 ⇒ 走 `last_date=""` 的「无日期 ⇒ 已静默」分支 | 既有坏形状钉总留一条带散文日期的行，**从没有一条走到「日期全被拒 ⇒ 归零」**；还兼查 `exact` 不被越界条目虚计 | `last=2027-06-01 / 升室候选 / warns=0 / exact=2` | `last=- / 族已静默 / warns=2 / exact=None` |
| `test_tomorrow_field_date_rejected_but_today_accepted` | `T` 放行 + `T+1` 拒绝的**紧边界对** | G2 用的是 `2027-01-01` 远日期——只按「年份 > 当年」比较的偷懒实现能骗过它；`T`/`T+1` 这一对才钉住语义本身 | `T+1` 被当合法 ⇒ `last=2026-10-27 / 升室候选` | `T+1` ⇒ WARN「晚于当日」+ 回退 `2026-01-01` ⇒ 族已静默 |
