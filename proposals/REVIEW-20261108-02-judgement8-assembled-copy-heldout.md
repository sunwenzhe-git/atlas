## 2. 机械证据复核（全部成立）

1. **pre-fix 红**：判据⑧在装配副本态（根无 `skills/`）按 fail-closed 判红；采纳仓整包 `pytest .atlas/tests` 现场为 `1 failed / 1209 passed`。
2. **post-fix 绿**：`0c8d196` 用装配戳（`VERSION` / `MANIFEST.json`）分流，装配态判 `N/A`；单文件用例转绿。
3. **反面包**：源包态「无 `skills/` 且无装配戳」仍 fail-closed（`test_skill_budget_fail_closed_without_skills_or_stamp`）。
4. **变异杀伤**：撤掉装配戳分流分支，装配态病例复红，其余钉全绿——注入面与红因一致，未出现无关钉被牵连。

**边界**：这四项证明「修复在已知形态上有效」，不证明「换一批未参与挖弱点的案例仍有效」。后者才是 D156 要的闭族前提。

---

## 3. 留出集判定：无合格留出集

* 唯一候选 = **发现该缺陷的那个装配态**（采纳仓 `.atlas/`：根无 `skills/`、有装配戳）。
* 该形态正是本次修复的靶子（`#56` 的现场），参与过挖弱点 ⇒ 按 D156「未参与挖弱点」直接不合格。
* 仓内不存在第二个未参与本次修复的真实装配态；本机也无 `.atlas/tests` 可复跑。
* 因此：**不能判 `闭族`**。这属于「留出不合格」，不是「确无可行留出集」。

---

## 4. 「结构不可达」按严格读法不成立

* 独立性第 ③ 条要求：夹具**不可**由既有钉夹具只改日期串 / 通道 / 增删行得到。
* 实际：既有钉夹具就是一个空根目录（`tmp_path` + `monkeypatch PKG_ROOT`）；往这个空根里加一个 `VERSION` 文件，即可得到「装配戳副本」形态。
* ⇒ 结构不可达论证不成立。`test_skill_budget_assembled_copy_is_na` 本身就是这么构造的，这也从侧面证明该形态是「加一个文件」即可到达。
* 独立性第 ② 条（变异增量杀伤）只证明钉有牙，不能补上第 ③ 条的缺口。

---

## 5. 未覆盖的假阴面

判据⑧仍有以下静默面：

> 任何根上带 `VERSION` 或 `MANIFEST.json` 却**没有** `skills/` 的树，都会被静默判 `N/A`。

* 包括「源包根误放了一个 `VERSION`」的情形：判据⑧不会红，也不会提示，直接跳过。
* 现有反面包只覆盖「无戳 ⇒ fail-closed」，**未覆盖「有戳但其实是源包」**。
* 该面与 `#56` 的根因同属「以形态（文件名存在）代替实质（是否真为装配副本）」，但本次修复没有也不打算处理它。

## 6. 被否掉的替代解释

| 主张 | 判定 | 理由 |
|---|---|---|
| 「机械证据齐全 ⇒ 可以提 `闭族`」 | **否** | 机械证据只证明修复有效；无合格留出集，闭族缺 D156 的核心前提 |
| 「既然找不到留出集，就改判 `单案修复（无留出集）`」 | **否** | `单案修复` 要求「独立评审确认 + QUEUE 观察行 owner/期限 + 残留风险入 RFC §4.5」三件齐备；`#56` 三件当时都没有。且本件是「留出不合格」，不是「确无可行的留出集」 |
| 「结构不可达成立，所以无留出集」 | **否** | 严格读法下不成立：空根加一个 `VERSION` 即得到该夹具 |
| 「反面包已经覆盖了假阴面」 | **否** | 现有反面包只覆盖「无戳」，未覆盖「有戳却无 `skills/`」的静默 `N/A` |

## 7. 不符合项清单

1. **N1 无合格留出集**：唯一候选是发现缺陷的装配态，违反「未参与挖弱点」。
2. **N2 结构不可达论证不成立**：夹具可由既有空根夹具加一个 `VERSION` 文件得到。
3. **N3 反面包覆盖不全**：未覆盖「根有 `VERSION` / `MANIFEST.json` 却无 `skills/`」的静默 `N/A` 假阴面。
4. **N4 三态升级条件不齐**：`#56` 专属的「独立评审确认 + QUEUE 观察行 + RFC 残留风险记录」三件不齐，不能改判 `单案修复（无留出集）`。
5. **N5 真实采纳仓复验未取证**：修复后未在真实采纳仓复跑整包 `pytest .atlas/tests`；整包 `1 failed / 1209 passed` 是 **pre-fix** 现场记录，不能当作 post-fix 绿证。

---

## 8. 结论与后续

* **结论：`未闭族`**。不得标 `闭族`；不得标 `单案修复（无留出集）`。
* **本次归档的作用**：补齐「独立评审确认」与 `#56` 专属的 RFC 残留风险记录两项材料；**仍不足以**改判三态——QUEUE 观察行尚未为 `#56` 单独立行，且本件的前提是「留出不合格」而非「确无可行留出集」。
* **补验路径**：在未参与本次修复的真实采纳仓复跑装配态整包测试；或构造结构不同的装配态（例如有戳且另有 `skills/`）验证判据按字符数判而非静默 `N/A`。
* **重开条件**：`install` 侧装配戳变更；真实采纳仓出现该红未红 / 该 `N/A` 却红；另行立项修复「加文件即假阴」；本判定被后续独立评审推翻。

---

## 9. 本记录证明什么 / 不能证明什么

**证明**：机械证据（pre-fix 红 / post-fix 绿 / 反面包 / 变异杀伤）成立；本件没有合格留出集；因此维持 `未闭族`。

**不能证明**：不能证明判据⑧已经泛化；不能证明 `install` 侧装配戳不可仿造；不能证明仓外不存在会触发假阴的树；本记录不构成 `atlas_check` 门绿，也不替代实现评审。
