## 逐问判定

1. **事实核对——基本属实，行号全部命中，两处小错**。`families.py:26-49`(parse_sections docstring + 实现)、`:47-48`(段内任意文本取最大日期)、`:64`(`last_date` 空 ⇒ active=False)、`:80-81`(render“日期取证 = 段内文本里的日期，无日期 ⇒ 视为已静默”）全部与 RFC 引文逐行相符；README:28 口径 B 三条明示盲区 ✓、README:35 D131 逃逸条款措辞 ✓、bugs.md:3（`状态 = 开放 / 已修·待复验` 双态）✓、bugs.md:58 自感知段跨段交叉引用「跨段复见 E2E 段 #20、#24」✓。小错一：RFC §1.1(b) 称出库锚行含「#24–#30 **六个**」，bugs.md:19 实列 #24/#25/#26/#27/#28/#29/#30 **七个** id。小错二：RFC §1.1(a) 称陈旧说明「长期误判升室候选」——现行基线 structure 段判「族已静默」（试跑输出），(a) 型失真当前是前瞻性形态、无活体翻面实例，措辞应降为“将随出库史累积而实证”。

2. **判据语义守恒——不守恒，须拍板**。判据三项的**形状**（三布尔合取）不变，但其中两项的**计量基础被重定义**：案数从“段内 `#NN` 去重数（上界近似：含条目、归纳行、交叉引用——判据只问够不够 3）"（README:28，同义行 DESIGN.md:571）变为“条目自身 id 去重”；活跃窗从“段内任意文本最大日期"（families.py:47-48）变为“条目自身日期字段"。这构成对 2026-10-17 维护者拍板口径 B 的**重新解释**，按 README §2 DR1 本条要求“旧行号 + 新证据”入拍板——RFC 引了旧行号但全文无 DR1 框架，自称“判据三项原样"属过度自评。方向推演：上界 → 精确，案数**只减不增，升室更严**。实段推演：E2E 段现行上界 16（试跑输出），剔锚行 #24–#30 七个（bugs.md:19）、归纳行 #19/#20/#23/#R2（bugs.md:15，#R 系无数字不计数）与同段重复条目后，精确病案 = #10/#11/#12/#13/#14/#18/#19/#20/#23 共 9（bugs.md:21-29），16→9 仍 ≥3 无翻面；但构造场景——某段上界 3 中两条为引用 id ⇒ 精确 2 ⇒ 「升室候选」翻「案数不足」，判据的扩展（extension）可变。最轻量两选一：(i) 判据仍用上界计数，字段只提供精确案数做展示列（零语义变更、零拍板）；(ii) 维持 RFC 提法但显式落一行 DR1 拍板请求进 QUEUE。**（起草会话采 (i)，(ii) 并行登记进 §4.4 拍板依赖。）**

3. **兼容与等价——等价钉可达成，但今天是空钉，且混合段语义未定义**。试跑现行基线五段：structure 3 案/无日期/族已静默；E2E 16/2026-10-25/升室候选；安装与装配 3/2026-10-17/升室候选；图谱 无同根归纳；自感知 8/2026-10-17/升室候选。因现行 bugs.md **零条目带尾缀**（逐行核过 bugs.md:5-60），字段版对现行全文必然全退段级回退 ⇒ 五段结论逐字节不变，等价钉成立——成立得太便宜：它防不住字段消费语义的回归（对无字段文本两条路径同构）。手推“全精确”：structure 3→3 静默、E2E 16→9 升室候选、安装与装配 3→3 升室候选、自感知 8→4 升室候选——五段无一翻面；题设的“structure 段三条已修案由升室候选翻族已静默”**不成立**，structure 段在现行口径下本就无日期、本就静默，两口径下一致——故这是钉面设计问题不是 bug。真正风险在**混合段**：一段内同时存在带字段新条目与无字段旧条目时，案数/日期如何聚合 RFC 全文未定义，等价钉当下一个字段的落地就会失稳。钉应补两条正向钉：合成文本上“带今日日期字段的新条目 ⇒ 翻升室候选”与“段内陈旧收尾日期 + 无新条目字段 ⇒ 不抬窗”。
