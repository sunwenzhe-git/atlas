## 1. 现象与取证

### 1.1 登记表已不是登记表，是决策档案

**基线 = commit `c80182c`**（源包态）。数字全部取自该 sha；同日另有并行批在其后落盘（`60511d0`），实现轮如基线再动，按同口径重测。

**口径写死**：`## 2. 登记表` 与 `## 3.` 之间、以 `|` 开头、排除表头（首格 = `门`）与 `|---|` 分隔行之后的全部数据行。

| 指标 | 实测（`c80182c`） |
|---|---|
| 全文 | 68,081 字符 / 172 行 |
| 登记行 | **52 行**，合计 55,604 字符 |
| 单行中位 / 均值 | 769 / 1,069 |
| 超 1,200 字符 | **13 行** |
| 超 2,000 字符 | **3 行**：`E2E 真跑` 11,696 · `validators/validate_e2e_index.py` 3,181 · `scripts/validate_review_report.py` 2,058 |
| 最大单行占比 | 11,696 / 68,081 = **17.2%** |
| 行内含 | 日期串 157、`D` 号 91、`issue #` 46 |

### 1.2 机器可读性的三个缺口

1. **按前缀取行会漏 12 行**：52 行里只有 40 行首格是行内代码 / 路径（`| \`` 开头），另 12 行首格是门名文字（如 `完成门（E2E 状态机 + 收口）`、`变异证明（scripts/mutation_proof.py）`）。按前缀取行的脚本只数到 40。
2. **3 行分列错乱**：`validate_stack_profile.py`、`cli_review_convert.py`、`E2E 真跑` 三行的格内含有**未转义竖线**（含行内代码里的 `cli_status=partial|failed`），按未转义 `|` 切分得 7 格 ⇒ 渲染多出一列。
   *限定*：仓内**当前没有**按格切分登记行的消费者，所以这是预防性缺口，不是既成故障（评审指出，采纳）。
3. **行标识不稳定**：同一张表按不同前缀口径可数出 40 / 52 两个行数。「没有稳定行标识」本身是将来任何腰围门、覆盖率对账、逐行预算的先决障碍。

### 1.3 「E2E 真跑」行的构成（决定拆法）

实测该行 11,696 字符，按未转义 `|` 切成 7 格：

| 格 | 字符数 | 内容 |
|---|---|---|
| 1–2 | 8 / 9 | 门名、对账平面 |
| 3 判据 | **912** | 运行器可导入性 / 靶场可达性两态 / 浏览器就绪 / SKIP 三态 —— **这是真判据** |
| 4 不查什么 | 56 | 真栈没起来时的任何结论 |
| 5 预算 + 触发物 | 38 | 真栈就绪后（已发生） |
| 6 假绿测试 | **6,954** | 等级 + 历轮咬合叙述（D108 首咬合、D148/D149 兑现、D150/D151 执行器、MB1–MB23 四段协议…） |
| 7（溢出格） | **3,697** | 「人工会话取出 = 纪律与盲区面」整段 —— 因格内游离竖线被切出来的，实际是第 4 格的溢出 |

**结论：真判据只有 912 字符，其余 10,784 字符是流水与纪律叙述。** 这正是 §13 说「不得在契约正文复述」的那一类。

### 1.4 与 §13 的正面冲突

`shared/global-rules.md` §13 原文：

> 规则正文只写**当前设计**：可执行判定 + **台账号锚（≤ 一行指路）**；事故经过 / 日期考据 / 被否方案 / 案例 ID 流水**不得在契约正文复述**——归台账（纪要卷），锚是唯一指路。

§13 的存量豁免是「实测纯史叙事占比 ≈3–5%，低于 §12 动手线 ⇒ 不整卷回写」。但单行 11,696 已不是比例问题：判据、盲区、预算、等级、流水被压进同一格，读者要取「这道门查什么」必须读完整行。

## 2. 决策与权衡

### 2.1 核心定案

1. **§13 落地口径（补半句，不是新规则）**：门登记表每行只写「判据 + 不查什么 + 预算/触发物 + 取证等级 + 一行锚」；**轮次咬合流水归 `DESIGN.md` D 行与留档，表内不再追加**。锚保持一行，指路而不复述。
2. **首拆 `E2E 真跑` 行**：11,696 → **≤ 1,600 字符**。
   - **不新建承载文件**。被删的流水按其 D 号归位到 `DESIGN.md` 既有行（D108 / D148 / D149 / D150 / D151 / D114 / D115 / D121 / D124 / D144 / D173 / D174 等）；表内「假绿测试」列只留：等级 + 变异编号清单（每个编号后跟 ≤ 20 字的作用注解，如 `M12a 摘可达性探针`）+ 四段协议留档位置（`.atlas/runs/mutation-proof/`）。
   - **迁移前审计**：每个被删段落必须在其 D 行 / 留档中有等价记录。实现轮在 §5 附「删段 → 承载位置」对照表；**查无承载的先补进对应 D 行，再删**（已知两枚：`M12a` / `M12b` 全仓仅存于本行）。
3. **修 3 行游离竖线**（转义为 `\|`），使登记表可按未转义 `|` 稳定切分为 6 格。
   *副作用*：对 `gates.md` 做原样字符串搜索时，`partial|failed` 会变成 `partial\|failed`；按 `\|` 归一后再搜即可（实现轮在门行说明里记一句）。
4. **测试口径函数随本批落地**：`tests/` 内的登记行解析函数（处理转义竖线、首格非代码的行）与三枚钉同批进仓，**不再推迟到升格条件**（评审指出原稿把前提挂了空，采纳）。

### 2.2 上限定为 1,600 的推导（不是凑整）

按 §1.3 的构成：

```text
判据 912 + 不查什么 56 + 预算 38 + 钉清单 ≈ 330 + 指针/行开销 ≈ 60  =  ≈ 1,396
1,396 × 1.15（余量） ≈ 1,606  ⇒  取 1,600
```

**为什么不取 1,200**：1,200 < 判据本体 912 + 盲区 56 + 预算 38 + 钉清单 330 = 1,336，只能靠删判据文本达成——那是拿判据换腰围，不是本 RFC 的目的。用户 2026-11-03 拍板 **1,600**（确认推导，放弃先前的 1,200）。

### 2.3 考虑过的备选方案及否定理由

- **备选 A：新建 `shared/gates-detail/e2e-real-run.md` 承载流水**（原稿方案）
  *否定理由*（评审指出，采纳）：① `shared/global-rules.md` §13 明文「流水归台账（纪要卷）」，而 `shared/` 属契约包、随 `cp -R shared` 整体出库给采纳仓；② 本 RFC 第 1 条自己也定「流水归 `DESIGN.md` D 行」——同一类信息两个家，`single-source.md` §2「两处正文即判漂移」的构陷现成；③ 该行的流水与 `DESIGN.md` D108/D148/D150/D151 行**已经同文重复**，再迁一份入 `shared/` 就是第三处正文。「不是第二正文」的自辩不成立：单一真相源判的是「同一信息两处正文」，不看别名。
- **备选 B：字符快照 + 「只降不升」棘轮**（原稿方案）
  *否定理由*：① 门行的增长是**制度要求**——每轮真跑咬合都要往「假绿测试」列追加实测，`只降不升` 与该实践正面相撞；② 原稿上限推导建立在错误均值上（曾误算 1,114），属拍脑袋数字；③ 先拆一行拿到真实收益，再按 §2.4 的触发升格。
- **备选 C：整卷回写瘦身**——§13 明禁；66,810 字符一次性重写风险高于收益。
- **备选 D：全表总字符上限**——会逼着删「不查什么」列；盲区列是这张表最值钱的部分。

### 2.4 生效后的升格条件

首拆落地后，**任一登记行新增超过 2,000 字符**（存量 >2,000 的 2 行按 §5 逐次处理，不即时触发）⇒ 立机器棘轮。届时：

- 行集定义直接复用本批进仓的解析函数；
- 上限由该函数对**写死口径**的实收集算出，不用均值外推；
- 先在 QUEUE 观察室记一行触发依据，再立 RFC。

### 2.5 代价与兼容性

- 一次内容审计 + 迁移（11,696 字符里约 10,784 字符是流水）；最坏情况是发现某段无承载、需先补 D 行。
- 表内多一次跳转（锚指向 D 行），少一次通读。
- **采纳仓零行为变化**：不改生成物、不改退出码、不改任何判据；只改契约文本与新增一个测试文件。
