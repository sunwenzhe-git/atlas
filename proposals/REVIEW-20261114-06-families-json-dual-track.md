## 2. P0 修正

### 2.1 钉 1：不做真实台账冻结反查

* `families()` 内部取 `date.today()`；真实台账最近活动日期四周内必滑出 30 天窗，
  冻结「升室候选 / 族已静默」会在无代码变更时翻红。
* 改法：派生日期夹具（`today = date.today()` 推导，不绑死某天；中间约定日期不可写成未来日），
  与进程内 `families(夹具文本, today=today)` 的 rows **逐字段对照**。

### 2.2 登记面：七处逐文件指名

`shared/gates.md` 条数 / `tests/test_duty_bug_families.py:4-5` 计数行 + 分项 /
`duty-review/README.md:30` 钉数分解 / `duty-review/README.md:32` 指针钉表述 /
`duty-review/README.md:65` §4 输出描述 / `DESIGN.md` §12 新决策行 / `CHANGELOG.md` 新批段。
「介质不动」只指台账 / QUEUE 介质不动，登记面照常落。

## 3. P1 要点

* 双轨 = 第一次调用（人读）与第二次调用（`--json`）同源同参；marker 行供脚本定位。
* 变异三向：MB24 摘 `--json` 分支 ⇒ 钉 1/2 红；MB25 JSON 丢 warns ⇒ 钉 2 红；
  MB26 动 no-flag 输出 ⇒ 钉 3 红；红因集合必须恰等于被摘物。
* 序列化：显式挑 `family/count/exact/last_date/active/verdict/warns`，不序列化 `ids` / `exact_ids`。

## 4. 反方独立裁决

* **值得落刀的四个可核事实**：① 现网输出体积 1142 字节 / 6 行可实测；② 单源模块无机器出口属实；
  ③ `set` 序列化陷阱真实存在；④ 无旗标轨可逐字节保持。
* **不立项也站得住**：正则刮中文列在当前 6 行规模下成本可控，可继续沿用。
* 裁决：收益（机器对账稳定、免正则脆性）> 成本（≤1KB 增量 + 3 钉 + 3 变异），**采纳改造后方案**。
