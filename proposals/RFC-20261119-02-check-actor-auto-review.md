## 1. 现象与取证 (The Problem & Evidence)

### 1.1 触发形态（抽象）

- **规则 / 环节**：实现代码独立审查（`shared/independent-review.md` §1 实例⑤；CLI 式，2026-09-29 接入）。
- **触发时机**：一条改动实现完成、暂存之后。
- **具体行为**：判据面与编排器**齐备**（`atlas review --unit/--from/--to`，RFC-20261103-05，c80182c），但实例⑤ 的门禁挂点在**收口完成门**（closeout.md 步骤 10）——离实现完成**晚一整个阶段**。实现完成到收口之间，没有任何机器咬合点。该阶段的审查请求以**口头形态**存在：维护者在会话里手动说一句「review 一下暂存区的改动」，由当前 agent 裸看 diff 应答——不经实例⑤ 权威输入注入（需求卡 + 受影响域级 PRD 的 AC + 受影响用例分片），不落 `review.json`，不进账本，结论无 fresh context 保证。
- **宿主侧现状**：Trellis（宿主插件，定界前承担 check 动作）2026-09-29 后停更；其 check 子代理不持 Atlas 判据面，审查质量与 Atlas 门面体系脱节。BACKLOG §5 已裁「迁出」，但迁入的执行层实体不存在——动作悬空，回落到维护者口头指挥。


### 1.3 为什么是现在

- Trellis 停更（外部宿主插件冻结），「宿主子代理代跑 check」的现状不可持续；
- 定界已裁、账已挂（BACKLOG EL 系 + §5），缺的只是第一块实体；
- 维护者实测痛点（2026-11-19 口述）：check 环节「都是手动说的」。

## 2. 决策与权衡 (The Decision & Trade-offs)

### 2.1 核心定案（骨架层）

**check 行为者 = 触发 + 派工单生成 + 结果回收三件事，不重造审查本身。**

- **判据注入**：复用 `atlas review` 编排器既有 6 步（权威输入经 background 类机制注入，不喂整仓）——行为者是它的**自动入口**，不是替代。
- **执行**：沿实例⑤ 既有执行器（`impl_review` 声明的 CLI 式独立审查进程，判据一项不放宽）；行为者派工单含实例⑤ 维度表与权威输入清单。形态锚与触发面互为约束：会话外触发（钩子/命令行）可驱动 CLI 进程，**拉不起宿主子代理**（后者活在 agent 会话里）。
- **回收**：落点沿实例⑤ §10.3 写死形态：`product/reviews/<日期>-impl-review-<范围>/`（双份留痕 + review.json；v1 引「`<环>` 通式」是实例①②侧惯例，双评 Minor 命中已改）。
- **审修循环（2026-11-19 维护者拍板补，Trellis Verify 等界）**：findings 分两类修——**机械类**（lint/格式/import 排序等确定性工具变换）由行为者直接 `--fix` 修，重跑工具即复验、不占重审轮；**判断类**（逻辑/实现问题）findings 回流执行侧修复（当前形态 = 干活中的实现 agent；终局 = 实现编排器），**修完重跑一轮独立审查**（骨架条款 1「改完必须重跑全部维度」既有语义），循环默认上限 2，超限如实报告「人工接管」。体验等价于 trellis-check 的 self-fixing；差异仅一处——「过」的结论永远出自重跑的审，不出自修的那双手（证据链：出问题可分清「审错了」还是「修坏了」）。
- **确定性工具链衔接（同拍补）**：行为者起跑时顺带跑各仓 lint / type-check / tests（D100 否的是 pre-commit 挂钩，非行为者跑测试），结果并入同一份结构化报告。
- **许可红线（背景约束，非本案改动面）**：Trellis / mini-trellis 均为 AGPL-3.0，Atlas 为 Apache-2.0——干净室自建，不 fork、不搬代码、不做同源命名。

### 2.2 触发面三候选（本案唯一需维护者拍板点，待评审做实后收敛）

| 候选 | 形态 | 优势 | 代价 / 风险 |
|---|---|---|---|
| **A. git 钩子**（pre-commit / prepare-commit-msg / post-commit） | **commit 时点**触发派工——git 钩子面**无「暂存完成」事件**（`git add` 不触发任何钩子；v1「暂存完成即触发」不成立，双评 Critical 双命中） | 唯一会话外自动形态；触发点在编排者裁量权之外（终局接管后墙强度最高） | ① **与 D100 在案裁决同表面**（DESIGN.md:569，2026-10-17「git pre-commit 校验兜底不启用，启用留待 CI 一起落」）——采纳 A 须显式区分（D100 否的是同步校验兜底，A 是软形态审查派工）或显式翻案，随落刀登记；② **权威输入装配另案前置**：钩子进程手里只有 staged diff，需求 ID 无机器可寻址来源 ⇒ 实例⑤ 权威输入三件组装不出，强行触发 = 系统性产出「无法判定完整性」非结论报告；③ 接线面**无先例**（v1 所引「D110 先例」实为 e2e 逐用例数据准备脚本、「Windows 钩子启动器」服务于 `.trellis/config.yaml` after_archive，均非 git 钩子；install 全库零 git 钩子接线）——`.git/hooks` 不可版本化、per-clone 重装、无幂等接线器，全部新造；④ `--no-verify` 可绕过且无机器面可检；⑤ 按 commit 频率（含 WIP/amend/merge）重估成本，`independent-review.md` §6 第 1/5 条（delta + 内容哈希复用）可作降频手段、是否启用随落刀定 |
| B1. Trellis workflow 面包屑（RFC-20261103-07 同构） | Phase 2 结束出提示 | 成本最低 | 挂 Trellis workflow = 加深将退役脐带；提示 ≠ 执行。**否** |
| **B2. agent-pointer 纪律行**（双评审建设性方案） | 在 `patches/project-wiring` 的 A 面（Atlas 自有、版本化、Trellis 退役后仍存活）落一条实现期纪律条款：「实现完成暂存后先跑 `atlas review --staged`」 | **Atlas 自有面**（绕开 B1 脐带问题）；零新钩子面；与实例⑤ §10「实现期设纪律」边界天然同构；完全可逆 | 纪律 ≠ 门——跳过无机器面拦截（残余防线 = 收口门 + 「报告不存在 = 未审」） |
| C. 单命令入口（`atlas review --staged`） | 显式命令，一条口令全链 | 无自动化倒退风险；会话内/会话外皆可驱动（CLI 进程形态） | 不单独解决「手动说」本体；实现批须先验证底层 CLI 支持 index/工作树 diff（现有 `--from/--to` 参数面只有 REV，「小扩展」未证实——双评 Minor 命中，落钉账） |

**推荐倾向（v2，随双评修订）**：**v1 = B2 + C**（纪律行挂 agent-pointer 自有面 + `--staged` 入口），A 降为**条件候选**（前置：D100 显式区分案 + 权威输入装配另案）；观测期出口 = 维护者实测仍常跳过纪律行 ⇒ 立 D100 区分案或随 CI 批落（D100 本就指名「留待 CI 一起落」）。此倾向未定案，开口 1 待维护者拍。

### 2.3 被否与不做

| 备选 | 判 | 理由 |

## 4. 验证与测试结果 (Verification)

- **钉（v2 八钉）**：① pre 失败注入 ⇒ 停步、结构化报告、无后续产物——*此钉沿自验收执行器案形态，本案按触发面实配改写*；② 派工单含实例⑤ 权威输入三件（需求卡 / 受影响 AC / 受影响分片）；③ 审查结论落 `review.json`（对齐 §3 输出契约，`{ok,status,checks[]}`）；④ 无权威输入 ⇒ 不得给「通过」（骨架条款 6 硬口径）；⑤ 执行态标记如实自报（D128 同族）——**取值随触发面定**（钩子起进程时操作者 = 脚本进程，照抄 `agent` 失真；落刀时定值，挂账防实现批顺手抄——双评 Minor 命中）；⑥ 触发→报告落点 = `product/reviews/<日期>-impl-review-<范围>/`（实例⑤ §10.3 形态）；⑦ `--staged` 若立：底层 CLI 支持 index/工作树 diff 的验证记录（「小扩展」证实）；⑧ 零变化：未触发时既有套件全绿、门行集零新增红（含：自动报告不改变既有门行集——「报告定位」消费语义不动，双评 Major 命中并入）。
- **真跑咬合**：下一次实现批经行为者起审查，留档含口头请求对照（本次手动形态 → 触发形态）。
- **验收线（2026-11-19 维护者口径：「改完就能用，不比之前用 Trellis 效果差」）**：
  - **装配即用线**：实现批合入后，本仓与采纳仓装配态开箱可用——agent-pointer 纪律行随装配生效（agent 到步自跑）、`atlas review --staged` 可直接执行；不要求使用者改任何既有习惯之外的东西。
  - **对照线（不差于 Trellis Verify 的可判定判据）**：连续 3 个真实实现批经行为者走完，**四不缺**——① 全程维护者零开口触发（对照现状：每批一次口头请求）；② 注入 = 权威输入三件最小集，不喂整仓（骨架条款 6 同时保证缺件不给通过）；③ lint / type-check / tests 并入同一份结构化报告（Trellis Verify 同款三件）；④ 审修循环闭合（机械修直接修、判断修修完重审、上限内修不动则如实报人工接管）。留证面（review.json + 账本 + round 序列）为 Atlas 既有优势项，自然带出不另设线。
  - **同批对照（必做，2026-11-19 维护者升级）**：场所 = **playground 合成靶场**（资产 `tests/fixtures/verify_playground/`，运行面 `/tmp/atlas-e2e/playground` 同生同灭——运行面已失则从 fixture 重建）。流程：同一实现 diff（含预置的规范类 + AC 类问题）双跑——Trellis 侧 vs 行为者侧。**Trellis 侧形态注记（2026-11-19 实探）**：其 CLI（0.7.0-beta.4）无 check/implement 命令，Verify 为会话内 workflow 子代理形态 ⇒ 对照按其 curated spec 注入面构造等价审查（同 diff + 其 spec 集注入 → 宿主子代理执行），形态差异在对照留档中如实记录，不伪装同环境。判据四栏：findings 数量 / 分级分布 / 依据可得性（每条 finding 能否溯到 AC 或契约锚）/ 触发形态（零开口 vs 会话内 phase 自动）。对照结论落 `reviews/` 留档；**「不差」任一栏劣于 Trellis 即打回实现批，不算完成**。
- **变异（落刀时定号）**：摘「权威输入注入」⇒ ①红；摘「无输入不给通过」⇒ ③红。
