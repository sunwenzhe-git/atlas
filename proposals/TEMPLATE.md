### 4.5 留出验证（系统性修复必填；`RFC-20261026-03`）

* **触发面核对**：(a) RFC §1 引子族锚（`bugs.md` 同根归纳）或 ≥3 条独立审查重复 finding；(b) 改门 / 校验器 / 契约判据且 diff 落在 DR4 段级锚路径族（路径交叉检查 = `git diff --name-only` + `scripts/closeout_derive.py` 路径族表手工对照，记「锚 → 路径族」映射与误报）；都不触发 ⇒ 写「不适用」+ 核对依据。
* **留出集**：未参与挖弱点（§1 探针 / 原失败用例 / 同夹具改写 / 看到修复后才补写的期望）的案例；独立性三条 = ①判据输出翻转（verdict / 案数 / 最近日期 / 精确病案数；仅 WARN 文本 / 日志 / 通道变化不算）②变异增量杀伤（既有钉全绿而留出案红）③结构不可达（不可由既有钉夹具只改日期串 / 通道 / 增删行得到）——附预跑输出；「只换日期串 / 只换调用通道」不合格。
* **pre-fix 红**：修复前实跑命令 + 输出（红不了 ⇒ 换用例；换不出 ⇒ 三态只能走「单案修复」）。
* **post-fix 绿**：同一留出集实跑输出。
* **反面包**：合法输入不误伤（两版一致）。
* **三态结论**：`闭族` / `未闭族` / `单案修复（无留出集）`——末者须评审确认「确无可行留出集」+ QUEUE 观察行 owner / 补验期限 + 残留风险写进本节，不得宣称闭族。
* **耗时与评审**：设计 + 运行耗时、评审轮次；唯一判定记录 = 本节 + 其 REVIEW（不新增台账；`bugs.md` 指针行 `- 留出验证：RFC-… / REVIEW-…`，无状态 / 无日期 / 无 `#NN`）。
