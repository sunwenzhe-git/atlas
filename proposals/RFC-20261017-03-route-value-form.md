# RFC-20261017-03 · 「路由值形态」判据：做还是不做（**推荐：判接受 + 写死升判条件**）

- 状态：**v2（已按独立评审补齐 MUST×3 / SHOULD×4）**；评审成品 `proposals/REVIEW-2026-10-17-route-value-form.*`
- 缘起：D94 ③ 登记的独立待办（原文，`CHANGELOG.md:183`）：
  > **值形态判据**：`/x/1/FUZZY` 这类「合法前缀 + **无注释的真垃圾尾**」仍判 PASS（需在 `_route_hit` 前叠「值形态」判据 + `reference.md` §8.2 契约增量；当前前缀命中口径是**有意设计**，单独收紧会把合法带参路径打红）
- 输出语言：中文

## 1. 现状（判据与它的声明）

`validators/validate_e2e_index.py::_route_hit`（`goto` 门与 `守卫` 门共用）：

```python
if p in page_routes: return True
return any(r != "/" and p.startswith(r + "/") for r in page_routes)
```

契约 `rings/e2e/reference.md:511`（§8.2）原文：**精确命中，或非根路由的子路径前缀命中**（`/projects/x` 匹配 `/projects`；根 `/` 仅精确）；**这套前缀口径写明是「有意设计」**（带参页面友好）。

⇒ 已知弱点：**前缀命中无法区分「合法的带参实例」与「合法前缀 + 垃圾尾」**，后者会被判 PASS（假 PASS 通道）。

## 2. 证据（决定要不要做的关键）

| 事实 | 取证 |
|---|---|
| **没有一条现场假 PASS 实例** | 全仓检索只有 D94 自陈的**理论**例子 `/x/1/FUZZY`，无任何项目现场 |
| 真实**正例**长这样 | `/console/#/app/agent/detail/2110669642083168258`（壳前缀 + `#` + 多段 + 数字）、`/home/42`、`/home/#/42`（D104 后的 hash 形态） |
| 现行前缀口径是**契约明写**的，不是实现漂移 | `reference.md:511` |
| **值形态的事实源存在** | `.trellis/spec/structure/global/routes.md`（`atlas:facts` 块）就是**模式形态**：`/app/agent/detail/:id`、`/market/app/agent/:id`（v2 实测 63 行） |

## 3. 三案

### 案 C（**推荐**）：判「接受」，把待办**关掉**，写死升判条件

- **做法**：不改判据；在 D94 ③ 行尾追记「**判接受**：无现场实例；前缀命中是契约有意设计；假 PASS 的实际后果由**真跑 404**兜住（导航到不存在路径 ⇒ 元素守卫在 goto 后即红）」。删掉待办身份，改为**已知边界（明示）**。
- **理由（v2 已按评审替换 —— 旧理由② 是假的，见 §3.5）**：
  1. **无现场实例**：全仓只有本行自陈的**理论**例子（`CHANGELOG.md:183`、`:166`），零个项目撞到；
  2. **前缀命中是契约有意设计**：`rings/e2e/reference.md:511`（§8.2）原文就写「非根路由的子路径前缀命中」，`validate_e2e_index.py:317-318` 的 docstring 同口径 —— 收紧前须先动契约；
  3. **收紧的代价落在「会误伤合法带参路径」上**，而唯一可行的收紧（B′）要引入跨环事实源（§3.4），成本/风险高于当前收益。
- **代价（如实，**不含**「真跑会兜住」）**：文本期少一道形态门，错误路径可能一路绿到真跑；而**真跑兜底是不可靠的**（§3.5）。
- ⚠️ **不得**把「真跑 404 ⇒ 元素守卫必红」写成接受理由（v1 的错，见 §3.5）。

### 案 B′：用 **structure 路由事实**派生值形态判据（升判时首选）

- **做法**：`validate_e2e_index` 增一档门：`goto`/`守卫` 路径**规范化**后必须匹配 `routes.md` 里某条**真实路由模式**（`:param` 段吃任意非空段）。
  - 规范化（缺一不可）：去壳前缀（`app_base_url` 的 path 部分，如 `/console/`）→ 去 `#` → 按 `/` 分段。
  - 事实缺失（未跑结构环 / `routes.md` 无该页）⇒ **`SKIP` + 原因**（不判红，沿用三态前置纪律）。
- **优点**：判据有**真实事实源**（不是字符白名单启发式）；`/x/1/FUZZY` 这类多出的段 ⇒ 无模式可匹配 ⇒ 红。
- **风险（都比 C 大）**：① 跨环读取（e2e 环读 structure 事实）+ 事实漂移 ⇒ 假红；② hash/壳前缀规范化本身就是**今天已经被推翻过一次**的那类假设（RFC-01 的 A 案教训）；③ 事实表按「应用 + 页面/路由」组织，与页面表 `路由` 列的**业务段**语义要对账；④ 成本：新增门 + 契约增量 + 两条钉 + 变异。

### 案 A：字符形态白名单（**不推荐**）

- 如「路径段仅允许 `[A-Za-z0-9._~-]`」或「禁止全大写词」。**不可判**：`/home/42` 与 `/home/42/FUZZY` 都合法字符；白名单只能挡「非法字符」，挡不住「合法字符的垃圾段」——它解决不了 D94 描述的那个问题，只会新增误伤面。

### 3.4 B′ 的规范化修正（评审 MUST：v1 的壳前缀来源错了）

| 项 | v1 写的 | 评审指正 → v2 |
|---|---|---|
| 壳前缀来源 | 「取 `e2e.app_base_url` 的 path」 | **错**：该值带 query（`stack-profile.yaml:54` 的 `…/console/?switchAgent=7202`），且 `ATLAS_BASE_URL` 只覆盖 host、不覆盖 base 的 query（`url_merge.py:18`）⇒ 从中取 path 要多剥一层、脆。**改从页面表 `路由` 自身在 `#` 处切分**（`/console/` + 业务段），零外部依赖 |
| 剥注释序 | 未写 | **先剥行内注释再切 `#`**（`#` 必须紧邻 `/` 才不被注释语义吞，`reference.md:78`） |
| 多应用 / 未实现行 | 未写 | structure 事实含 `实现状态`（`/upload-demo` 未实现、`/component` 部分）与可选段 / splat（`/rag/:kbId/:tab?`）⇒ 参与匹配的行集合、可选段与 splat 语义须先定 |
| **原则冲突（更根本）** | 未写 | `reference.md:470`：**页面 URL = 页面表，唯一来源，不从文件系统派生**。B′ 让 e2e 环路由门读 structure 事实 = 把 `路由` 列的权威**分给两个环**（`D90` 的「一字段两相反语义」教训同族）⇒ 升判前须先解此冲突 |

⇒ B′ **可作升判首选方向，但 v1 的规则不可照抄**。

### 3.5 v1 的核心理由为何不成立（评审 MUST，本节保留以免重犯）

v1 写「该假 PASS **不是假绿**：真跑 404 ⇒ 元素守卫 `toHaveCount(1)` 必红」。评审用两条**取证到的**反例推翻：

1. **壳层 testid 兜底型**：守卫红的前提是 `testid:` 清单**全缺席**；而 `reference.md:80`（§3.2）明写**壳层 testid 也在页面应然清单里** —— 垃圾尾落到 NotFound、但 NotFound 在**同一壳布局**内渲染时，清单里的壳层 id 仍在 ⇒ 守卫**绿**。
2. **宽匹配 / catch-all 路由型**：structure 事实里已有 `/app/:tab`、`/market/:type`、`/rag/:kbId/:tab?` 这类段；若路由对多余尾段宽匹配（或尾段被当 `:tab` 消费），页面照常渲染、断言目标在场 ⇒ 绿。

**第二重漏洞**：即便 404 真的必红，兜底也不可靠 —— 地址空 / 靶场不可达 ⇒ 真跑门 **SKIP**（`reference.md:437`）；`blocked`/`skipped` 用例执行按钮**禁用**（`:613`）；有门无形态的靶场走 **D103 人工会话**（不可复现、CI 不可用）。多场景下「兜底」等价于不兜。

⇒ 判接受的依据只能是 §3（案 C）里那三条，**不是**兜底。

### 3.6 案 D′（同环实例段数上界）—— 评审提出，**不背书、不做**

- **判据**：以页面表路由为前缀的**同环已存实例**（分片 `goto:`/`守卫:` 值）取最大段数为上界，超出 ⇒ `WARN`。
- **优点**：同环、零跨环事实、零契约增量、不动既有判定。
- **不做**：① 收益面窄（只覆盖「已有更长实例的页」）；② `WARN` 不足以在文本期挡住垃圾尾；③ 误伤：该路由只有一条实例且它是最长合法形态时，合法新增参数段会假 WARN；无实例页面空转。
- **评审亦不背书**（"我不为它背书"）。

## 4. 推荐结论

**走 C**：判接受、关待办、改为「已知边界（明示接受）」。

**升判条件（v2 按评审 MUST 改写 —— v1 的「出现实例即自动转 DR4」几乎不可触发，等于永久关闭却伪装成自动升判）**：

> **升判口径 = 维护者，非自动**：默认不收紧；**仅当维护者拍板**才立项，立项形态为「**页面表路由自派生壳前缀 + structure 事实仅作 `:param` 段数佐证**」（§3.4），不做案 A。**不设**「出现实例即自动升判」。

理由：真跑在地址空 / 靶场不可达时 `SKIP`、`blocked` 用例不可执行、且系统**不回写「根因」字段** ⇒ 「文本期 PASS ∧ 真跑红 ∧ 根因=垃圾尾」这一对事实**没有落盘位置**；真跑红的根因排查第一顺位也不是「路径多一段」。
