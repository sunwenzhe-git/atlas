# RFC-20261017-03 · 「路由值形态」判据：做还是不做（**推荐：判接受 + 写死升判条件**）

- 状态：**待独立评审**；本文只是方案，未改代码
- 缘起：D94 ③ 登记的独立待办（原文，`CHANGELOG.md:183`）：
  > **值形态判据**：`/x/1/FUZZY` 这类「合法前缀 + **无注释的真垃圾尾**」仍判 PASS（需在 `_route_hit` 前叠「值形态」判据 + `reference.md` §8.2 契约增量；当前前缀命中口径是**有意设计**，单独收紧会把合法带参路径打红）
- 输出语言：中文

## 1. 现状（判据与它的声明）

`validators/validate_e2e_index.py::_route_hit`（`goto` 门与 `守卫` 门共用）：

```python
if p in page_routes: return True
return any(r != "/" and p.startswith(r + "/") for r in page_routes)
```

契约 `rings/e2e/reference.md:511`（§8.2）原文：**精确命中，或非根路由的子路径前缀命中**（`/projects/x` 匹配 `/projects`；根 `/` 仅精确）；**这套前缀口径写明是「有意设计」**（带参页面友好）。

⇒ 已知弱点：**前缀命中无法区分「合法的带参实例」与「合法前缀 + 垃圾尾」**，后者会被判 PASS（假 PASS 通道）。

## 2. 证据（决定要不要做的关键）

| 事实 | 取证 |
|---|---|
| **没有一条现场假 PASS 实例** | 全仓检索只有 D94 自陈的**理论**例子 `/x/1/FUZZY`，无任何项目现场 |
| 真实**正例**长这样 | `/console/#/app/agent/detail/2110669642083168258`（壳前缀 + `#` + 多段 + 数字）、`/home/42`、`/home/#/42`（D104 后的 hash 形态） |
| 现行前缀口径是**契约明写**的，不是实现漂移 | `reference.md:511` |
| **值形态的事实源存在** | `.trellis/spec/structure/global/routes.md`（`atlas:facts` 块）就是**模式形态**：`/app/agent/detail/:id`、`/market/app/agent/:id`（v2 实测 63 行） |

## 3. 三案

### 案 C（**推荐**）：判「接受」，把待办**关掉**，写死升判条件

- **做法**：不改判据；在 D94 ③ 行尾追记「**判接受**：无现场实例；前缀命中是契约有意设计；假 PASS 的实际后果由**真跑 404**兜住（导航到不存在路径 ⇒ 元素守卫在 goto 后即红）」。删掉待办身份，改为**已知边界（明示）**。
- **理由**：
  1. 本仓纪律：**不为理论风险加一条会误伤合法用的门**（`D94 ③` 自己就写了「单独收紧会把合法带参路径打红」）；
  2. 该假 PASS **不是假绿**：它只让「写错的路径」通过**文本期**，真跑时 `page.goto` 404 ⇒ 元素守卫 `toHaveCount(1)` 必红 ⇒ **现场可发现**（与「门看着绿、东西用不了」那族不同，后者才是本仓最忌的）；
  3. 零成本、零回归面。
- **代价（如实）**：文本期少一道形态门；错误路径要跑到**真跑**才现形（真跑本来就要跑）。

### 案 B′：用 **structure 路由事实**派生值形态判据（升判时首选）

- **做法**：`validate_e2e_index` 增一档门：`goto`/`守卫` 路径**规范化**后必须匹配 `routes.md` 里某条**真实路由模式**（`:param` 段吃任意非空段）。
  - 规范化（缺一不可）：去壳前缀（`app_base_url` 的 path 部分，如 `/console/`）→ 去 `#` → 按 `/` 分段。
  - 事实缺失（未跑结构环 / `routes.md` 无该页）⇒ **`SKIP` + 原因**（不判红，沿用三态前置纪律）。
- **优点**：判据有**真实事实源**（不是字符白名单启发式）；`/x/1/FUZZY` 这类多出的段 ⇒ 无模式可匹配 ⇒ 红。
- **风险（都比 C 大）**：① 跨环读取（e2e 环读 structure 事实）+ 事实漂移 ⇒ 假红；② hash/壳前缀规范化本身就是**今天已经被推翻过一次**的那类假设（RFC-01 的 A 案教训）；③ 事实表按「应用 + 页面/路由」组织，与页面表 `路由` 列的**业务段**语义要对账；④ 成本：新增门 + 契约增量 + 两条钉 + 变异。

### 案 A：字符形态白名单（**不推荐**）

- 如「路径段仅允许 `[A-Za-z0-9._~-]`」或「禁止全大写词」。**不可判**：`/home/42` 与 `/home/42/FUZZY` 都合法字符；白名单只能挡「非法字符」，挡不住「合法字符的垃圾段」——它解决不了 D94 描述的那个问题，只会新增误伤面。

## 4. 推荐结论

**走 C**：判接受、关待办、改为「已知边界」并写清升判条件：

> **升判条件（写进 D94 ③）**：出现 **≥1 条现场实例**——某用例的 `goto`/`守卫` 路径在文本期被判 PASS、而真跑因 404 / 元素缺席而红，且根因确为「合法前缀 + 垃圾尾」⇒ 转 DR4，按 **案 B′** 立项（含规范化规则与 `SKIP` 语义），不做案 A。
