## 1. 现象与取证 (The Problem & Evidence)

### 1.1 触发形态（抽象）

* **规则 / 环节**：真跑日协议（`docs/guide/real-run-day.md`，D148：detached worktree 隔离执行、七项咬合清单）。协议只回答「这轮真跑把哪些已立待咬的能力咬合了」，**没有摩擦面与宏观消融面**——每个机制每次真跑吃多少人工分钟（摩擦账）、机械整体在摘除态下四件事是否照常（宏观消融），均无承载。
* **触发时机**：任一真跑日准备时。
* **具体行为**：三个在案待办长期无排期载体——①「过重」感受只有主观账：微观变异即红有证，**宏观净贡献未测**、反事实不作判据；成本面只有门级耗时观测（D137，见 §1.2），人工同步与重装配环节零计量；②宏观消融（**2026-10-24 案 8** 拍板方向，`duty-review/QUEUE.md:73`）无下轮排期；③覆盖维度「四判据实测」（RFC-20261106-01 剩步，首轮 2026-11-06 已执行）一直未与真跑日合并。

### 1.2 客观证据 (Evidence)

- 本批（RFC-20261114-01）落地过程实测：出厂测试在采纳仓默认门 **9 分 22 秒 + 7 failed**；计数棘轮四面人工改齐 + 跑三面 ≈ 9 分钟——**摩擦账一采集就出真数字**；而这些数字此前无处落。
- **已有观测面**：D137 已把 `atlas_check` 逐门耗时落成 `duration_ms`（`DESIGN.md:606`）——门级耗时**不是零计量**；缺口是门之外的人工环节（同步动作 / 重装配 / 留档）。摩擦账只补这一段，并抽检一笔与 `duration_ms` 对账（防自指）。
- 消融工具已就位：`scripts/ablation.py`（RFC-20261101-04，begin/restore/status 事务，隔离场实测三判据全过）——宏观消融的机械面零新建。
- **宏观消融的真实空白**：`research/2026-10-25-net-contribution-ledger.md` 是只读聚合（零新实验、无真场摘除）；**本提案 §6 那轮才是第一次工具化真场宏观消融**。
- 防度量自指教训（RFC-20261106-01 独立评审核心）：计量判据必须人工抽检，不得自指。
- 三待办同源：摩擦账 / 宏观消融 / 四判据实测全部要求「真跑 + 真实采纳仓」场景，分开排期 = 真跑日重复准备（每轮七项咬合同样的前置成本）。

## 2. 决策与权衡 (The Decision & Trade-offs)

### 2.1 核心定案 (The Decision)

* **方案总结**：`docs/guide/real-run-day.md` 增补一节 **「§6 摩擦账与宏观消融」**（现有 §0–§5，节号顺延为 §6），三件事合并进同一真跑日：
  1. **摩擦账**：真跑日全程逐机制计时（每道门单跑耗时 / 每次同步动作人工分钟数 / 每次重装配耗时），格式 = 一张表（机制｜触发点｜耗时｜当轮咬合次数），落点是 **worktree 根目录的 `friction-ledger-<日期>.md`**——**不落 `.atlas-run/`**（Playwright 每次起跑会清空它，`real-run-day.md:20`）；raw 副本随当日留档进 `product/e2e/reviews/<日期>/`，防誊写无对账。**汇总数字回写 §6 表格**（协议页保留最近两轮对比；回写树 = atlas 源仓的这页协议，靶场 worktree 与用户 checkout 不留原件）。判据 = 人工秒表级计时 + **抽检一笔与 D137 `duration_ms` 对账**，不做自动埋点（防度量自指，零新门零新字段）。
  2. **宏观消融**：同一 worktree 内跑一轮 `ablation.py begin → 四件事验证 → restore`。摘除候选集 ⊆ `.atlas/` 装配面（host_mode=adopter），按最近一轮摩擦账的「低价值高成本」象限逐格选定，**每次真跑日前由维护者拍板**；**候选集无账可依的冷启动轮**按维护者判断选定，并在表中记「选择依据」。**咬合次数是筛选输入不是价值判决**（D108 留证类绿轮零咬合 ≠ 低价值，不得因「没咬到」就摘）。窗口内四件事指名清单：`atlas check --fast` / 分片重生成对账 / 一条冒烟用例 / `bugs.md` 一行回写演练——**全量 E2E 不进窗口**。判据沿用 RFC-20261114-01 §1.2 三判据形态（fast 逐行 diff / 门行状态 / restore hash）。
  3. **四判据实测合并**：覆盖维度「四判据实测」（RFC-20261106-01 剩步）与本节同场执行——同一场真跑产出三份数据（摩擦账 / 消融差分 / 四判据），排期声明 = 「下一次真跑日三件必跑，缺一在收口注记缺因」。**四判据前置（缺一即记「门未咬合原因」，不静默空转）**：① 该轮已**单独拍板 apply 需求增量**（RFC-20261106-01:120 的在案动作，不是真跑日顺手做）；② 实测域含**覆盖就绪页**（否则判据 3 恒 `N/A`）；③ 台账记轮次序号与首轮（2026-11-06，RFC-20261106-01:199）的可比性说明。
* **时序与失败隔离（写死）**：七项咬合与四判据证据采完 → **消融窗口排当日最后**（begin 前置 `smoke rc=0`，RFC-20261101-04:100；窗口内禁重装配，`install` 互锁 `rc=2`；restore 后复跑 `atlas check --fast` 并逐行 diff **归零**才算收口）→ 三件**各自独立收口、互不阻塞**（摩擦账成立而消融失败，不外溢成整轮失败）。
* **为何这是正解**：三件事的场地（真实采纳仓 + 重装配后状态）与前置（七项咬合）完全同构，合并 = 一次准备三份产出；成本面数字是「过重」问题的唯一客观载体，不计量则增减机械永远靠感觉。

### 2.2 考虑过的备选方案及否定理由 (Considered Alternatives)

* **备选 A**：摩擦账做自动埋点（每脚本自带计时上报）
  * *否定理由*：给每个机制加计时上报 = 逐脚本改动 + 新数据面（新字段），违反零新门零新字段；且埋点的计量口径无人抽检即度量自指。人工秒表 + 抽检一笔已够决策精度（分钟级）。
* **备选 B**：摩擦账独立成文档（不进真跑日协议）
  * *否定理由*：脱离真跑日的摩擦账没有采集场景（摩擦发生在真跑日动作里）；独立文档 = 第二份要维护漂移的协议。
* **备选 C**：宏观消融固定摘除集写死在协议里
  * *否定理由*：摘除集的价值依赖最近一轮摩擦账数据（动态）；写死 = 消融退化为仪式。协议只定「何时跑、怎么跑、判据形态」，候选集逐轮拍板。

### 2.3 必须警惕的刺痛代价与兼容性影响 (Trade-offs)

* **真跑日变长**：三件合并预计增 30~60 分钟（摩擦账全程计时 + 消融一轮 begin/restore）——换来的是三个待办一次清账 + 后续增减机械有据。
* **消融摘除集的误判风险**：摘除「低价值」候选若实际咬红了四件事之一 ⇒ 恰是宏观净贡献的证据（记入台账，不视为失败）；restore 保障逐字节还原，风险封闭。
* **摩擦账的观测者效应**：知道在被计时的动作可能变快 ⇒ 汇总表标注「人工计时口径，含观测偏差，仅用于增减机械的方向性判断，不作 SLA」。
* **环境不可用日**：靶场不可达 / API 无实响应的日子**整轮顺延**，不视为「缺因污点」（`real-run-day.md` §1 前置没过 = 没起跑，不是跳步）。
* **存量采纳仓适配**：协议适用对象不变（任一已装配采纳仓的 detached worktree）；§6 是可选节——真跑日可以只跑原七项咬合 + §6（拍板了三件待办的轮次才三件必跑）。
