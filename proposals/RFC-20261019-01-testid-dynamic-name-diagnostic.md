## 1. 现象与取证 (The Problem & Evidence)

### 1.1 触发形态（抽象）

* **规则 / 环节**：`validators/validate_testids.py` 的「分页双向集合相等」门，及其在 FAIL 时附带的诊断提示（本文件 `:623`）。
* **触发时机**：运行 `python3 .atlas/validators/validate_testids.py --root <项目根>` 时。
* **具体行为**：用例把一个**运行期生成、无法静态枚举**的行元素名（形如 `<prefix>-<运行期值>`）**只写在 `step` / `expected`**、不写进 `testid:` 清单 —— 这正是本门自己的 FAIL 提示所建议的形态。结果该名仍判「缺失」而 FAIL，提示与实际口径相抵。

### 1.2 客观证据与日志 (Minimal Evidence)

**（a）提示文案与应然集合口径的相抵（同文件两处）**

```text
$ grep -n "仅在 step/expected 中引用即可" validators/validate_testids.py
623:        hint = " (💡 提示: 动态列表项如 *-item 切勿列入用例 testid: 块，仅在 step/expected 中引用即可)" if any("item" in str(d.get("缺失(抽取源无)", [])) for d in unequal) else ""
```

```text
$ sed -n '394p' validators/validate_testids.py
def shard_testids(...)  # docstring: 分片侧（用例侧）testid 集合 = **`testid:` 声明 ∪ `step`/`expected` 派生**
```

`step`/`expected` 里的名字**自 2026-09-25（§B40 / §B64）起同样是应然集合的来源**，故「只在 step/expected 中引用」不构成任何豁免 —— 提示建议的两条路都进同一套对账。

**（b）最小复现（本项目装配副本上实测，跑完删除、分片 `diff` 逐字节还原）**

在既有分片末尾追加一条探针用例：`<dynamic-name>` **仅**出现在 `step` 与 `expected`，`testid:` 清单里**只列一个无关的既有名**。

```text
$ python3 .atlas/validators/validate_testids.py --root .
  [FAIL] 分页双向集合相等 —— [{"page": "<page-slug>",
          "缺失(抽取源无)": ["<dynamic-name>"], "多余(用例未引)": []}]
  [WARN] 应然落点 —— 未登记落点=['<page-slug>:<dynamic-name>']
```

⇒ 该名未写进 `testid:` 清单，仍进应然集合并被判缺失。

**（c）附带病灶：触发判据是词形启发式**

提示的触发条件为 `any("item" in str(...))` —— 按**名字里是否含 `item` 这个子串**决定要不要给指引。对 `<prefix>-<运行期序号>`、`<prefix>-<运行期 id>` 这类同样「无法静态枚举」的形态**不触发**，即同一类问题只对特定词形给提示（漏提示），而对名字里恰好含该子串的**真漏实现**（另一类问题）反而给出误导性指引（错提示）。

## 2. 决策与权衡 (The Decision & Trade-offs)

### 2.1 核心定案 (The Decision)

**只修诊断，不动判定强度**：

1. **文案改正**：把 `:623` 的提示改为指向契约 §4 已给定的正规替代形态 —— **容器 + 计数**（对容器断 `count`）、**稳定样例行**、或**类型级静态名**；删去「仅在 `step`/`expected` 中引用即可」这句已失效的建议。
2. **判据由词形改为结构**：触发条件从「名字含 `item` 子串」改为「**缺失名命中源里某个模板 testid 的结构模式**」。
   * 依据：不可静态枚举的模板（占位符不在词表内）在 `expand_template_testid` 里返回 `None`，其**展开值集合为空**（`:360` 声明、`:382` 收集的 `expanded` 收不到它）—— 但它本身是一个**模式**，可由模板体构造：`${…}` 段换成 `.+?`、字面段 `re.escape`。
   * **为何不用「静态前缀」**（初稿的方案，实现阶段自我否决）：模板**以占位符开头时前缀为空**（如 `` `${slug}-row-${idx}` `` 的首个占位符前没有任何字面量）—— 而这恰是本仓最常见的模板形态（实测），前缀判据对它**恒不触发**，等于没修。
   * 反误判护栏：**只保留字面总长 ≥ 3 的模板**。全占位符的模板（如 `` `${a}` ``）会退化成 `^.+?$`（匹配一切名字），留下来会把「真漏实现」误判成「模板派生」。
   * 实现面：新增一个**独立**的轻量收集函数（在同一批已读入的文本上再跑一次正则），**不改 `file_testid_decls` 的返回元组**（该函数是「全量抽取」与「应然落点」门的**单源**，改元数会牵动两处消费方与既有测试的解包面）；收集入口用 `collect_testids_expanded` 的**可选出参**（该函数返回的 5 元组已被 4 处调用方按位解包，加元数会一井打破）。

**判定面零变化**：本次改动**不改变任何 PASS / FAIL 结论**，只改变 FAIL 时附带的那句诊断。门禁强度、`unequal` 的构造、缺失/多余的判罚口径一律原样。

### 2.2 考虑过的备选方案及否定理由 (Considered Alternatives)

* **备选方案 A：真开一条「运行期生成名」的豁免通道**（如 `testid:` 项加 `!` 前缀，或新增 `dynamic:` 段：声明「此名由运行期生成、豁免全名对账、仅由落点门按模板前缀看守」）
  * *否定理由（本期）*：这会**削弱静态门** —— 豁免生效后，即便该模板声明被整段删除，双向集合门也不再报红，缺陷从「静态可判」退化为「只能靠真跑发现」。而本仓真跑链路对多数项目仍是人工/阻塞态，把检出点推到真跑是净损失。且目前**没有具体的业务用例需要「按序号取第 N 个实例」**（现有需求都能用类型级静态名 + 靶场前提满足）。该能力缺口已随本提案的 `atlas report` 上报，**交上游定案**；若定案要做，必须同时给「幽灵豁免」检出（死豁免不许长期挂着），否则退化成永久放行口。
* **备选方案 B：把提示改成无条件附加（去掉一切判据）**
  * *否定理由*：普通「实现漏了」的缺失（占绝大多数）会被附上一句与它无关的「动态列表项」指引，属噪声；诊断的价值在于精确。
* **备选方案 C：只改文案、不碰判据**
  * *否定理由*：可接受但只解决了 2.1 的一半 —— 1.2(c) 的「漏提示 / 错提示」仍在。而结构判据（模板结构模式匹配）实现成本极小（复用同一批文本，不动公共函数签名，见 2.1），值得一并做。
* **备选方案 D：把 `step`/`expected` 派生的名字从应然集合里摘出去（回到 2026-09-25 之前的口径）**
  * *否定理由*：直接推翻 §B40 / §B64 的两条动因（① 定位错人：断言了某 id 却没列清单时，门的判罚落到**别的**用例头上；② 清单纯属派生信息、每改用例都要人肉补齐 = 漂移面）。这是**回退**而非修正。

### 2.3 必须警惕的刺痛代价与兼容性影响 (Trade-offs)

* **兼容性**：判定面零变化 ⇒ 既有项目的 PASS/FAIL 不会因本改动翻转。唯一可能翻转的是**输出文本**（FAIL 的 detail 多/少一句提示）——若有测试对 detail 做整串断言，需同步。已核查：`tests/` 内无对 `:623` 这句文案的断言（本改动**新增**钉子，见 §3）。
* **装配**：`install.sh` 的装配副本**不溯及既往**（`shared/gates.md` 2.2 的咬合点口径）⇒ 存量项目需重跑装配才拿到本修正。已核验：源包 ⇄ 某装配副本的**全量差异仅 `__pycache__/*.pyc` 缓存**（源码逐字节一致）⇒ 重装配的影响面可控，不会夹带其它内容漂移。
* **执行耗时**：新增一次同文本正则扫描（模板前缀收集），量级与既有 `file_testid_decls` 同级，无新增文件 IO。
* **词表守恒**：本改动**不新增词表**（无枚举取值），故不触「词表三处同步」（`ORIGINS` 先例）的约束。
