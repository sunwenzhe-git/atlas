# KICKOFF —— 需求起手与评审接力协议

> **类型**：非 RFC 工作方法档（与 `TEMPLATE.md` 同层的流程文档，不进装配面、无机器判据）
> **留证面**：`RFC-20261114-07`（本档 = 该 RFC §2 四机制的落地正文；两者不一致以 RFC 为准）
> **触发**：零口令——Agent 默认起手行为，用户正常说需求即入场；单点事实问答、一句话小改不套仪式；用户说「直接做 / 别问」跳过轻档仪式
> **外部来源**：Meldwork 三机制移植（Ryder-Sun/Meldwork README 与 architecture.md，访问 2026-11-14）

---

## 1. 需求起手（第一回复三件套 + 一次对齐门）

原始需求入场后，Agent 第一回复固定三件套：

1. **结构化回读**：目标 / 范围 / 非目标；
2. **假设清单**：本该问但按合理默认推进的点，逐条带依据与证伪方式；
3. **档位声明**：轻档 / 全档（判据见 §5）。

随后候选方案按档位给 1~3 个**不同取舍方向**的独立候选（非同案微调）；全档时 Agent 侧先互评一轮（各挑对方最大风险）再收敛为「推荐 + 备选」；有子 agent 环境时由并行子 agent 独立生成，无则单会话分视角生成并显式声明。

**一次对齐门**：用户只答三类事（见 §2），单轮 ≤2 问（`skills/atlas-grill/SKILL.md` 单轮 1~2 问纪律），按影响排序，其余转假设清单留痕；答完即开工，不再逐条确认。

## 2. 三类才问人（全程中断权）

升级判据封闭三值，三类之外一律 Agent 侧按假设推进并留痕（写进假设清单），不打断用户：

* **缺信息**：答案改变方案形态，且 grep / 读码 / 查料不可自证；
* **缺权限**：用户资产、外发、不可逆操作（发版、仓外/生产面/不可逆写盘、删改他人产物；git 可逆的仓内写盘不在此列）；
* **真取舍**：≥2 个候选各有实质代价，无人能替用户选。

既有必问义务不收窄：`shared/global-rules.md` §7 四条恒为必问，不因三类判据豁免；`skills/atlas-grill/SKILL.md`「事实属于模型，决策属于用户」与 `shared/stack-profile.md:204`「先问人，再问代码」（D 类接口探测判定顺序）照旧。

## 3. 意见处置（评审接力四分法，方案细节 review 与代码 review 通用）

评审意见回来后不逐条请示、不把用户当传话中枢：

1. **自证面直接修**：grep / 读码 / 跑测试可核实的事实问题 → 修完留证（diff / 测试输出），不请示不逐条汇报；
2. **判断面回应留痕**：判断 / 取舍建议 → 提案方逐一回应（采纳 / 不改＋理由），留痕在意见单 / REVIEW 档，不外溢到会话；
3. **真取舍升级一次**：回应后仍分歧且影响验收口径 → 收敛成一个决策点（选项＋代价＋推荐）升级用户，一次问完（≤2 问）；§7 四条所在项不受本分拣影响，一律人工；
4. **回评审按派工规则**：批量修复方案先按 1~3 收拢再动工；re-review 按 §4 派工。

## 4. 并行双评审派工（全档）

同一冻结输入（同一提案文件 + 逐字相同的评审指令）派两个互不可见的独立评审（独立性既有锚 = `shared/independent-review.md` §2「先独立得出，再比对」），两份意见按四条规则合流：

1. **刻度复用**：严重度沿用 `shared/independent-review.md` 既有闭集，不另造；同一问题两评定级不一致时**取高**；
2. **重合**：同一问题双命中标注「双评命中」；升可信度前提 = 两评给出独立定位 / 独立理由（仅措辞重合不升档）；
3. **分歧**：真冲突不做假合流——提案方逐条回应并留痕；回应后仍分歧且影响验收口径的升级用户裁决，其余**默认从严**；升级用户仅此一类；
4. **落盘**：两份原始意见按既有 `REVIEW-YYYYMMDD-NN` 编号规则落盘（两列号各自独立递增），合流单引用两份编号；显式选择不落盘时，合流单内必须附双评结论对照表。

**降级路径**：无并行子 agent 环境时降级单人单评并**显式标注「未双评」**，不伪装双评。轻档维持单人单评；评审者 / 合流者发现轻档误报可当场升档。

## 5. 分档判据（成本闸）

**全档 = 任一命中，存疑从严**——①跨 ≥2 个契约面 / 环（跨域）②不可逆（发版、外发、删改他人产物）③触及机器门 / 校验器 / 契约判据；其余为轻档。起手声明初档；候选成形后按实际改动面**可升档**（评审者亦有权升档），降档需用户点头。轻档 = 单候选 + 自评 + 单评审；全档 = 完整协议（多候选 + 互评 + 对齐门）+ 并行双评审。

## 6. 与既有面的关系

* **§0 起案前澄清**（`RFC-20261114-05`）：对齐门问题集必须覆盖 §0 四必须（做什么 / 为谁做 / 关键约束 / 验收口径），缺项按「缺信息」进门；起案时刻以 §0 为放行判据（假设留痕不得覆盖四必须）；对齐门的回读与假设清单即 §0 复述理解的输入，落笔不重问。
* **`atlas review` 编排器**（`RFC-20261103-05`）：CLI 实现审查的命令编排入口（单评审流程一键化），不解决本协议的多评审员派工与意见合流——两者叠加使用。
* **`shared/independent-review.md` 骨架**：管「意见怎么产生」，本协议管「意见进来之后怎么处置」——叠加不替代，骨架判据零改动。
