## 1. 现象与取证 (The Problem & Evidence)

### 1.1 触发形态（抽象）

DR4 口径 B 的判据语义是三项（**同根归纳在案 ∧ 案数 ≥3 ∧ 近 30 天有新案**，`duty-review/README.md` §2），但它的机器实现（`duty-review/families.py`，口径 B 单源）只能从**无制式的散文段**里推断三件事：族 = 段、案数 = 段内 `#NN` 去重上界、日期 = 段内**任意文本里的最大日期串**。README 同时明示三条盲区（`duty-review/README.md` §2 口径 B 尾）：

* ① **跨段同族机器串不起来**——靠手写「同族复发」交叉引用，且必须在被指段也留一行，残缺即机器不可见；
* ② **段是人工按环分的，分段漂 ⇒ 计数跟着漂**；
* ③ **`bugs.md` 无日期字段**——日期是靠正则从散文里刮出来的。

由此产生四种可实证的失真形态：

* **(a) 陈旧说明抬活跃窗（前瞻性失真）**：段内任何 `YYYY-MM-DD` 字符串都参与 `last_date` 取最大（`families.py:47-48`）——段尾「已修、全量绿」的收尾说明随出库史这类必留段（`duty-review/bugs.md` E2E 段「已出库锚」行）持续累积，足以长期抬窗。现行基线下五段无一因此翻面（试跑基线：structure 段无日期、判「族已静默」；E2E / 安装与装配 / 自感知三段判「升室候选」且确有近窗日期在案）——所以它是**会随数据积累而实证**的形态，不是当下翻面现场；措辞按评审修正为前瞻性。
* **(b) 交叉引用计入案数（已拍板语义，但不可见）**：同根归纳行与「已出库锚」行自带 `#NN`，上界按「条目、同根归纳行、交叉引用」三面都算（README §2 口径 B 原文自认；同义行 = `DESIGN.md` §12 D102「案数上界」）。`duty-review/bugs.md` E2E 段「已出库锚」一行就含 `#24`–`#30` **七个**出库史引用。计量基准已被维护者拍板接受（README:28 / DESIGN.md:571），**本 RFC 不改它**——痛感是上界与真实病案数的差量对巡检与维护者不可见。
* **(c) 跨段族靠运气**：自感知上报段的同根归纳点名「跨段复见 E2E 段 #20、#24」（`duty-review/bugs.md` 自感知段），机器只看得见**自己段**内的 `#NN`；跨段且一面忘抄 ⇒ 两段族计数互不知晓（盲区①原样）。现行唯一跨段引用两段各自都有 `#NN`（试跑：自感知段案数含 #20/#24 ✓），属**还运转中的人工保障**。
* **(d) 新案忘写日期即「已静默」**：无日期 ⇒ `last_date` 为空串 ⇒ `active=False`（`families.py:64`），一条**今天**新报的未解观察若恰好没带日期文本，判「静默」——方向性反了。render 行也已自认（`families.py:80-81`「无日期 ⇒ 视为已静默」）。

### 1.2 客观证据

1. 段级近似的机器自述——`families.py:26-33` docstring：「ids = 段内出现的 `#NN` 去重集（**上界近似**：条目、同根归纳行、交叉引用都算）」「last_date = 段内出现的最大 `YYYY-MM-DD`（无 ⇒ 空串）」；`:80-81` render：「日期取证 = 段内文本里的日期，无日期 ⇒ 视为已静默」。
2. README 侧盲区自认——`duty-review/README.md` §2 口径 B 末「**明示盲区**」三条与 RFC 前文对应。
3. 计量基准已是拍板项——README:28（口径 B 上界原文）+ `DESIGN.md` §12 D102 同义行；**引用污染属已拍板语义**，本批不重开，只做可见化。
4. D131 证明件已强制但台账不可指认——`duty-review/README.md` §2 逃逸条款：确认的逃逸缺陷出库前必补「红→绿回归用例 + M 系列变异钉」。证明件存在，但 `bugs.md` 条目上**无指向它的字段**；而出库=删（README §4），删后证明件「挂在谁的账下」在台账文本上是断链——外部「共享 known-bug 契约」在 Atlas 的真实缺口就这一道「条目 ↔ 证明件」的机读引用面。
5. 解析形状生根于单源 + 钉面——`families.py` 头注自认「解析形状一旦与文件形状漂开 ⇒ 静默归零，钉守」，`tests/test_duty_bug_families.py`（形状钉 + 喂坏输入钉）全绿。本批只增形状，不换实现。
6. 惰性路径实证（证锚设计依据）：`.atlas-run/` 产物会被 Playwright 每次起跑清空（`duty-review/bugs.md` E2E 段「留证留存窗口」观察，2026-10-25 实证 28 失败构件复跑即蒸发），留档路径**易腐**；正式记录恒在 `DESIGN.md` §12 决策行（README §4「出库不抹史」的正式面）。

### 1.3 动机一句话

把 DR4 判据的输入从「散文推断」升级为「条目字段」：**日期字段**根治 (a)/(d) 两型失真，**证字段**闭环 D131 证明件的台账断链；案数计量**保持已拍板的上界语义**、字段只 提供「精确病案数」显示列与坏形状显性告警；车辆跨段族身份字段先「解析记录、不参与判据」。「已知 bug 资产化」在 Atlas 现势的真实合成量 = **台账制式化作，不是新机器**。

## 2. 决策与权衡 (The Decision & Trade-offs)

### 2.1 核心定案

**bugs.md 条目新增机器尾缀制式**（沿用本仓「条目括号标记」既有文体，如同 `duty-review/bugs.md` 已有的 `[逃逸: 门/根因]`——全角 `〔〕` 与半角 `[]` 字符集不相交，可共存；头部制式块同时说明两套括号标记的归属）：

```text
〔日期 YYYY-MM-DD｜状态 开放｜族 <可空>｜证 <可空>〕
```

字段语义（**封闭三枚消费 + 一枚记录 + 形状规则**）：

| 字段 | 必填 | 语义 / 缺省行为 |
|---|---|---|
| `日期` | **必填**（新案落账时写 = 巡检/会话记事当天；修订再跑的结论日期同段可保持，条目以首计日期参与活跃窗） | 条目产生日期，格式 `20\d\d-\d\d-\d\d`；无字段旧条目缺省 |
| `状态` | 可空 | 封闭值域 = `开放` / `已修·待复验` / `已出库`（「开放 / 已修·待复验」沿用 `duty-review/bugs.md:3` 既有人写双态；出库即删行,状态枚举本值形态由头部制式块声明） |
| `族` | 可空（**解析记录、不参与判据**） | 跨段同根族显式标识；本批 `families.py` 只记录不消费——升档条件 = 库内出现**第 2 个跨段同族实例**（grep 可判：非本段条目带同名族），届时另批落地拼合逻辑与 README 输出形状连锁改 |
| `证` | 可空 | D131 证明件的机读锚，**优先级写死**：`DESIGN.md` 决策行 D 号 > M 变异号 / pytest 钉名 > 留档路径（仅辅助注记——`.atlas-run/` 留证易腐，见 §1.2⑥；决策行是出库不抹史的正式面） |
| 形状规则 | — | 重复字段 / 日期越界 / 状态值外 ⇒ **坏形状**：`families.py` 运行面输出 **WARN 行到巡检信号**（不静默），该条目按「无字段」回退参与现行口径 |

`families.py`（单源）消费升级——判据三项与计量基准**原样不动**：

1. **活跃窗精确化**：日期来源从段级全文本改为**分层来源**——① 带字段条目：只取字段日期（该行自身散文日期不再参与）；② 无字段条目行：取该行文本内日期（现行回退）；③ 其余行（段头 / 同根归纳行 / 出库锚行 / 收尾说明 / 无害正文）：**不再是日期来源**。段 `last_date` = 全源头并集取最大。直接效果：陈旧收尾说明不再抬窗（(a) 治）；新案必有字段日期（(d) 治；漏写 = 坏形状 WARN，非静默）。
2. **案数计量不变 + 显示列**：DR4 案数仍按 README:28 上界口径（`#NN` 去重上界含条目/归纳行/引用——已拍板），逐字节不变；`render()` 新增整段「精确病案数」展示列 = 带字段条目的 `#NN` 自身去重数（无字段条目不可计数不计入），括号注明「上界 N / 精确 M」。跨段族拼合**不做**（族字段未消费），`render()` 的行键仍为段名。
3. **read**：`scripts/duty_signals.sh` **零改动**（唯一接点 `duty_signals.sh:30` 只调 `families.py`，输出变化全部由 `render()` 承载）。

配套（同批、不另案）：

* `duty-review/README.md` §2 口径 B 末追加「条目字段制式」小节（定义表 + 与现行判据/混入规则的映射 + 两套括号标记归属），三条明示盲区改写为「① ② 已由字段制式收窄/记嚴；③ 旧条目无字段退化为段级近似依旧在盲区面」（诚实收窄，不删除既成面）；
* `duty-review/bugs.md` 头部制式块：加一行字段尾缀示例 + 「新案必带 `〔日期 …〕`」条款；
* `duty-review/README.md` §4「新 bug 的入路」段追加「新案落账必带尾缀字段」条款——**README §4 = 仓内巡检 automation prompt 的裁决面**（ZCode 侧 prompt 文本在自动化配置里、不在仓内），人面纪律的家就在这里落；
* 钉面增补：`tests/test_duty_bug_families.py` 详见 §4.1。

### 2.2 考虑过的备选方案及否定理由

* **备选 A：把 `bugs.md` 整体搬成 JSON / SQLite**
  * 否——「库是工作面不是台账」（README §4 原话）：巡检器和维护者均以**散读**消费；换介质 = 换工作方式，与「单源 + 形状钉」稳健姿态背离，机器面模板成本不成比例。
* **备选 B：全量回填旧条目字段（git 考古判日期）**
  * 否——库的职责是比对新病不复活历史；旧条目回退现行口径仍有判据支撑；考古判日期反而引入难校验的失真源（回填不改变任何判据结果）。
* **备选 C：独立 validate_bugs_ledger 校验门**
  * 否——台账**不是流水线产物**（不走生成-校验回路），不值得上门册；解析健壮性由 `families.py` 形状钉 + 喂坏输入钉 + **运行面 WARN**（必修 2）三件保证，不开第二门。
* **备选 D：每条带 `证:` 后自动复跑证明件**（真「已知 bug 可执行」执行面）
  * **明示缓行**——巡检铁则「全程只读」（`duty-review/README.md` §1；`families.py` 头注铁则）禁止在巡检链里跑断言。**升档条件（可判）**：库内带 `证:` 字段条目 **≥3 条**（grep 可判）⇒ 另批立项独立于巡检的执行面（进 CI / 交互会话跑），不得偷偷上巡检链。本批半径锁死在字段落账。
* **（评审必修 1 的备选 i 逆非案）计量面直接精确化（判据换 `#NN` 精确去重）**
  * 不采——上界是 README:28 + `DESIGN.md` D102 已拍板语义；上界 → 精确必然缩案数（升室**更严**），推演钉仍完全不吃（新旧五段无翻面，reviewer 的试跑理由），但属于对已拍板判据的重新解释，**必须**显式走 DR1（旧行号 README:28 + DESIGN.md:571)才能改。本 RFC 保持 (i)：判据原样，精确数做显示列；若维护者将来要精确计量，按 DR1 另案（到时候字段已落地，增量只剩一行判据字）。

### 2.3 必须警惕的刺痛代价与兼容性影响

1. **文档-实现同批同步是硬约束**：`README.md` §2（语义源）与 `families.py`（机器源）必须同批改——否则盲区陈旧表述与新版实现直接漂移（口径 B 自己已经为「实现未同步文案」付过学费：README §2 里的 D131 段与 families.py 的盲区表述都要同批刷新）。
2. **旧条目零改动**：无字段条目全走现行回退路径；对现行 `bugs.md` 全文，活跃窗/案数/升室结论**逐字节等于现行**（`render()` 措辞按所选项同步标签）。差异只发生在新条目与坏形状下载体上。
3. **人写负担（如实计价）**：每条新案尾缀约 20 字符；巡检器侧由 prompt/会话模板自动生成，无人工增量。
4. **打包面如实陈述**：`duty-review/` 与 `proposals/` 不在 npm 包 `files` 面（已核 `package.json` files 清单）；**tests/ 在包面上**（本批新钉随包分发，采纳仓副本态由既有 skipif 跳过兜住）——「机器面不进包」的准确表述 = results 执行源（families）不进包，钉进包但不执行。
5. **本批咬合点 = 当日**：无需重装配/等真跑日；无版本串 / 地图锚 / install.sh 变动。

## 4. 验证与测试结果 (Verification)

> 本节为**落刀日**验收计划（本 RFC 仍是 Draft；落地批须全绿后方可关舱）。

### 4.1 钉（`tests/test_duty_bug_families.py`，在既有形状/喂坏家族上扩展）

1. **四型字段解析钉**：全字段 / 半字段 / 无字段（回退现行）/ 坏形状（重复字段 / 日期越界 / 状态值外）四组——坏形状组断言「WARN 到 stdout + 回退"，非静默。
2. **判据零变更对照钉**：对现行 `duty-review/bugs.md` 全文（全条目无字段），本版解析输出与现行版**逐字节一致**（含 render 行，除清理标签措辞）；即旧库零扰动。
3. **正向钉两条**：① 合成段「带今日日期字段的新条目 + 段尾陈旧收尾说明」⇒ 判「升室候选」（字段日期接管活跃窗）；② 合成段「仅陈旧收尾说明日期、无带字段新条目」⇒ 判「族已静默」（收尾说明不再抬窗——(a) 型治实证）。
4. **混合段聚合钉**：同段「带字段新条目（今日）+ 无字段旧案（带散文日期）」⇒ 活跃窗 = 并集最大 = 仍活跃（条目级回退 + 段级取最大规则实证）。
5. **显示列钉**：`render()` 输出含「上界 N / 精确 M」双列（M = 带字段条目的 `#NN` 自身去重数），无字段段 M 不显示。

### 4.2 变异

* 变异号位落刀时按 M 序顺占（不预占号）：预记两条主题——① 摘分层日期来源（回到段级全文本）⇒ 正向钉②红；② 摘坏形状 WARN ⇒ 四型钉坏形状组红。四段协议（基线 GREEN → 注入 RED → 逐字节还原 → 再 GREEN）沿 `scripts/mutation_proof.py` 承载不变。
