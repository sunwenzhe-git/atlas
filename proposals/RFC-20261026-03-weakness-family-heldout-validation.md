## 0. 一句话

**DR4 已经能发现「同根复发 ≥3」并把段送进 QUEUE；本提案先不制度化，而是做一次前瞻试点：在下一个系统性修复上，强制自己写一个「未参与挖弱点」的留出集，看它是否真的改变闭族判断或咬出回归。试点证明有用，才把留出验证写进 RFC 机制；证明不了，就否决。不新增自动门、不新增台账、不改生产代码。**

**术语（本提案内固定）**：

* **弱点子族**：同一根因机制的案例集合；载体 = `bugs.md` 某个 `##` 段下的 `- 同根归纳` 行（一个段可以有多条同根归纳），或 ≥3 条独立审查重复 finding。**不是**整个 `##` 段。
* **段级信号**：`duty-review/families.py` 的输出单位 = `##` 段（`bugs.md:26-49` 的 `parse_sections`）。段级「升室候选」只表示该段近期活跃，**不等于**某个子族复发。
* **系统性修复**：改动门 / 校验器 / 契约判据或 skill 描述，声称消除某个子族的 RFC；不是单案修复。
* **留出集**：未参与挖弱点（§1 探针 / 原始失败用例 / 同 fixture 改写 / 看到修复结果后才补写的期望）的验证案例集。
* **闭族**：子族锚在案 ∧ 系统性修复已落 ∧ 留出验证通过 ∧ 反面包红。缺任一条件只能叫「单案修复」或「未闭族」。
* **试点**：在本 RFC 之外的下一个真实系统性修复上，按本协议跑一次；结果写进那份 RFC 的 §4.5 与独立评审，不新增台账。

## 1. 现象与取证 (The Problem & Evidence)

### 1.1 触发形态（抽象）

* **规则 / 环节**：`duty-review/README.md` §2 DR4 口径 A/B（[README.md:28](file:///Users/sunwenzhe/Desktop/atlas/duty-review/README.md#L28)）+ §3 QUEUE 三区与出室条件（[README.md:41-50](file:///Users/sunwenzhe/Desktop/atlas/duty-review/README.md#L41)）；`proposals/README.md` §2 强测试约束（[README.md:43-46](file:///Users/sunwenzhe/Desktop/atlas/proposals/README.md#L43)）。
* **触发时机**：DR4 判「升室候选」→ 进 QUEUE → 维护者选「立门 / 改契约 / 单修」→ 立 RFC 并合入。
* **具体行为**：RFC 只要带测试钉子或 M 系列变异钉就能合入（`proposals/README.md` §2）；合入后，子族是否真的闭了，现行出室条件由人按族手写，形态各异——有「无新案」、有「新案重入」、也有「特定实证才重开」（实例见 `duty-review/QUEUE.md` 归档案 2026-10-17 三族，[QUEUE.md:35-37](file:///Users/sunwenzhe/Desktop/atlas/duty-review/QUEUE.md#L35)）。**没有一条要求证明：换一批未参与挖弱点的任务 / 域 / 判据，修复仍然有效。**

现有机制各自回答的问题不同：

| 现有机制 | 它回答的问题 | 它不回答的问题 |
|---|---|---|
| DR4 口径 A/B + `families.py` | 「同类问题是否还在段级复发？」 | 「这次系统性修复是否消除了子族根因？」 |
| D131「逃逸缺陷追问与评测闭环」（`duty-review/README.md:35-37`；`shared/closeout.md:75` 起 7 检查点） | 「逃逸缺陷有没有回归用例与变异钉？」 | 「回归用例是否只覆盖了原失败形态？」 |
| 假绿测试 / 变异证明（`shared/gates.md:94`） | 「门被绕过时会不会红？」 | 「换一个环 / 夹具 / 栈，判据是否仍然成立？」 |
| 独立审查（`shared/gates.md:92`） | 「这次改动本身有没有问题？」 | 「修复是否只在被挖出的那批用例上有效？」 |
| QUEUE 出室条件 | 「最近还有没有新案 / 有没有触发重开的实证？」 | 「没有新案，是因为修好了，还是因为没人再撞到？」 |

**唯一的新增**：留出集的**独立性**与「闭族」判定。D131 的回归用例、变异证明的反面包、独立审查的 finding 都可以来自同一批失败形态；本提案要求的是**另一批**。

**能得出的结论**：

* 3/3 段在 `families.py` 口径下都是「升室候选」；但这是**段级活跃度**，不是子族复发证明；
* 1/3 子族有**跨段复发**的书面证据（自感知上报 → E2E #20/#24，`bugs.md:58` 明文）；
* 0/3 子族有留出验证记录；
* QUEUE 归档的「已处置 / 已收敛 / 维持纪律」与段级「升室候选」并存，恰好说明：**人写的闭族判断需要一个独立证据面**，否则「已收敛」与「又活跃」会长期各说各话；
* 这是**回顾性桌面演练**，只能证明「缺口存在」，不能证明「留出验证有增益」。增益必须靠 §4.1 的前瞻试点。

### 1.3 为什么不是 DR4 / D131 / 变异证明重复

* DR4 = **发现 + 升室**；本提案 = **修后验证 + 闭族**。前后段，不是两套聚类。
* D131 = 逃逸缺陷必须有回归用例 + 变异钉；两者都可以从**原失败形态**派生，回答的是「同类坏输入还会不会红」。
* 变异证明 = 证明门有牙；反面包仍是**同一判据的坏输入**。
* 独立审查 = 审这次改动本身；不负责「换域是否泛化」。
* **唯一新增 = 留出集的独立性 + 闭族判定**；其余全部复用现有机制。

### 1.4 外部参考的使用边界

* Self-Harness（arXiv:2606.09498）只借用循环形状：弱点挖掘 → 提案 → **在未参与挖掘的留出任务上验证**；摘要中的收益数字与具体基准不作为 Atlas 证据。
* 公众号系列只作背景；其转述数字与 arXiv 摘要口径不一致，具体数字不进入本 RFC 的证据面。
* 不采：自动 harness 演化、LLM 自评分、Spec Fidelity 百分比硬门、OpenSpec archive 模型、把 Atlas 做成 runtime。

## 2. 决策与权衡 (The Decision & Trade-offs)

### 2.1 核心定案

1. **Phase 0 = 前瞻试点，不是制度化**：
   * 试点对象 = **下一个**真实系统性修复（有子族锚或 ≥3 条重复 review finding），不是历史族；
   * 试点开始前，在那份 RFC 的 §4.5 写下留出集、为什么独立、预期结果、**pre-fix 红证据计划**；
   * **pre-fix 必红**：修复前先跑留出集，必须红并留证（对齐 D131 Red First，`shared/closeout.md:75`）；红不了 ⇒ 该用例不合格，换用例；换不出 ⇒ 试点失败，只能走「单案修复（无留出集）」；
   * 修复落地后真跑同一留出集，必须绿；记录实际输出、耗时、评审耗时、路径交叉检查误报；
   * **试点成功判据 = pre-fix 红 → post-fix 绿，且留出结果改变了闭族判断（咬出回归 / 证明修复比声称窄 / 给出同集测试给不出的证据）**；只是同集测试复跑、没有新增信息 ⇒ 试点失败；
   * 试点结果写进那份 RFC 的 §4.5 + 其独立评审（轮 3 或追加复审节），由独立评审确认无 blocker；不新增台账。
2. **Phase 1 = 试点通过后才制度化**：
   * 通过 ⇒ 改 `proposals/README.md` / `TEMPLATE.md` / `duty-review/README.md`，并在 `shared/gates.md` §2.5 登记一行**流程门**（语义项，无机器判据；盲区明写「触发靠自述，可被逃」）；同批更新计数 / `docs/map`；
   * **独立评审契约**：若试点证明路径交叉检查可用，Phase 1 同批把检查项写入 `shared/independent-review.md`（否则评审者契约里看不到）；若试点证明不可用，删掉触发 (b)，只保留 (a) + 人工判断；
   * 未通过 ⇒ 否决本提案，不进入 Phase 1；结果记入 `REVIEW-20261026-06`；QUEUE 只留一行案号指针，不复述状态。
3. **触发面（Phase 0 试点；Phase 1 起强制）**：
   * (a) RFC §1 引用一个子族锚（`bugs.md` 同根归纳）或 ≥3 条独立审查重复 finding；
   * (b) RFC 改动门 / 校验器 / 契约判据，且 `git diff --name-only` 落在已有 DR4 段级锚的路径族内；
   * 不触发：一次性 bug 修复、纯文档、无复发声明的新功能、纯重构。
   * **防逃**：独立评审必须做 (b) 的路径交叉检查；不能以「§1 没写族锚」为由跳过。Phase 0 先用 `git diff --name-only` + `scripts/closeout_derive.py` 现有路径族表手工对照，记录「锚 → 路径族」映射与误报；Phase 1 再决定是否接线，不先造脚本。
4. **留出集定义（可操作版）**：
   * Atlas 自身门：另一个环的同类判据、另一个 fixture 族、另一个 stack profile、另一条运行器轨、另一种装配态（npm 全局 / 本地源包 / 干跑）；
   * 采纳项目：另一个任务卡 / 域且措辞不同、未参与 §1 探针的冻结历史批次；
   * 不合格：同一失败用例复跑、同 fixture 只改措辞、§1.2 的探针本身、看到修复结果后才补写的期望值。
   * **同样不合格（D155 两轮证伪得来，原文没有这一条）**：**只换日期串 / 只换调用通道**——同输入下结论由同一个判据函数唯一决定时，换通道不产生判据级信息。**「独立」不看「代码路径是否新」**（分支覆盖既证不出独立——新轨迹可全由旧分支拼成；也会误伤有效边界钉），改判三条、缺一即按「同夹具变体」驳回，由独立评审当场重放、不由作者自证：① **判据输出翻转**——pre 版实跑，verdict / 案数 / 最近日期 / 精确病案数至少一项翻转，仅 WARN 文本 / 日志 / 通道变化不算；② **变异增量杀伤**——当场注入一个退化变异，既有钉全绿而留出案红（独红或与指名新钉共同红），注入 diff + 红集留档；③ **结构不可达**——夹具不可由任一既有钉夹具只改日期串 / 通道 / 增删行得到。通道变化只配得单独钉一条「告警是否送达消费者」，不凑成留出（D155 实际物 = 归零路径留出 + `T+1` 判别钉 + CLI 送达钉，轮 3 判词）。
5. **三态结果（不阻塞合法修复）**：
   * `闭族` = pre-fix 红 ∧ post-fix 绿 ∧ 全量回归绿 ∧ 相关门绿 ∧ 反面包红；
   * `未闭族` = 留出失败；如实记录，子族若仍在库中则保持观察；
   * `单案修复（无留出集）` = 允许，但**所有触发族**走此态都须满足三条：① 评审确认「确无可行留出集」；② QUEUE 观察室留一行 owner + 补验期限（默认下一次相关变更前）；③ 残留风险写进那份 RFC §4.5；不得宣称闭族。紧急修复（安全 / 装配阻断 / 门恒红阻断收口）是此态的子集，不是额外后门。
6. **记录位置（不造第二台账）**：
   * **唯一判定记录** = 那份 RFC 的 §4.5 + 其独立评审记录；本 RFC §7 只放试点摘要与链接，不是第二判定；
   * 若子族仍在 `bugs.md` 工作库中，可加一行指针：`- 留出验证：RFC-... / REVIEW-...`；**不写状态、不写日期、不写 `#NN`**（「留出验证」比「闭族验证」中性，未闭族时也不误导）；
   * **已归档族不追溯**：QUEUE 已结的族不因本提案重开；重开仍走 DR1（旧行号 + 新证据）。`families.py` 的 `has_root` 只认 `- 同根归纳`，`ids` / `last_date` 扫段内所有行（[families.py:44-48](file:///Users/sunwenzhe/Desktop/atlas/duty-review/families.py#L44)）；指针行不带日期 / `#NN` 才不会污染段级信号。
   * QUEUE 只为「单案修复（无留出集）」留一行案号指针（owner / 期限），不复述闭族状态。
7. **不新增自动门 / 不假装是门**：
   * Phase 0 不改 `atlas_check`、不改校验器、不登记 `shared/gates.md`；
   * Phase 1 若制度化，只登记 §2.5 **流程门**（人 / agent 纪律），明写「无机器判据、触发靠自述」；不把它写成机器门。
8. **独立评审检查项（落点明确）**：
   * 检查：留出集是否真独立；pre-fix 是否真红；post-fix 是否真绿；失败是否如实写；闭族声明是否与证据一致；是否偷偷造第二台账；触发是否被逃；
   * 落点 = `proposals/TEMPLATE.md` §4.5 的必填字段 + `proposals/README.md` §3 的一行审批说明；**Phase 0 不改 `shared/independent-review.md`**；Phase 1 若保留触发 (b)，同批把检查项写入 `shared/independent-review.md`（否则评审者契约里看不到）。
9. **证据纪律**：
   * 只引用 arXiv 摘要的机制句；公众号具体数字不进入证据面；
   * 留出验证必须贴真实输出；没跑就写「未跑」，不得用「预计通过」。

### 2.2 备选方案及否定理由

| 备选 | 否定理由 |
|---|---|
| A. 新建 `duty-review/WEAKNESS.md` 台账 | 与 `bugs.md` 同根归纳 + QUEUE 观察室重复；第二台账必漂。 |
| B. 新增「弱点聚类」自动门 / 校验器 | 聚类语义不可机判；会变成投机硬门，把「同根」判断交给正则。 |
| C. 自动 LLM 聚类 + 自动改契约 | 过拟合、无独立评审；与「门禁不信模型自评」冲突；外部研究也报告自动演化收益被高估。 |
| D. 调 DR4 阈值 | 不是本缺口；DR4 的发现能力没问题，缺的是修后验证。 |

## 4. 验证与测试计划 (Verification)

### 4.1 前瞻试点设计（Phase 0 的核心）

**候选对象**：下一个满足以下任一条件的真实系统性修复：

* 引用一个 `bugs.md` 子族锚（如自感知上报「判据可被形态 / 措辞 / 配置满足」、E2E 子族①「契约字段 / 守卫面与生成器不同步」、安装子族「装配态残留物与守卫语义未分层」）；
* 或 ≥3 条独立审查重复 finding；
* 或改动门 / 契约判据且 diff 落在已有 DR4 段级锚的路径族内。

**试点步骤**：

1. 在那份 RFC 的 §4.5 写下：留出集、为什么独立、预期结果、pre-fix 红证据计划、反面包、残留风险；
2. **pre-fix 先跑留出集并留红证**（对齐 D131 Red First）；红不了 ⇒ 换用例；换不出 ⇒ 试点失败；
3. 修复落地后真跑同一留出集，贴实际输出（必须绿）；
4. 记录：留出设计 + 运行耗时（分钟）、评审耗时、路径交叉检查误报、「留出结果是否改变闭族判断」；
5. 写三态结论：`闭族` / `未闭族` / `单案修复（无留出集）`；
6. 结果回写那份 RFC §4.5 + 其 REVIEW（轮 3 / 追加复审），本 RFC §7 只放摘要链接。

**成功判据（可证伪）**：

* **pre-fix 红 → post-fix 绿**（硬前提；红不了 / 绿不了都不算）；
* 且留出结果**改变**闭族判断：咬出回归、证明修复比声称窄、或给出同集测试给不出的证据；
* 或留出结果**确认**闭族，且该确认是原回归用例 / 变异钉给不出的（例如跨环 / 跨栈 / 跨装配态）；
* 若只是同集测试复跑、没有新增信息 ⇒ 试点失败，Phase 1 否决。

**时间盒与 owner**：从维护者接受本 RFC 试点之日起 30 天；owner = 提案作者 / 维护者；30 天内无候选 ⇒ 休眠，由巡检器在下一个系统性修复出现时唤醒，或 30 天后报告一次；不静默制度化。
