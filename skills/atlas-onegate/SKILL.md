# atlas-onegate —— 一次对齐门（零口令协作协议）

把「确认与评审循环里的传话负担」收敛成结构化拍板点。本文件为**仓内正本**
（`install.py` 逐 `skills/atlas-*/` 装配分发到各平台 skill 目录：
`.agents/skills` / `.claude/skills` / `.codex/skills`）；留证面 = Atlas 仓
`proposals/RFC-20261114-07` 与 `proposals/KICKOFF-requirement-protocol.md`
（骨架正文在 proposals/，不进装配集，故本档自包含）；用户级
`~/.agents/skills/atlas-onegate/` 为同内容副本。正本 / 副本 / RFC 不一致时
以 RFC 与本正本为准（发现漂移先回写正本）。

## 0. 零口令

本协议默认生效，用户正常说需求即入场。Agent 自判启用：需要产出候选方案 /
改动的讨论才走仪式；单点事实问答、一句话小改不套。启用可见（档位声明）；
用户说「直接做 / 别问」即跳过轻档仪式。

## 1. 需求起手（第一回复三件套）

1. **结构化回读**：目标 / 范围 / 非目标；
2. **假设清单**：本该问但按合理默认推进的点，逐条带依据与证伪方式；
3. **档位声明**：轻档（单点改动 / 可逆）→ 单候选 + 自评 + 单评审；全档
   （跨 ≥2 契约面、不可逆、触及门/判据，**任一命中存疑从严**）→ 多候选 +
   互评 + 一次对齐门 + 并行双评审。候选成形后可升档（评审者亦有权升档），
   降档需用户点头；
4. **一次对齐门**：单轮 ≤2 问，按影响排序，其余转假设清单；答完即开工，
   不逐条确认。

## 2. 三类才问人（全程中断权）

封闭三值，之外一律按假设推进并留痕：
- **缺信息**：答案改变方案形态，且 grep / 读码 / 查料不可自证；
- **缺权限**：用户资产、外发、发版、仓外/生产面/不可逆写盘（git 可逆的
  仓内写盘不算）；
- **真取舍**：≥2 个候选各有实质代价，无人能替用户选。

既有必问义务不豁免：`global-rules.md` §7 四条恒为必问（Atlas 仓内）。

## 3. 意见处置（方案细节 review / 代码 review findings，四分法）

评审意见回来后不逐条请示、不把用户当传话中枢：
1. **自证面直接修**：grep / 读码 / 跑测试可核实的事实问题 → 修完留证
   （diff / 测试输出），不请示不逐条汇报；
2. **判断面回应留痕**：判断 / 取舍建议 → 作者逐一回应（采纳 / 不改+理由），
   留痕在意见单或 REVIEW 档，不外溢会话；
3. **真取舍升级一次**：回应后仍分歧且影响验收口径 → 收敛成一个决策点
   （选项+代价+推荐）升级用户，一次问完（≤2 问）；§7 四条所在项不受本分拣
   影响，一律人工；
4. **回评审按派工规则**：批量修复方案先按 1~3 收拢再动工；re-review 全档
   双评、轻档单评。

## 4. 并行双评审派工（全档）

同一冻结输入（同一文件 + 逐字相同指令）派两个互不可见评审；合流四规则：
严重度沿用既有闭集、定级不一致取高；双命中需独立定位/独立理由才升可信度；
真分歧不做假合流——回应留痕，仍分歧默认从严、影响验收口径才升级用户一次；
原始意见按 REVIEW 编号落盘，或合流单附双评对照表。无并行环境 → 单评 +
显式标注「未双评」，不伪装。

## 5. 与既有面的关系

- Atlas 仓内：`independent-review.md` 骨架管「意见怎么产生」，本协议管
  「意见进来之后怎么处置」——叠加不替代；`atlas review` 编排器照旧。
- 起案落笔前的澄清节（RFC-20261114-05 §0）：对齐门问题集覆盖四必须
  （做什么 / 为谁做 / 关键约束 / 验收口径），缺项按缺信息进门；门回读即
  §0 复述输入，落笔不重问。
