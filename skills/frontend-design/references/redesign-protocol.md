# 改版协议

_原 SKILL.md Section 11 逐字移入。_

本 skill 同时处理 **全新搭建和改版**。**模式判错，是改版产出变差的第一大来源。**

### 11.A 先判模式（第一个动作）
* **全新搭建**：没有既有站点，或已获批准彻底重做。旋钮基线取自 Section 1。
* **改版 - 保真**：现代化但不破坏品牌。先审计，抽出品牌 token，逐步演进。
* **改版 - 重做**：在既有内容之上换一套新的视觉语言。视觉按全新搭建处理，内容与信息架构保留。

如果两者难分，**只问一次**：*「这次改版是保留既有品牌，还是视觉上从零开始？」*

### 11.B 动手之前先审计
提出改动方案之前，先把现状写下来：
* **品牌 token**：主色 / 强调色、字体栈、logo 处理方式、圆角。
* **信息架构**：页面树、主导航、关键转化路径。
* **内容区块**：现在有哪些、哪些在干活、哪些是填充物。
* **要保留的范式**：标志性交互、可辨识的 hero、文案调性。
* **要淘汰的范式**：AI 味破绽、坏掉的版面、死链、通用图库图、性能陷阱。
* **给现有站点读一遍旋钮**：推断它当前的 `DESIGN_VARIANCE` / `MOTION_INTENSITY` / `VISUAL_DENSITY`。**这才是你的起点，不是基线。**
* **SEO 基线**：当前有排名的页面、meta title、结构化数据、OG 卡片。**SEO 迁移是改版的第一号风险。**

### 11.C 保留规则
* **不要动信息架构**，除非用户要求。页面 slug、锚点 ID、主导航标签保持稳定，为了 SEO 也为了用户的肌肉记忆。
* **先抽出品牌色，再套 Section 4.2。** 已经是紫色的品牌就让它保持紫色，套用 LILA 规则的覆盖条款。
* **保留文案调性**，除非用户要求改写。**视觉现代化 ≠ 内容重写。**
* **尊重既有的可访问性成果。** 不要回退焦点状态、alt 文字、键盘导航、对比度。
* **尊重既有的埋点事件。** 不要重命名下游追踪依赖的按钮、表单字段、section ID。

### 11.D 现代化杠杆（按优先级）
**按顺序用，brief 满足了就停：**
1. **字体刷新**：单位风险换来的视觉提升最大。
2. **间距与节奏**：加大 section padding，修正纵向节奏。
3. **配色校准**：去饱和、统一中性色、保留品牌强调色。
4. **动效层**：给既有组件加符合 `MOTION_INTENSITY` 的微交互。
5. **hero 与关键 section 重排**：用 Section 10 的词汇重构漏斗顶部。
6. **整块替换**：仅当既有区块已经救不回来时。

### 11.E 决策树：定向演进还是彻底重做
* 信息架构、内容、SEO 都健康 → **定向演进**（杠杆 1-4）。约 40% 的风险拿到约 70% 的价值。
* 视觉债是结构性的（信息架构坏了、没有设计系统、移动端坏了）→ **彻底重做**，但严格保留内容。
* 品牌本身要换 → **全新搭建**。

### 11.F 绝不允许悄悄改的东西
未经用户明确批准，绝不修改：
* URL 结构 / 路由 slug。
* 主导航标签。
* 表单字段名或顺序（会破坏埋点和自动填充）。
* 品牌 logo 或文字标。
* 既有的法律 / 同意 / cookie 文案。
