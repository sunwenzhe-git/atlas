# 设计工程指令（偏见纠正）

_原 SKILL.md Section 4 逐字移入。4.7（版面硬规则）与 4.11（页面主题锁）在 SKILL.md 里保留了一份摘要；读到时注意两边一致，数值以本文件为 canonical。_

LLM 会默认掉进陈词。**主动覆盖这些默认。** 每条规则都有情境化的覆盖路径。

### 4.1 字体排印
* **Display / 标题**：默认 `text-4xl md:text-6xl tracking-tighter leading-[1.05]`。
  * **Display 字号上绝不用裸 `leading-none`。** 1.0 会切掉降部，并让多行挤成一团。紧度来自 `tracking-tighter`，不来自零行高。
  * **单行**：最低 `leading-[1.05]`。**两行及以上，或斜体词含 `y g j p q`**：`leading-[1.1]` + 留 `pb-1`。裁决见 Section 6.K。
* **正文 / 段落**：默认 `text-base text-gray-600 leading-relaxed max-w-[65ch]`。
* **无衬线字体选择：**
  * **不推荐作为默认**：`Inter`。优先选 `Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi`，或契合品牌的衬线字。
  * **覆盖条件**：用户明确要中性 / 标准 / Linear 风，或 brief 是公共部门 / 可访问性优先的站点时，`Inter` 可用。
  * **营销表面：一个字族覆盖全页。** 品牌字同时负责导航、按钮和表单控件。身份感就是目的；FOUT 靠 `font-display: swap` + 预加载关键字重解决（`typo-preload-fonts.md`）。
  * **应用表面：chrome 用系统字栈。** 在 Web 产品界面里，导航 / 按钮 / 表单 label / 输入框 / 表格单元格用系统字栈（`typo-system-font-stack.md`）。控件上「即时渲染」优先于品牌字体；品牌字留给标题和品牌时刻。**按表面切，不按元素切**，见 6.K。
* **值得记住的搭配**：`Geist` + `Geist Mono`，`Satoshi` + `JetBrains Mono`，`Cabinet Grotesk` + `Inter Tight`，`GT America` + `IBM Plex Mono`。

* **衬线纪律（作为默认非常不鼓励）：**
  * 把衬线当作**任何项目的默认字体**都是非常不鼓励的。「它感觉有创意 / 高端 / 编辑感」**不是**用衬线的理由。模型心里那套「创意 brief = 衬线」的默认心智，是生产测试里被验证次数最多的单一 AI 味。
  * **只有满足以下之一，衬线才是可接受的：**
    - 品牌 brief 字面点名了某个衬线字体，或
    - 审美家族确实是编辑 / 奢华 / 出版 / 手稿 / 传承 / 复古，**且**你能说清为什么这个具体的衬线字契合这个具体的品牌
  * 其它所有情况（创意代理、设计工作室、现代品牌、高端消费、作品集、生活方式），**一律默认无衬线 display**（Geist Display、ABC Diatype、Söhne Breit、Cabinet Grotesk Display、Migra Sans、GT Walsheim、Inter Display、PP Neue Montreal）。无衬线 display 字不「无聊」，它成为默认的原因和黑色成为时尚默认色的原因一样。
  * **强调规则（相关）**：想在标题里强调某个词（那种「and *spatial* design」的动态处理），就用**同一字族的斜体或粗体**。**不要**为了增加视觉兴趣，往无衬线标题里塞一个衬线词（反之亦然）。跨字族混用强调是业余做法。同族斜体 / 粗体强调才是对的。
  * **明确禁作默认**：`Fraunces` 和 `Instrument_Serif`（模型最爱的两个 display 衬线字）。
  * **如果衬线确有正当理由**（按上面标准，很少见），从这个池子里轮换，**不要连续项目复用同一个衬线字**：PP Editorial New、GT Sectra Display、Cardinal Grotesque、Reckless Neue、Tiempos Headline、Recoleta、Cormorant Garamond、Playfair Display、EB Garamond、IvyPresto、Migra、Editorial Old、Saol Display、Söhne Breit Kursiv、Domaine Display、Canela、Schnyder、Tobias、NB Architekt、ITC Galliard。

* **斜体降部间隙（强制）**：display 字体用斜体、且词里含降部字母（`y g j p q`）时，`leading-[1]` 或 `leading-none` 会切掉降部。最低用 `leading-[1.1]`，并在外层元素上留 `pb-1` 或 `mb-1`。**交付前逐个审 display 标题里的斜体词。**

### 4.2 配色校准
* 强调色最多 1 个。默认饱和度低于 80%。
* **LILA 规则**：「AI 紫 / 蓝色发光」审美不鼓励作为默认。不要自动给按钮加紫色光晕，不要随机霓虹渐变。用中性基底（Zinc / Slate / Stone）配单个高对比强调色（Emerald、Electric Blue、Deep Rose、Burnt Orange 等）。
* **覆盖条件**：品牌或 brief 明确要紫 / 紫罗兰 / lila 时就拥抱它。但要有意图地执行：配色一致、中性色协调、渐变克制。不要做成通用的 AI 渐变糊。
* **一个项目一套配色。** 不要在同一项目里冷暖灰来回摆。
* **配色一致性锁（强制）**：一旦为页面选定了强调色，它就在**整页**使用。暖灰站不会在第 7 个 section 突然冒出蓝色 CTA。玫瑰色强调的站不会在页脚出现青色状态徽章。选一个强调色，锁住，交付前审每个组件。

* **高端消费配色禁令（强制，第二高频的 AI 味）：**
  * 面对高端消费类 brief（厨具、健康、手作、奢侈品、传承工艺、DTC 家居等），LLM 的默认是**暖米色 / 奶油色 + 黄铜 / 陶土 / 牛血红 / 赭石 + 浓缩咖啡 / 墨色深字**。以下 hex 家族禁止作为默认背景与强调色：
    - 背景：`#f5f1ea`、`#f7f5f1`、`#fbf8f1`、`#efeae0`、`#ece6db`、`#faf7f1`、`#e8dfcb`（都是「暖纸 / 奶油 / 粉笔 / 骨白」）
    - 强调：`#b08947`、`#b6553a`、`#9a2436`、`#9c6e2a`、`#bc7c3a`、`#7d5621`（都是「黄铜 / 陶土 / 牛血红 / 赭石」）
    - 文字：`#1a1714`、`#1a1814`、`#1b1814`（都是「浓缩咖啡 / 暖近黑」）
  * 这套配色**禁止**作为高端消费 brief 的默认落点。你交付过的每一个高端消费站点用的都是这套一模一样的配色。品牌因此变得不可见。
  * **默认替代（轮换，不要复用）：**
    - **Cold Luxury（冷感奢华）**：银灰 + 铬 + 烟熏（参考 Tesla、去掉皮质的 Apple Watch Hermes）
    - **Forest（森林）**：深绿 + 骨白 + 琥珀强调（参考 Filson、Patagonia 高端线）
    - **Black and Tan（黑与棕褐）**：真正的近黑 + 暖棕褐，强对比，不用米色
    - **Cobalt + Cream（钴蓝 + 奶油）**：饱和蓝压单个中性色，不用黄铜
    - **Terracotta + Slate（赤陶 + 板岩）**：暖锈红压冷灰，不用黄铜
    - **Olive + Brick + Paper（橄榄 + 砖红 + 纸白）**：低饱和橄榄加砖红强调
    - **纯单色 + 单点饱和**：近白 + 近黑 + 一个明亮强调（电蓝、翠绿、亮粉等）
  * **配色轮换规则**：上一个你生成的高端消费项目用了米色 + 黄铜家族，这一个**必须**换一个家族。不要连续两次交付同一套暖手作配色。
  * **覆盖条件**：只有当品牌 brief 明确点名那些颜色，或品牌身份确实是复古 / 手作 / 暖工艺，**且**你能说清为什么这套配色契合这个品牌时，米色 + 黄铜 + 浓缩咖啡才可接受。**因为「这是个厨具 brief」就默认去拿它，禁止。**

### 4.3 版面多样化
* **反居中偏见**：`DESIGN_VARIANCE > 4` 时避免居中 hero / H1。强制走「分屏」（50/50）、「左正文 / 右资产」、「非对称留白」，或滚动钉住结构。
* **覆盖条件**：编辑 / 宣言 / 发布公告类 brief，当信息本身就是设计时，居中 hero 可以。

### 4.4 材质、阴影、卡片
* **仅当抬升承载真实层级时**才用卡片。否则用 `border-t`、`divide-y` 或留白来分组。
* 用阴影时，把它调成背景色的色相。浅色背景上不要用纯黑投影。
* `VISUAL_DENSITY > 7` 时：通用卡片容器禁止。数据指标在平铺版面里透气。
* **圆角一致性锁（强制）**：整页选**一套**圆角尺度并坚持。选项：全直角（radius 0）、全柔角（radius 12-16px）、全胶囊（交互元素用 full radius）。允许混用，但**必须有书面规则**（例如「按钮全胶囊、卡片 16px、输入框 8px」）且处处遵守。方形版面里放圆角按钮，或胶囊按钮的页面里放方形卡片，都是破损设计。

### 4.5 交互 UI 状态
LLM 默认只做「静态成功态」。完整循环每次都要实现：
* **Loading**：骨架加载器，形状要贴合最终版面。避免通用圆形转圈。
* **空状态**：认真构图，并说明如何填充内容。
* **错误状态**：清晰、内联（表单），或情境化（toast 只用于瞬时信息）。
* **触感反馈**：`:active` 上用 `-translate-y-[1px]` 或 `scale-[0.98]` 模拟物理按压。
* **按钮对比度检查（强制，a11y）**：交付任何按钮之前，确认按钮文字对自身背景可读。白底按钮 + 白字、`bg-white` CTA 配 `text-white` 标签、无边框透明按钮压在页面背景上，**全部禁止**。逐个审 CTA：对比度最低 WCAG AA（正文 4.5:1，大字 18px+ 用 3:1）。压在照片上的 ghost 按钮同理（加背板、压暗层或描边）。基线规则：**6.D.9**。
* **CTA 换行禁令（强制）**：桌面端按钮文字**必须**一行放得下。像「VIEW SELECTED WORK」这种标签换到 2-3 行，按钮就是坏的。修法二选一：**缩短标签**（主 CTA 最多 3 个词，理想 1-2 个）**或加宽按钮**（不要人为给 CTA 加 `max-width` 约束）。桌面端 CTA 换行即预检失败。
* **同意图 CTA 去重（强制）**：一页上两个意图相同的 CTA 即预检失败。同意图的例子：「Get in touch」+「Contact us」+「Let's talk」+「Start a project」+「Start something」+「Reach out」全部属于「联系」意图，**只能挑一个标签**并在全页（导航、hero、页脚）统一使用。「Try free」+「Get started」+「Sign up free」（都是「注册」意图）以及「View work」+「See selected work」+「Browse projects」（都是「作品集」意图）同理。**一个意图一个标签。**
* **表单对比度检查（强制，a11y）**：表单输入框、placeholder、focus ring、辅助文字、错误文字，对所在 section 背景全部满足 WCAG AA。近白表单上的浅色 placeholder、白色表单放在白色 section 上、表单 label 灰到不足 4.5:1，**全部禁止**。交付前审每个表单。基线规则：**6.D.9**。

### 4.6 数据与表单范式

表单规则的规范副本在 **Section 6.E**（结构、校验时机、错误文案、移动端输入类型、自动填充）。其中两条不容商量，这里再重复一次：**label 放在输入框上方**，**绝不用 placeholder 当 label**。

### 4.7 版面纪律（硬规则。有一条不满足即为交付破损作品）

* **hero 必须占满首屏。** 桌面端标题最多 2 行，副文案最多 **20 个词**且最多 3-4 行，CTA 不滚动就能看到。文案太长：降字号**或**砍文案。**如果你用 20 个词的副文案说不清价值主张，那是价值主张不清楚，不是规则太紧。** 绝不让 hero 溢出、逼用户滚动才能找到 CTA。
* **hero 字号纪律。** 字号和图片尺寸**一起**规划。hero 资产很大、标题又超过 6 个词时，不要从 `text-7xl/text-8xl` 起手。合理默认区间：多数 hero 用 `text-4xl md:text-5xl lg:text-6xl`；只有标题 3-5 个词时才用 `text-6xl md:text-7xl`。**hero 标题占到 4 行，永远是字号错误，不是文案长度错误。**
* **hero 顶部留白上限（强制）**：桌面端最多 `pt-24`（≈6rem）。超过这个值，hero 内容会浮在视口中段，读起来是版面 bug 而不是刻意留白。hero 需要更多呼吸感时，加大字号或资产尺寸，**不是加顶部留白**。
* **hero 文本栈纪律（最多 4 个文本元素）。** hero 是一个瞬间，不是 feature 列表。允许的文本元素，总数最多 4 个：
  1. Eyebrow（小号大写标签）**或**品牌条**或**都不要，三选一
  2. 标题（最多 2 行，见上）
  3. 副文案（最多 20 个词，最多 4 行）
  4. CTA（1 主 + 最多 1 次）
  * **hero 内禁止**：CTA 下方的小标语（「Works with GitHub, GitLab, and self-hosted Git」）、信任微条（「Used by engineering teams at...」）、价格提示（「Free for solo, $10/user for teams」）、feature 项目符号列表、social proof 头像行。这些全部下移到 hero 正下方的专门 section。
  * 如果同一个 hero 里既有 eyebrow 又有 CTA 下方小标语，砍掉小标语。既有品牌条又有小标语，砍掉小标语。**一个 hero 最多一个小的文本元素。**
* **「Used by / Trusted by」logo 墙放在 hero 下方，绝不放进 hero。** hero 是给价值主张和主 CTA 的。logo 墙是紧邻其下的独立 section。不要把信任 logo 塞进和 hero 文案同一个 flex 行里。
* **导航在桌面端必须一行排完。** 到 `lg`（1024px）还放不下，就压缩标签、砍掉次级项，或收进汉堡。**桌面端两行导航是破损设计。**
* **导航高度上限：桌面端最多 80px，默认 64-72px。** 不要那种吃掉 15% 视口的巨大「代理机构」导航条。
* **bento 栅格必须有节奏，不能一边倒重复。** 不要堆 6 个「左图右文」行。变化构图：交替全宽 feature 行、非对称瓦片尺寸、纵向断点。
* **bento 单元格数规则（强制）**：bento 栅格有多少内容就**正好**多少个格子。3 个 item → 3 个格子（1+2 或 2+1 或非对称三连）。5 个 item → 5 个格子（2+3、3+2、hero+4 等）。**栅格中间或末尾出现空格，就是你规划错了。重排栅格，不要贴空白瓦片。**
* **Section 版面家族重复禁令。** 一旦某个 section 用了某套版面家族（例如三栏图片卡、全宽引言、图文分栏），这套家族在整页最多出现**一次**。「Selected commissions」不能长得像「What we do」。**8 个 section 的落地页至少要用 4 种不同家族。**
* **zigzag 交替上限（强制）。** 「左图右文」然后「左文右图」的交替 zigzag 很平庸。**这种图文分栏模式最多连续 2 个 section。第 3 个连续的图文分栏即预检失败。** 用全宽 section、纵向堆叠 section、bento 栅格、跑马灯或另一个版面家族来打断它。
* **eyebrow 克制（强制，生产测试里被违反最多的规则）。** eyebrow 是指坐在 section 标题上方的小号大写宽字距标签（例如 `FOUR COLORWAYS`、`SELECTED WORK`、`THE HARDWARE`、`Git-native task management`）。典型 CSS 特征：`text-[11px] uppercase tracking-[0.18em]`、`font-mono text-[10.5px] uppercase tracking-[0.22em]`。**每个 AI 搭出来的站都在每个 section 标题上放一个 eyebrow，于是节奏全部模板化。** 硬规则：
  - **每 3 个 section 最多 1 个 eyebrow。** hero 算 1 个。所以 9 个 section 的页面最多用 3 个。
  - 如果 section A 有 eyebrow，接下来 2 个 section 就不能有。
  - **预检是机械的**：统计所有 section 组件里 `uppercase tracking`（或类似的小号大写等宽标签）的出现次数。若次数 > `ceil(sectionCount / 3)`，产出失败。
  - **不用 eyebrow 该怎么做**：直接删掉。光有标题就够了。如果觉得需要给 section 归类，它在页面上的位置已经完成了归类，不需要标签。
* **分栏标题禁令（强制）。** 「左边大标题 + 右边小解释段」当 section 标题（左 col-span-7/8，右 col-span-4/5，小正文段飘在右栏里）**默认禁止**。section 应该只承载**一个**聚焦信息。确实同时需要标题和解释段，就纵向堆叠（标题在上，正文在下，max-width 65ch）。只有存在真实构图理由时（例如右栏承载视觉或交互元素，而不只是填充文字）才回到分栏标题范式。
* **bento 背景多样性（强制）。** bento 与 feature 栅格 section 不能是 6 张白底白边、里面只有文字的卡片。任何多格栅格里至少**2-3 个格子**要有真实视觉变化：真实图片、契合品牌的渐变（不是 AI 紫）、图案、有色背景。奶油色压奶油色、里面只有文字的 bento，即使页面其余部分很好，读起来也是无聊的 AI 默认。
* **移动端塌陷必须逐 section 显式声明。** 每个多栏版面，都要在同一个组件里声明 `< 768px` 的降级。不要「它能跑，Tailwind 会处理」这种假设。

### 4.8 图片与视觉资产策略

落地页和作品集是**视觉产品**。用 div 拼假截图的纯文字页面是垃圾。

**视觉资产的优先级顺序：**
1. **优先生成工具。** 环境里只要有**任何**图像生成工具（`generate_image`、MCP 图像工具、IDE 集成的生成、OpenAI 图像工具等），就**必须**用它生成 section 专属资产：hero 摄影、产品图、纹理背景、氛围图。按 section 需要的宽高比生成。**不要因为手搓 CSS 感觉更快就跳过这一步。**
2. **其次用真实网络图片。** 没有生成工具时，用真实摄影来源。可接受的默认：
   * `https://picsum.photos/seed/{描述性种子}/{w}/{h}` 做占位摄影（种子要描述该 section，例如 `marrow-cookware-kitchen`）
   * brief 提供了就用真实的图库或品牌 URL
   * 明确允许时用开放授权来源（Unsplash 直链、Pexels）
3. **最后手段：告诉用户。** 两者都不可行时，**不要**用手绘 SVG 插画或 div 拼的「假截图」把页面填满。而是留下清楚标注的占位槽（`<!-- TODO: hero product photo, 1600x1200 -->`），并在回复末尾说：*「这个页面需要真实图片，位置在：\[列出所有位置\]。请生成或提供。」*

**再极简的站也需要真实图片。** 纯文字页面不是极简，是没做完。即使是 Linear 风的编辑型站点，也至少需要 2-3 张真实图片（hero、一张产品 / 生活方式图、一张辅助图）。brief 克制就生成黑白极简摄影；**不要因为旋钮低就完全跳过图片**。

**social proof 用真实公司 logo。** brief 需要「Trusted by / Used by / Customers」logo 墙时，**不要**默认用纯文字文字标（`<span>Acme Co</span>` 排成一行）。用真实 SVG logo：
* **来源：Simple Icons**（`https://cdn.simpleicons.org/{slug}/ffffff` 可指定颜色，或 `simple-icons` npm 包）。覆盖大多数知名品牌。
* **备选：devicon** 用于技术栈 logo（`@svgr/cli` 或 CDN）。
* **品牌名是编的？那 logo 标记也一起编。** 生成简单字母组合标记（圆圈里一个字母、两个字母连字、抽象字形），用符合页面风格的内联 `<svg>` 渲染。**编造的品牌名配纯文字文字标看起来很通用。**
* 浅色与暗色模式下**都要**确认 logo 能正常渲染（暗底白字、浅底黑字，或单色主题变量）。
* **只放 logo 规则（强制）**：logo 墙就是 logo，别的都不要。**不要**在每个 logo 下方印行业 / 品类标签（不要在 `Vercel` 下面写 `hosting`、`Stripe` 下面写 `payments`、`Cloudflare` 下面写 `infra`）。logo 本身就是可信度，标签提供不了用户不知道的信息。可选：品牌名作为屏幕阅读器的 alt 文字，可选链接到品牌站点。就这些。

**手绘插画：**
* 库里的 SVG 图标：可以（见 Section 3.C）。
* 手绘装饰性 SVG（自定义插画、logo、标记）：**强烈不鼓励**，绝不作为默认。仅在以下情况可接受：
  - brief 明确要求（「给我画个 SVG logo」）
  - 它是单个简单的几何标记（一个方块、一个圆、一个 display 字体的文字标）
  - 你对产出质量有把握

**div 拼假截图禁止。** 用 `<div>` 方块拼的「手搭产品预览」、假任务列表、假 dashboard、假终端窗口，都是 AI 味。需要展示产品时：
* 有真实截图 URL 就用它
* 用图像工具生成一张
* 用真实的组件预览（页面内嵌一个真的 UI 迷你版）
* 或干脆不放预览，改用编辑型摄影

**hero 需要真实视觉。** 文字 + 渐变光斑不是 hero，那是占位。

### 4.9 内容密度

落地页活在**第一印象**里，不靠通读。**下狠手砍。**

* **每个 section 的默认内容形态**：短标题（≤ 8 个词）+ 短副段落（≤ 25 个词）+ 一个视觉资产**或**一个 CTA。超出这个量，必须由该 section 的职责来论证。
* **不要数据倾泻型 section。** 营销页上放 20 行出版目录、30 行获奖名单、巨大价格矩阵，就是错的版面。改用：
  - 精选 3-5 条 + 「View full list」链接
  - 跑马灯 / 轮播表达广度
  - 数据本身就是产品时，另开一个页面
* **长列表需要换 UI 组件，而不是把列表拉长。** 默认 `<ul>` 加项目符号 / `divide-y` 行是最懒的选择。超过 5 项时，改用：
  - 分两栏并分组
  - 卡片栅格，每项配图 + 标签
  - 可分类的话用 tabs / 手风琴
  - 横向 scroll-snap pills
  - 广度型列表（证言、logo、能力项）用轮播
  - 「一堆不需要逐个关注的东西」用跑马灯
  **10 行规格表每行下面一条发丝线，是最糟的默认。** 要么把行分成 2-3 组、组间用稀疏分隔，要么改成每个规格一张卡。
* **规格表专门说（Marrow 厨具那个模式）。** 每行都 `border-b` 的长规格表，是厨具 / 硬件 / 服饰 / 手作类 brief 的 AI 默认。**禁止。** 具体替代：
  - **双栏卡片栅格**：每个规格一张卡，含规格名、数值（大号 display 数字）、一行「为什么重要」的正文。桌面端两栏，移动端一栏。
  - **scroll-snap 横向 pills**：每个规格一个 pill，用户可以横向甩着看。
  - **分组块**：把 10 个规格归成 3 个逻辑簇（例如「材质」「烹饪」「保修」），每簇一条柔和分隔线加一个簇标题。
  - **重点 vs 其余**：3-4 个重点规格做成大号 display 瓦片，剩下的收进「View full specifications」折叠区。

* **文案自查（交付前强制）**：宣布任务完成之前，把页面上每个可见字符串重读一遍（标题、副标题、eyebrow、按钮标签、正文、图注、alt 文字、页脚文字、错误信息）。标出以下任何一类：
  - **语法破损**（「free on its past」「two plans but one is honest」「to put it on the table」脱离语境）
  - **指代不清**（「we plan to stay that way」但没有前文）
  - **听起来像 AI 幻觉**（机灵但错的文字游戏、接不上的强行隐喻、「优雅的空话」）
  - **像 LLM 在努力显得有想法**（被动的谦逊、装手工匠人的标签、假装诗意的微元句）
  每条被标出的字符串都要重写。拿不准一句话讲不讲得通，就换成平实的功能句。**AI 生成的机灵文案比无聊文案更糟。**
* **假精确数字会被标记。** 像 `92%`、`4.1×`、`48k`、`5.8 mm`、`13.4 lb` 这类数字，只有三种情况：
  - 来自真实数据（brief、品牌规范、公开指标）：可以
  - 明确标注为模拟（`<!-- mock -->`、「example」、「sample data」）：可以
  - 是 AI 编出来的规格美学：**禁止**。不要伪造品牌并未宣称的工程精度。
* **一页一种文案语域。** 不要把技术等宽（「47 tasks · 0.6 ctx-switches/day」）、编辑散文和营销短句混在同一段构图里，除非品牌调性明确要求。

### 4.10 引言与证言

* 引言正文**最多 3 行**。绝不 6 行。原引言更长就砍。**落地页上的引言是节选，不是完整评测。**
* 极小字号时（例如页脚式证言），行数上限可以略微放宽。精神是「一眼看完」。
* 引言文字里**不要用破折号**做设计花活（长停顿、动态破折号、破折号项目符号）。见 Section 9.G，破折号完全禁止。
* 署名：姓名 + 职位 +（可选）公司。**绝不只写名字**（「- Sarah」）。
* 引号：用真正的排版引号（“ ”）或干脆不用。**不要用 ASCII 直引号（" ）。**

### 4.11 页面主题锁（浅色 / 暗色一致性）

**整页只有一个主题。section 不得反转。**

* 页面是暗色，**所有** section 就都是暗色。深色 section 中间不许夹一个浅色暖纸 section（反向同理）。用户不该在滚动中途感觉走进了另一个网站。
* 例外：brief 明确要求「Color Block Story」或「Theme Switch on Scroll」手法，**且**那是一次刻意的构图（一次完整主题切换配强转场，而不是随机交替），此时每页允许一次。
* 默认做法：在页面层面选定浅色、暗色或 auto（`prefers-color-scheme`）并锁住。同一主题家族内的 section 背景色差可以（`bg-zinc-950` 紧挨 `bg-zinc-900`）；在 `bg-zinc-950` 的页面中间翻成 `bg-amber-50` 就是破损。
* 使用自带主题机制的设计系统（Radix Themes、带 `<Theme>` 的 shadcn/ui）时，在 `layout.tsx` 或页面根节点**只设一次**主题。不要让各个 section 各自覆盖。
