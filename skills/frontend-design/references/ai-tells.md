# AI 味：完整禁令清单

`SKILL.md` Section 9 只放了摘要。这里是完整版，**产出任何版面之前读一遍**。

这些签名来自真实 LLM 生成营销页的测试。它们是模型想「看起来像设计过」时自动掉进去的套路。**除 brief 明确点名要求，一律硬禁。**

---

## 9.A 视觉与 CSS

* **不要霓虹光 / 外发光。** 用内描边或轻微带色阴影代替。
* **不要纯黑 `#000000`。** 用近黑、`zinc-950` 或炭灰。
* **不要过饱和强调色。** 降到能和中性质融合的饱和度。
* **大标题不要渐变文字。**
* **不要自定义鼠标指针。** 过时、对可访问性和性能都不友好。

## 9.B 字体

* **默认避开 `Inter`。** 见 Section 4.1，有覆盖条件。
* **不要只靠巨大 H1 喊叫。** 层级靠字重 + 颜色建立，不靠原始字号。
* **衬线约束**：用于编辑 / 奢华 / 出版，**不用于产品界面**。

## 9.C 版面与间距

* **数学上精确**的 padding 与 margin。不留位置尴尬的空隙。
* **禁止三等分 feature 卡片。** 横向三张一模一样的卡片是头号禁令。改用两栏 zigzag、非对称栅格、pin 住滚动，或横向滚动。

## 9.D 内容与数据（「Jane Doe」效应）

* **不要通用人名。** 「John Doe」「Sarah Chan」「Jack Su」一律换成真实可信、符合地域的名字。
* **不要通用头像。** 不要 SVG 蛋形或 Lucide 用户图标，用可信的照片占位或明确的风格化处理。
* **不要假完美数字。** 避开 `99.99%`、`50%`、`1234567`。用有毛边的真实数据感（`47.2%`、`+1 (312) 847-1928`）。
* **不要创业套壳品牌名。** 「Acme」「Nexus」「SmartFlow」「Cloudly」一律换成有上下文、听起来像真品牌的命名。
* **不要填充动词。** 「Elevate」「Seamless」「Unleash」「Next-Gen」「Revolutionize」换成具体动词。

## 9.E 外部资源与组件

* **不要手写 SVG 图标。** 用 Phosphor / HugeIcons / Radix / Tabler。`Lucide` 仅在被明确要求时用。
* **手绘装饰性 SVG 强烈不鼓励**作为默认（见 Section 4.8）。
* **不要 div 拼的假截图。** 永远不要用 `<div>` 方块拼出假产品界面来充当截图。用真图、生成图，或干脆不放。
* **不要挂掉的 Unsplash 链接。** 用 `https://picsum.photos/seed/{可读的种子串}/{w}/{h}`、生成的占位图，或真实资产。
* **`shadcn/ui` 只能用改造过的状态。** 改造圆角、颜色、阴影、字体以匹配项目审美，**绝不交付默认样式**。

## 9.F 生产测试里的高频 AI 味（直接禁止）

以下条目都来自真实测试，是模型试图「看起来像设计过」时最常掉进去的坑。

### Hero 与页面顶部

* **hero 里不要版本号。** `V0.6`、`v2.0`、`BETA`、`INVITE-ONLY PREVIEW`、`EARLY ACCESS`、`ALPHA` 不得用作 eyebrow。仅当 brief 确实在讲发布 / 预览状态时可用。
* **不要「Brand · No. 01」式副 eyebrow。** 「Marrow · No. 01 · The 6-quart」这类微元行，跳过。

### 章节编号与微标签

* **不要章节编号式 eyebrow。** `00 / INDEX`、`001 · Capabilities`、`002 · Featured commission`、`06 · how it works`、`05 · The honest table` 一律禁止。eyebrow 应该用平实语言命名主题，不该做枚举。
* **图片或 bento 瓦片上不要 `01 / 4` 式分页标记。** 用户数得出来，不需要标签。
* **不要 `Scroll · 001 Capabilities` 式滚动提示。** 一个箭头或「Scroll」就够了，不要章节号前缀。
* **不要「Index of Work, 2018 - 2026」式区间标签**当 eyebrow。直接说这个 section 是什么。

### 分隔符与圆点

* **middle-dot（`·`）要配给。** 每行元数据最多 1 个。**不要**把它当万能分隔符用（「foo · bar · baz · qux · quux」）。需要分隔时优先用换行、发丝线或分栏。
* **不要在每个列表 / 导航 / 徽章前加装饰性彩色圆点。** 「ONE Q4 SLOT OPEN」前面、每个导航项前面、每行任务前面都来一个圆点，默认禁止。仅当圆点承载真实语义状态（服务器状态、可预约标记）且极度克制时才可用。

### 破折号与排版花活

* **不要 em-dash（`—`）做设计元素，也不要出现在任何其它位置。** 完整禁令见 9.G。标题、eyebrow、pills、正文、引言、署名、图注、按钮文字、alt 文字一律禁止。用普通连字符 `-`。
* **不要 `<br>` 断行 + 斜体标题**当成默认的设计动作。「for thirty\<br\>*years.*」这类切分。标题先要读得自然，只有 brief 要求时才玩巧。
* **不要竖排旋转文字**（「INDEX OF WORK, 2018 - 2026」旋转 90°）。这是代理机构作品集的老套。仅当 brief 明确要求代理 / Awwwards / 实验风格，且竖排真的有构图作用时才用。
* **不要十字线 / 发丝栅格线做装饰。** 只为「让页面看起来被设计过」而画的横竖线，禁止。只有当它们真的在组织内容时才用。

### 假产品预览

* **hero 里不要 div 拼的假产品界面**（假任务列表、假终端、假 dashboard）。这是第一号 LLM 设计破绽。用真截图、生成图、真组件预览，或什么都不放。
* **假截图里不要放假版本页脚**（「v0.6.2-rc.1」「last sync 4s ago · main」）。不增加任何信息，只在喊 AI。

### 营销文案的 AI 味

* **不要「Quietly in use at」/「Quietly trusted by」**这类 social proof 标题。用自然语言：「Trusted by」「Used at」「Customers include」，或干脆不写标题，让 logo 自己说。
* **不要「From the field」「Field notes」「Currently on the bench」「On our desks」「Loose plates」**这类诗性标签贴在引言、博客或侧栏上。读起来像装手工匠人。用平实的功能性标签（「Testimonials」「Latest writing」「Now working on」）或不写。
* **不要「We respect the French ones」式**假谦逊的行业内梗。又甜又 AI。
* **不要天气 / 地区条**（「LIS 14:23 · 18°C」），除非 brief 明确是关于某个地点或跨时区工作室的。
* **eyebrow 下面不要微元句。** 像「Each of these is a feature we ship today, not a roadmap promise. The list will stay short on purpose.」这种挂在 section 标题下面的句子是杂物。eyebrow + 标题 + 正文就够了。
* **不要通用步骤标签。** 「Stage 1 / Stage 2 / Stage 3」「Step 1 / Step 2 / Step 3」「Phase 01 / Phase 02 / Phase 03」「Pass One / Pass Two / Pass Three」全部禁止。步骤内容本身就是标签。真要展示推进，用动词加名词（「Install」「Configure」「Ship」），不要「Stage 1: Install」。

### Pills、标签与版本戳

* **图片上不要叠 pills / 标签 / 徽章。** 不要在照片上盖 `<span>`，写 `Brand · 02`、`PLATE · BRAND`、`Field notes - journal`。要么让图片自己说话，要么把说明放在图片外的正下方。
* **不要装饰性来源署名。** 「Field study no. 12 · Ines Caetano」「Plate 03 · House archive」「Frame XII · 35mm」这类压在图库图下面的字符串是做作。**只有真的在为某位真实摄影师署名**时才允许。否则：不写，或写一行功能性说明（「The 6-quart, in Sage.」）。
* **营销页不要版本页脚。** `v1.4.2`、`Build 0048`、`last sync 4s ago · main` 是 CLI / 开发工具的装饰，不是落地页内容。
* **不要「Reservation 412 of 800」式实时库存计数器**做装饰。仅当 brief 明确是限量发售预约且数据真实时才可用。

### 装饰文字条

* **hero 底部不要装饰文字条。** `BRAND. MOTION. SPATIAL.`、`TYPE / FORM / MOTION`、`DESIGN · BUILD · SHIP`、`ESTD. 2018 · LISBON · BRAND. MOTION. SPATIAL.` 这类横贯 hero 底部的小号 mono 大写条是代理机构作品集老套，默认禁止。仅当这条真的承载可导航链接（sticky 底部导航）或真实状态信息（cookie 提示、文档站的构建信息）时才可用。
* **section 标题右上角不要飘小字。** 左边一个巨大标题，右上角飘一段和任何东西都不对齐的小解释段，**那个飘着的块就是破绽**。要么把副文案放到标题正下方，要么做成干净的两栏（左标题、右正文，各自对齐）。

### 列表、分隔线与打分

* **长列表 / 规格表不要每行都 `border-t` + `border-b`。** 二选一（行间下边框，或整组上方一条上边框），且稀疏使用。10 行规格表每行一条发丝线是最懒的版面，替代方案见 Section 4.9。
* **不要带填充底轨的打分 / 进度条**做对比图。要表达「X / Y」时，优先用数字 + 小图标，或没有底轨的细线内联条。大块 `bg-zinc-200` 底轨配部分填充，是 dashboard 的东西，不是落地页的。

### 地区、时间、滚动提示

* **99% 的 brief 都禁止地区 / 城市名 / 时间 / 天气条。** hero 里的「Lisbon, working with founders」、页脚里的「1200-690 Lisbon, Portugal」、导航里的「Lisbon 14:23 · 18°C」，都是代理机构作品集的装饰破绽。**仅当** brief 明确描述跨时区分布式工作室且时区与工作相关，**或**旅行类品牌，**或**有真实实体场地时才允许。页脚提一次联系地址可以，营造氛围的整条地区带不行。
* **禁止滚动提示。** 「Scroll」「↓ scroll」「Scroll to explore」「Scroll to walk through it」、滚轮图标动画，全部禁止。用户还没滚动时就在看 hero，他们知道滚动是什么。视口底部不需要标签。
* **默认零装饰性状态圆点。** 导航项前、列表行前、徽章前、状态标签前的彩色圆点都是破绽。仅当承载真实语义状态（真实服务器状态、真实可预约标记）且每个 section 限一个时才可用。

## 9.G 破折号禁令（最高频的 AI 味）

**英文输出里，em-dash `—` 完全禁止。** 它是 LLM 的招牌修辞拐杖，也是生产测试里的第一号视觉破绽。没有「限量使用」的余地，没有「自然语言频率」的余地，没有「正文里可以」的余地，一点都没有。

* **标题里禁止。** 用句号或逗号。
* **eyebrow / 标签 / pills / 按钮文字 / 图注 / 导航项里禁止。** 换成换行、分栏或发丝线。
* **正文里禁止。** 重构句子：两句加句号，或逗号，或括号，或冒号。
* **引言的署名里禁止。** 用普通连字符加空格（` - `），或换行加小号字重。
* **en-dash（`–`）当分隔符用同样禁止。** 日期区间用连字符（`2018-2026`）与数字区间同样（`€40-80k`）。

**中文输出里的破折号「——」** 是规范标点，但同样被 LLM 当成修辞拐杖滥用。不得出现在标题、eyebrow、按钮、图注中；正文里只用于真实的解释或插入语，且整页不超过一处。不用它做停顿、强调或列举。

页面上允许出现的横线字符只有：

* 普通连字符 `-`（复合词、区间、标记里的分隔线）
* 数学负号（`-5°C`）

**产出中只要出现一个不该有的 `—` 或 `——`，预检即失败，必须重写。**

这条规则没有商量余地。把限制写成「克制使用」时，模型在历史上一直会无视它。所以这里的措辞是二值的：零个。
