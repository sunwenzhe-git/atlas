## 0. 一页结论

**根因不是"人不够仔细"，是四类机制缺口叠加。** 按发生频次×修复代价排序：

| # | 根因（一句话，可证伪） | 覆盖事件 | 仓库落点（或缺失） |
|---|---|---|---|
| R1 | 只要某个计数/口径没被登记成派生占位，它必然在下一次结构变更后 1–3 天内产生一次纯手抄修复提交 | 6 起 | `scripts/ledger_snapshot.py` 的 `DEFAULT_PATHS` + `TOKEN_RE` 覆盖面之外 |
| R2 | 结构/契约变更只要没在同一次提交里盘完所有**读取方**，就会产生一次"门全绿但功能静默出域"，且只能由重新盘点的人发现 | 3 起 | 无"消费者清单"机制；`test_canonical_consistency` 只对校验器文件集合对账 |
| R3 | 新增判据的测试由实现者自写、夹具形状由实现者的假设决定 ⇒ 该判据在真实数据上至少误判/漏判一次，且只能由独立复核发现 | 5 起（含 4 轮返工） | 变异钉只验"注入必红"，不验"真实样本必不误判"；`0eac771` 自认单向 |
| R4 | 只要某批测试不在发版默认集合里（被排除 / 被 skip / 被环境旁路），它的契约漂移必然晚一个批次才被发现 | 4 起 | `release.py` 全量 + `preflight.py` 窄集；无"排除登记" |
| R5 | 发版提交只要允许夹带 `package.json`/changelog 之外的代码文件，bisect 与回滚就失效 | 2 起 | `scripts/release.py` 无"干净批"校验；10-25 的拒发守卫只挡未跟踪/脏树 |
| R6 | 多会话共用固定名资源（临时目录 / 工作树）时必有且仅有一次"读到陈旧状态" | 2 起 | 无会话命名空间；仅 `QUEUE.md` 一句"并行会话件不代清" |

**最反直觉的一个发现**：最贵的一次事故（`#70` 归档静默出域）不是"忘了写测试"，而是**新测试与实现同源、互相自洽**——`tests/test_atlas_workflow.py` 按扁平 `archive/<id>` 写断言，于是门全绿；而三个既有消费者和四组老测试按 `archive/<月>/<id>` 写死，归档后任务卡**直接不再受检**。门越绿，漏得越干净。

**数据不支持的说法**：「大多数红是并行会话造成的」。全区间 37 条 fix 提交里，能归因到并发/共享资源的只有 2 条（`bd5bea1` 的 `#66`、`fba49ec` 前史），占比 5%；最大头是判据自身写错（约 15 条，41%）与功能缺口（约 8 条，22%）。

## 3. 根因层

> 每条的格式：可证伪表述 → 覆盖事件 → 仓库机制落点 → 为什么不是"沟通不足"。

### R1｜派生事实的"单一源"只覆盖被登记成占位符的子集，其余仍是手抄

**可证伪表述**：把时间窗切成 D201 前后两段，若"账本类提交占全部提交的比例"没有显著下降，或下降后仍在 1 次/活跃日以上，则单一源机制未解决漂移，只是转移了漂移面。

**数据**：18.7% → 10.0%，**下降了，但没消失**；残余 3 条/4 天全部落在**未登记为占位符的形态**上——行数锚（`ace8d4e`）、HTML 内计数（`2191290`）、散文"N 器"（B2 现查未修）。设计文档自定的验收判据"账本文件退出 fix Top10"**未达成**（`CHANGELOG.md` 第 3、`docs/map/cli.md` 第 2、`gates.md` 第 5）。

**覆盖事件**：C1、C3、C4、B2、`1a17306`（计数值域）、`17ffaad`（D201 残留收口）。

**机制落点**：`scripts/ledger_snapshot.py:26` `TOKEN_RE = 〔数:key=value〕`，`:31` `DEFAULT_PATHS = ("docs/map/index.md", "shared/gates.md")`。`check_ledger_tokens` 只校验"重渲染后占位符字节不变"——**没有占位符的散文数字天然免疫**。`b0c230d` 删掉的两条正则（「移除后 N/N」「当前 N)」）实测 0 命中多年，正是上一代"覆盖不全"的化石。

**为什么不是"沟通不足"**：机器认 key 不认写法，这是对的设计；错在**只把"作者记得加占位符"的部分纳入了判定**。凡是作者忘了加占位符的地方，机制反而更安全（不会被判红）。

### R2｜结构变更的"读取方清单"靠人记，门的检查面由被改的那一侧定义

**可证伪表述**：任何改变数据布局/枚举值的变更，若不在同一提交里改完所有消费者，必产生一次"门全绿但读取方静默失效"；且该失效不会被门发现，只会被重新盘点的人发现。

**覆盖事件**：B1（归档布局：3 个消费者 + 4 组测试）、B2（校验器 12→13）、A1（判据⑧扫根 `skills/`，而装配副本不带该目录）、历史 E1 退役漏四处（`shared/global-rules.md` §11 自述）。

**机制落点**：
- `tests/test_canonical_consistency.py` 的"校验器清单集合对账"只对账**校验器文件 ↔ VALIDATORS**，不对账**文档散文里的数字**。
- 没有反向依赖/消费者清单。`f2b3b45` 的"反向依赖棘轮"只守 `_support → validators` 的方向，不守"哪些代码读了 `.atlas/tasks/archive`"。
- `shared/global-rules.md` §11 的退役三件套列了**七类面**（状态标签/输入链/门/校验器/模板/装配项/规则），**不含"读取方（glob / 路径常量）"**——B1 恰好漏在这一类。

**为什么不是"沟通不足"**：B1 的实现者不是不知道有消费者，而是**消费者清单没有机器可枚举的载体**。`archive/*/*` 这种固定深度假设散落在 3 个文件里，没有任何一处声明"这是布局契约"。

### R3｜判定逻辑写成"看起来对"的近似实现，且验收样本由实现者自己定义

**可证伪表述**：凡"新增/修改判据"的测试与实现同一提交、且夹具形状由实现者假设决定，该判据在真实数据上至少出现一次误判或漏判；纠正一定来自独立复核，不会来自门。

**覆盖事件**：A2（3 次改写）、A3（4 轮 21 条）、A5（semver 预发布边界）、`afacccb`（`prd_schema_gate_unarmed` 的补丁第一次赋值是空操作 ⇒ 打不中也绿）、`2d46d4f`（append-only 只校验现状）、B1。

**机制落点**：
- 变异钉只验"注入坏输入必红"的**单向**。`0eac771` 自认："反向的幽灵钉（门册登记但代码没有，如曾经 M20–M24）机器分不清历史与现实，仍归人。" M20–M24 曾长期作为"已实现"登记在门册右列，实际代码里不存在（`b0c230d`）。
- 没有"判据必须附真实仓样本"的强制项。`shared/independent-review.md` 有评审流程，但没有"判据类 finding 必须给样本路径 + 反例"的字段。

**为什么不是"沟通不足"**：这是**采样偏差**，不是沟通问题。实现者只能按见过的数据写判据；仓库没有把"见过的数据"沉淀成可复用夹具。

### R4｜验证在"点"上很强，在"批"上缺失，且点上的验证可被排除/降级

**可证伪表述**：只要某类测试不在发版默认集合里（被 `--deselect`、被 skipif、被环境旁路、被排除出该批次），它引入的契约漂移必然晚一个批次才被发现。

**覆盖事件**：D3（beta.35 发版排除 playground ⇒ D194 落点变更迟到一批才咬出）、D1（孤跑绿/全量红）、D2（本地绿/发版门红）、A1（装配副本态没有对应用例）、以及修复前的 CI 只跑 2 个测试文件（`2026-11-17` 审计 F2；11-17 已改走 `preflight.py`）。

**机制落点**：
- `scripts/release.py:307` 之前只有"canonical + 全量 pytest"一个强制点；`scripts/preflight.py`（11-17 新增）是补的批次入口，但 `LEDGER_PREFIXES = ("shared/", "docs/map/")` **不含 `docs/guide/`**，所以 C3（guide changelog）在 preflight 里仍然无覆盖。
- 没有任何地方登记"本批跳过了什么"。

**为什么不是"测试不够"**：测试很多（1,750 项），问题是**哪些测试在这一次真的跑了**没有记录。跳过是静默的。

### R5｜发版是高频手工步骤集合，发版提交成为杂项改动的合法载体

**可证伪表述**：若某次发版提交包含"7 个版本落点"之外的代码文件，则该次发版的 bisect 与单点回滚能力已失效。

**覆盖事件**：G1（`787dd42` 夹带 `install.py` + golden 重录）、G2（71% 发版紧跟清障提交）、`fba49ec` 前史（beta.8 卷入并行在途）。

**机制落点**：`scripts/release.py` 的 `sync_version_files` 只写 7 个落点（package.json / README / vitepress / docs/map×2 / CHANGELOG / guide changelog），但**不校验"除这 7 个之外没有别的改动"**。10-25 加的"杂改动拒发守卫"只挡未跟踪/脏树，挡不住**已提交**的无关改动。

**为什么不是"流程不严"**：恰恰是流程太密（17 次/15 天），每次发版都要跑全量，于是"顺手把改动塞进发版提交"成了省一次全量跑的理性选择。

### R6｜多会话共享固定名资源，边界只有口头纪律

**可证伪表述**：只要两个会话同时使用固定名资源（`/tmp/atlas-e2e/playground`、同一工作树、同一 `docs/map`），至少一次会读到陈旧或半成品状态。

**覆盖事件**：F1（#66 证据目录互串）、F2（分析中行号被并行提交作废）。

**机制落点**：`QUEUE.md` 机器状态行"并行会话件不代清"是唯一约定；`scripts/atlas_workflow.py` 的 run/evidence 落点没有会话后缀。

**为什么不是"协调不够"**：两个会话彼此不可见，口头纪律无法执行。必须靠**资源命名**而不是**沟通**。

## 4. 二阶 / 长期层：三个月内会以什么形态再出现

| 根因 | 三个月后的形态（推测，附依据） | 可观察的预警信号 |
|---|---|---|
| R1 | 占位符与散文混写，读者不知道信哪个；每次结构变更（新增校验器/新目录）都伴随 1–2 条"同步 N 器/N 行"提交 | `git log --since=<d> --pretty=%s \| grep -cE '同步\|回正\|刷新\|补齐'` 的日频 > 0.5；`docs/map/*.md` 中出现 `数字 + 器/行/个` 且该行无 `〔数:` |
| R2 | 下一次改 `.atlas/tasks` 布局、报告落点或 E2E 索引结构时，再出现一次"归档/迁移即免检"；且**先在采纳仓发生**，再回头补 | 新代码里出现固定深度 glob（`archive/*/*`、`*/runs/*/*`）；`validate_*` 与 `_support/*` 对同一路径的 glob 深度不一致 |
| R3 | 0.4 的认证封条 / v2 清单在真实采纳仓上误判 → 加豁免开关 → 豁免长期化（已有 `--allow-dangling-acs` 先例，`bugs.md` 明确记"宽限被长期依赖"为升室判据） | 新判据的测试文件与实现同提交且无 `REVIEW-` 引用；`BUGS`/`QUEUE` 中出现"宽限/豁免/兼容开关"新增 |
| R4 | 下一次大重构（167 文件级）再次"交接即完工"，次日返工；且被排除的那批测试的问题会在**下一个 tag**才爆 | 交接文档出现"全部通过/具备条件"而 `git log` 中该批无独立复核提交；`pytest -q` 输出中 skipped 数上升 |
| R5 | 一次真实线上问题需要回滚，发现发版提交含 20 个文件、无法单独回退 | `git show --stat <release>` 出现 7 个落点之外的文件 |
| R6 | 一次真实缺陷的失败证据被另一个会话的 `playwright test` 起动清空（D148 已观察"留存窗口=到下一次起跑"，尚未造成损失） | `/tmp/atlas-e2e/` 下出现同名目录被两个进程写；`.atlas-evidence/` 中 manifest 时间与失败时间不匹配 |

**一条整体判断**：R1、R2、R3 是**同一个东西的三个面**——"把可以算/可以枚举的事实，留在人的记忆里"。11-17 的单一源批解决了"数字"这一面，没解决"读取方"和"真实样本"这两面。所以返工率降了一半，剩下的一半会以更难察觉的形态（静默出域、误判后加豁免）继续。

## 5. 预防层：每条根因配一个动作

> 排序 = 成本低 × 能挡掉的重复多。三类之一：项目规则 / 自动化 / Skill·流程。**每条都写失效条件**——什么情况下它会变成新的形式主义。

### P1（对应 R1）｜给"裸数字"加一条 lint，并让 guide changelog 变成镜像

- **自动化**：`scripts/ledger_snapshot.py` 增 `--lint-bare-numbers`：扫 `docs/map/*.md`、`README.md`、`shared/gates.md`，命中 `\d+\s*(器|个校验器|个测试文件|行)` 且该处无 `〔数:` 占位 ⇒ exit 1。挂到 `scripts/preflight.py` 的 `LEDGER_TESTS` 窄集（改这些文件时必跑）。
- **规则**：`docs/guide/changelog.md` 从"手写第二份"改为"`release.py` 从根 `CHANGELOG.md` 生成的镜像"，`7831b68` 的"权威收敛"才算落地。
- **成本**：低（半天，不动判据本体）。**能挡掉的重复**：全区间 C 类 31 条里约 12 条。
- **失效条件**：一旦为"历史快照"语境开**按文件**的豁免（"changelog 不查"），豁免会蔓延到其他文件；必须只允许**按行 + 锚**逐条登记，且每条带理由。第二个失效点：`\d+ 行` 会把"代码示例里的行号"误伤 → 必须限制在受管区块内。

### P2（对应 R5）｜发版提交白名单化

- **自动化**：`scripts/release.py` 在 `run_test_suite()` 之前增加一步：`git diff --name-only <last_tag>..HEAD` 必须 ⊆ 7 个版本落点 ∪ 本次显式 `--allow-file`；否则 exit 1，提示"先单独提交"。
- **成本**：低（1 小时）。**能挡掉的重复**：G1 类（本区间 1 次，但每次代价是整版回滚能力）。
- **失效条件**：如果加 `--force` 逃生，它会被常态化使用。逃生必须写进 CHANGELOG 并在下一次复盘点名；否则等于没做。

### P3（对应 R3）｜判据类改动强制"外部样本 + 反向变异钉"

- **自动化**：`tests/test_canonical_consistency.py` 增加**反向**集合比对：门册右列声明了 `M<id>` 但 `tests/` 里找不到对应 docstring ⇒ FAIL。补上 `0eac771` 自认缺失的那一向。
- **Skill/流程**：`shared/independent-review.md` 的"判据类 finding"模板增加两个必填字段：`样本路径@commit`（必须来自真实仓/既有归档，不得由实现者现造）与 `应判不中的反例`。没有这两项，review 不得给 PASS。
- **成本**：低（反向钉约 2 小时）+ 中（review 模板改动需要一次宣贯）。**能挡掉的重复**：A2/A3/A5 类约 15 条中的大部分"第二次返工"。
- **失效条件**：样本由实现者自己挑（挑一个正好能过的）——所以必须要求样本路径带 commit hash 且 reviewer 能独立复跑。若 reviewer 变成"只读 diff 不看样本"，这条立刻退化为形式。

### P4（对应 R4）｜把"本批跳过了什么"变成可见输出

- **自动化**：`preflight.py` 输出段固定加一行"本轮未运行（含 skip/排除/无覆盖）的测试文件与原因"，并在 `docs/guide/changelog.md` 镜像化后把 `docs/guide/` 加入 `LEDGER_PREFIXES`。
- **规则**：`shared/gates.md` 每行的「不查什么」列，凡因**批次排除**（而非设计盲区）不跑的，必须同时写"补偿批次"（如 D194 的"下一批必须咬合"）。
- **成本**：低–中（半天）。**能挡掉的重复**：D1/D2/D3 类 4–5 条。
- **失效条件**：如果"未运行"清单变成每次都一样的长列表，就会被无视。必须只列**与本次改动相关**的未运行项，其余归总为一个数字。

### P5（对应 R2）｜给结构布局建"读取方"反向查找

- **自动化**：`_support/layout.py` 增加布局常量（`TASKS_ARCHIVE_DIR`、`TASKS_ARCHIVE_PATTERN`）；`tests/test_layout.py` 增加反向扫描：全仓出现 `glob(".*archive.*")` / 硬编码 `.atlas/tasks/archive` 且不引用常量的位置 ⇒ FAIL。配一条变异（在消费者里写回字面量 ⇒ 必红）。
- **规则**：`shared/global-rules.md` §11 退役三件套的**七类面**增加第八类「读取方（glob / 路径常量 / 固定深度假设）」，并规定"迁移提交必须附 `grep -rn <旧布局>` 的结果"。
- **成本**：中（1–2 天，含变异）。**能挡掉的重复**：B1/B2/A1 类 3 条，但**单条代价最高**（静默出域）。
- **失效条件**：如果反向扫描按 import 名匹配，消费者可以绕开常量直接拼路径而不红——必须扫"路径字面量 + glob 深度"两个信号，并用变异证明能咬住。

### P6（对应 R6）｜会话命名空间

- **Skill/流程**：`atlas workflow run/verify` 的 run/evidence 落点自动追加会话标识（进程 pid 或 `--session` 派生），默认值不得是固定名；工作树层面维持"一树一会话"，提交一律 `git add <精确文件名>`（用户既有纪律）。
- **成本**：低（2 小时，`#66` 的 `_runtime_dirs` 已有雏形）。**能挡掉的重复**：F1/F2 类 2 条（低频，但一旦发生会毁掉失败证据）。
- **失效条件**：若会话标识靠人手填，会退化成"永远填同一个值"。必须由进程自动派生且写进日志头。

### 5.1 排序与理由

| 序 | 动作 | 成本 | 挡掉的重复（本区间） | 为什么排这个位置 |
|---|---|---|---|---|
| 1 | P1 裸数字 lint + guide 镜像 | 低 | 12 | 频次最高（C 类占账本提交 3/4） |
| 2 | P2 发版白名单 | 低 | 1–2 | 成本几乎为零，但保住回滚能力 |
| 3 | P3 反向钉 + 样本字段 | 低+中 | 8–10 | 直接砍掉"A 批→B 批→C 批"的第二、三轮 |
| 4 | P4 跳过可见化 | 低–中 | 4 | 与 P3 互补：一个管"判据对不对"，一个管"有没有跑" |
| 5 | P5 读取方反向查找 | 中 | 3 | 频次低但单次代价最高，值得单独做 |
| 6 | P6 会话命名空间 | 低 | 2 | 优先级最低；但若不做，"证据被清空"的损失不可逆 |

**如果只做两件**：P1 + P2。两条都是"零判据变更、纯机械"，当天可落，且立刻能把发版前的清障提交压掉一大半。
**如果只做一件**：P3 的反向钉（半向 → 双向）。它不解决频次，但解决"门声称守住了、其实没实现"这类最贵的假绿（M20–M24 那种）。
