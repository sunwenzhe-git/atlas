# atlas e2e — 验收用例环

> 本环为 atlas 独立 skill `atlas-e2e` 的执行契约，位于 `.atlas/rings/e2e/reference.md`。
> 执行前先读共享契约：`.atlas/shared/global-rules.md`、`stack-profile.md`、`single-source.md`、`layout.md`。
> 路径约定：本文 `product/` 均为**默认资产根**示例；实际按项目根 `atlas.config.yaml` 的 `layout.assets_root` 解析（见 `shared/layout.md` §1.1）。

## 0. 一句话

读**域级 PRD 的 AC**（业务预期）与**用例分片的 `testid:` 应然清单**（交互与锚点），产出「**页面分片 + 总索引**」的 E2E 用例资产；testid **应然（分片）⇔ 实然（前端源码）**按页双向集合校验；用例定稿后从分片生成 **E2E 脚本**，在**真实应用单段**（`e2e.app_base_url`）上执行，结果回写索引状态。

- **用例真相源** = `product/e2e/e2e-index.md`（唯一入口）+ `product/e2e/cases/<page>.md`（分片）。
- **testid：应然源 = 用例分片，实然 = 前端源码**（E1，2026-09-28，`3508 §92`）——分片隐式决定元素清单与初始态，前端 `data-testid` 扫描是实然，执行即对账（§4）。
- 本环**只产用例资产与 E2E 脚本**；不产 PRD、结构事实、业务代码。

## 3. 组织形态：页面分片 + 总索引

```
product/e2e/
├── e2e-index.md        总索引（唯一入口，严格表格）
├── cases/<page>.md     页面分片（`atlas-case` 块）
└── scripts/<page>.<ext>  E2E 脚本（由分片派生，见 §7）
```

> **模板**（骨架）：`.atlas/templates/e2e/`（`e2e-index.md` 主表+反向视图 / `case-shard.md` 分片）。

**三条硬规则（不可协商）**：

1. **总索引是唯一入口且机器可校验**：ID 全站唯一、每个 ID 都有可达分片链接、分片里没有索引外的孤儿用例。
2. **每条用例只存在于一个分片**：归到它的**断言落点页**；跨页流程在用例内记 `pages[]` 全链路，**绝不复制**。
3. **分片键只认页面**，不允许"临时归到别处"。

### 3.1 「页面」的唯一来源

- `page` = 分片文件名（去扩展名），即 `slug`；**slug 规则正文自原型环迁入本环（E1，2026-09-28）**：全小写、连字符分词、静态路由 = `/` + slug、带参路由取**业务段**（如 `/projects` 而非 `/projects/:id`）、根页 slug 惯例 `home` 但路由为 `/`。**「页 ↔ 真实路由」映射的唯一真相源 = 索引页面表（§3.2）**。
- **断言落点页**：`page` = 该用例断言所观测元素所在的页；跨页时其余页记入 `pages[]`。

### 3.2 索引：主表 + 反向视图

`e2e-index.md` 含三张表。**页面表**（E1 起，页 ↔ 路由 ↔ **实现状态**的唯一真相源，生成器 URL 的唯一来源）列（顺序固定）：

| 页面 | 路由 | 域 | 实现状态 |
|---|---|---|---|

（`页面` = slug；`路由` **以 `/` 开头**且全表唯一，**可含 hash 段**（如 `/console/#/app/agent/detail`——hash 路由应用的壳前缀与 `#` 都属**路径形态**；`#` 必须紧邻 `/`，否则会被 `.atlas-case` 的行内注释语义吞掉，见 §5.5）；**宿主注入的 query（如 tenant）不进 `路由`**，由 `e2e.app_base_url` 承载（见 §5.5「宿主注入型 base query 的转发」）；`域` = 域级 PRD 的域 slug；`实现状态` ∈ `已实现` / `实现中` / `未开始`。主表引用的每个 `页面` 必须在页面表里。）

**`实现状态` 的判据（E1，`3509 §B106`）**：testid 门（§8.1）对**页**做应然↔实然对账，而实现粒度是**页内特性** —— 「前端有该页任意 testid」不足以判定「已实现」（壳层 testid 会让一个尚未实现的页被严判）。故：

- `已实现`：页面表与用例分片的 testid 集合**双向相等**，多 / 少即 **FAIL**；
- `实现中` / `未开始`：同形缺口降 **WARN** 并附逐页清单（实现落地并经复核后改回 `已实现`）；
- **缺状态列 ⇒ 按 `已实现` 严判**（不得因缺列而静默放宽）；**词表外取值 ⇒ FAIL**（防拼写错误把严判静默降为 WARN）；
- 与实然矛盾的状态（`未开始` 却有该页 testid / `已实现` 却无）记 **WARN**；
- 页 slug 词表同样以本表为准，**不再从 testid 首段推断**（表外前缀归「未归属」WARN）。

主表列（顺序固定）：

| 用例ID | 页面 | 中文标题 | 类型 | 关联AC | 需求 | 状态 | 状态原因 | 分片 |
|---|---|---|---|---|---|---|---|---|

- `分片` = 相对链接 `cases/<page>.md#<id 小写>`（如 `cases/config.md#e2e-config-004`）；分片内以 `## <ID>` 开头的标题为锚点依据（校验器按**标题前导匹配**判定，不依赖渲染器的 slug 算法）。
- `状态原因`：仅 `blocked` / `skipped` 时非空。
- 反向视图（紧接主表的小节，标题固定为 `## 页面 ↔ 用例`）：

| 页面 | 断言落点用例 | 链路经过用例 |
|---|---|---|

- 「断言落点用例」= 主表 `页面` 等于该页的 ID 集合；「链路经过用例」= 主表其他用例中 `pages[]` 含该页的 ID 集合。
- 反向视图**由 agent 维护**，但必须与「主表 + 分片」推导出的集合一致（§8 校验）。
- **不设「AC ↔ 用例」手工表**：AC 反向覆盖是**派生量**（真相源 = 主表 `关联AC` 列 + 域级 PRD §五 AC 定义行），由 `validate_e2e_index.py` 现场计算并报缺口（§8.2 追溯门）——多一张手工表就是多一处漂移面（`shared/single-source.md` §4）。

## 4. testid 规范（唯一硬锚）

- **唯一硬锚**：所有**必要元素**必须带 `data-testid`；生成的脚本一律以 testid 定位，**不使用语义 / 样式 / 位置选择器**。
- **必要元素** = 所有可交互元素（按钮 / 输入 / 链接）+ E2E 需断言的展示元素；其余不打。
- **逐行渲染的元素不打 testid**（2026-09-27 补，`3509 §B89`）：**列表行 / 表格行**这类按数据逐行生成的元素**不是**必要元素 —— 它们无法在真实 UI 上取到**逐行互异且稳定**的名字（名字随数据变），又与「全站唯一」天然冲突（一条列表渲染 N 行 ⇒ 同一名字出现 N 次）。需要断言列表内容时，用**容器 + 计数**（对容器断 `count`，或另设一个计数摘要元素）或**稳定样例行**（固定的一两行），**不用**逐行 testid。
- **命名**：`<页面slug>-<元素语义名>[-<变体>]`，如 `config-llm-add-btn`、`prompt-list-item`。
  - 页面段 = 该元素所在页的 slug；
  - 元素段必须**语义名**，**禁止样式名 / 位置名 / 序号名**；
  - 全站唯一、不复用；重命名必须同步全部引用。
- **共享元素取名策略：一零件一名（2026-10-16 落，issue #19 裁定）**：同一个**共享组件**在多个页面 / 多个语境上渲染的同一语义元素，**只取一个 testid**；其页面段 = **归属页**（该元素承载其用例的那个页，即双向校验里的 `tid_owner`），**不随渲染页变化**。
  - 因此「同一 testid 在多个页面渲染」是**合法**的：唯一性判据是**声明处计数**（源码里字面量/可枚举值出现几处），**不是渲染点计数**——渲染 N 次不等于声明 N 处。
  - 于是本环**不采用**「按当前页 slug 派生前缀」的模板机制作为共享元素的默认形态；`${slug}` 模板仍合法（共享外壳确实按页派生前缀时用），但**不是**跨页同元素的推荐解——推荐解 = 一零件一名 + 下文「常驻槽位口径」。
  - 后果（知悉项）：在非归属页上该元素顶着归属页的 slug，这是策略的选择而非缺陷；非归属页若需自己的观测面，应另立语义元素而非复制 testid。
- **双向集合校验语义**（`validate_testids.py`）：
  - **抽取源 = 前端源码**（E1 统一，不再按 `origin` 分流——原型的代理职责随环退役）：`apps[].kind ∈ {frontend, fullstack}` 的路径下的 `data-testid`。
  - **测试面与夹具不是声明处（issue #27/#33，2026-10-19 补）**：`__tests__`、`test`、`tests`、`__mocks__`、`__snapshots__`、`e2e`、`fixtures` 目录与 `*.test.*`、`*.spec.*`、`*.cy.*`、`*.stories.*` 文件**不入抽取源**——测试断言里的 `querySelector('[data-testid=x]')` 是页面元素的回声，计进「声明处计数」会把「真实元素 + 自身测试里的同名字符串」判成全站重复假红。
  - 按页比对「抽取源上的 testid 集合」⇔「该页分片引用的 testid 集合」；
  - 某页**有分片** → 两集合必须**相等**（多一个或少一个都 FAIL）；
  - **未实现的页**（前端扫描无该页 slug 前缀的任何 testid）⇒ **SKIP**（记「未实现页」清单，不算失败）——检查点搭便车于必然存在的工件（`3508 §94` 推论③）：页实现落地之日即对账之时；前端扫描到 0 个 `data-testid` ⇒ 全部 SKIP + WARN。
- **apply 刚结束时的预期态（`3509 §B88` 的 SKIP 化，E1）**：`apply` 跑在实现之前且不写业务代码 ⇒ 新定 testid 的页在实现前是「未实现的页」⇒ 按 SKIP 吸收（不再是红）；**实现落地后必须绿**（判据：该页双向差集为空）。本条款不降低门强度——已实现页的红是真红。
- **存量项目「该页零 testid」的推进链（issue #28，2026-10-19 补）**：testid 门把「前端该页零 `data-testid`」判为未实现页并 SKIP，于是分片可以合法落笔、门也放行，但生成物一律以 testid 定位 ⇒ **真跑必然定位不到元素**。推进责任方与机读完成判据写死三步链：
  1. **分片落笔**（写 `testid:` 应然清单 + `落点:`；门按未实现页 SKIP）—— 责任方 = 需求承接方；索引主表将对应未埋点用例置为 **`blocked`**（原因声明 `推进中：前端零 data-testid`），运行器原生发射 `test.skip(reason)` 隔离待办态，**不得与用例真失败同面**；
  2. **派生薄桩 + 实现侧补齐**（`gen_testid_stub.py` 出 `.trellis/spec/conventions/testid.md`；实现侧按应然清单补 `data-testid`）—— 责任方 = 实现侧；
  3. **复跑真跑** —— 责任方 = 收口方。
  **推进完成的机读锚 = 该页双向差集为空**（`validate_testids` 该页既无「缺失」也无「多余」）。

- **抽取器接受的声明形态（2026-10-16 补，issue #19）**：下列形态均视同**该处声明一次**，同档参与「声明处计数」与双向集合两侧判罚：
  1. **静态字面量**：`data-testid="a-b-c"`；
  2. **同文件静态字符串常量 + 单层引用**：`const X = 'a-b-c'` … `data-testid={X}`（值单跳且同文件可解析 ⇒ 仍属静态可枚举；**跨文件导入不解析**——无模块图，宁缺不猜，共享常量请把字面量落在使用点文件内的常量或占位分支）；
  3. **可枚举模板字面量**：`data-testid={`${slug}-x`}`（`${slug}` 的词表 = 索引页面表；展开值**只参与「缺失」判罚，不参与「多余」判罚**——外壳挂载范围静态未知，见上「共享元素取名策略」）；
  4. **命令式注入**：`el.dataset.testid = "a-b-c"` / `el.setAttribute("data-testid", "a-b-c")`（含模板形态，同上）。
  非上述形态（函数调用、三元、字符串拼接、未在本文件声明的标识符）**不解析 ⇒ 报缺失**（宁缺不猜）。
- **常驻槽位口径（实现侧合法形态，2026-10-05 落，voice-library / project-management 两域沉淀；**2026-10-19 起非必需**，`DESIGN` D114 / issue #26）**：分片声明的每个 testid 在前端源码须为**恰一处静态字面**（全站唯一 = 字面计数；组件 prop 传值对抽取不可见——请把 prop 的**值**落在上述任一可解析形态上，典型 = 占位分支里的字面量）。**动作产物元素**（上传卡 / 导入结果 / 弹窗行等由操作产生的元素）**默认不再需要 hidden 占位槽** —— 守卫按 §7.1 拆两段后，这类元素的在场性由**触碰它的 step / 断言**自身的自动等待承接（D114）；占位槽保留为**可选形态**（存量项目可继续使用、不强制回退；其 `count` 期望里「真实数 + 1」的口径亦随之保留）。若采用占位槽：真实元素经 props 挂同名值、字面只出现在占位分支，且**占位槽必须位于动作目标之后**（生成脚本的动作与断言一律取 `.first()` —— 放在前面会让动作命中隐藏元素，而该错位**当前无校验器可判**，须人工保证）。**占位槽的可交互态应取「与用例断言期望相反」的态**（断言为 `disabled` 的入口用未禁用占位、断言为 `enabled` 的用已禁用占位）：这样守卫仍命中，而真实元素缺席时断言照样红——不得以占位元素充当断言证据（假绿通道，`shared/independent-review.md` §2 第 3 条）。**模态容器**的 testid 可落在模态内可见标题元素（子元素可见 ⟺ 遮罩打开，断言真值等价）。**占位空值控件**（如下拉）不得以空串作初值参与 `value` 断言语料（初始态成立 = 基线恒真），用哨兵值占位。

### 4.1 实现期薄桩（Trellis 注入）

- 落点：`<项目根>/.trellis/spec/conventions/testid.md`，带**块列表** `paths:`（= 该产品 `kind: frontend|fullstack` 的 app 路径 globs），供 Trellis 原生注入到实现任务。
- **生产者（2026-09-26 补，`3509 §B73`）**：`scripts/gen_testid_stub.py --root <项目根>`。它是**确定性派生**：源 = 与 `validate_testids` 同一个**抽取源**（§4），输出稳定，可重复重生成。**它不存在 ⇒ `validate_testids` 就地自动补齐并记 `PASS`**（F32 机器兜底，2026-10-15：缺失的派生工件由就近工具补齐，同 R6 基线报告哲学；否则它就是一条「契约要求、无人产出」的空头登记）；`FAIL` 只留给**生成不了**的真错（生成器定位不到 / render 抛错）。
- 内容（**派生视图，非正文**）：
  1. 一条祈使句（E1 统一）：**实现按分片应然清单命名 `data-testid`，不得自造；既有实现保持现有 `data-testid`**。
  2. 指向正文的指针：`.atlas/rings/e2e/reference.md` §4；
  3. **两块清单**（E1）：① **分片应然**（按页，`product/e2e/cases/*.md` 的 `testid:`）——实现者的命名依据；② **前端实然**（按页扫描 `data-testid`）——现状。两块差集 = 待实现面 / 漂移面。
- 正文唯一在**本契约**（`single-source.md` §1）；薄桩不得复制命名规则词表。

**面板容器标记（硬，2026-09-28 补，`3509 §B111`/`§95` 的失义清单实例）**：前端里**Tab 级面板**的容器必须标 `data-atlas-panel`，而**由动作展开的内容面板不得标**。

- **为何归本环**：原宿主原型环随 E1 退役，消费者自始至终是本环运行期门（§5.6 R9 两趟取样靠它判断「哪些面板该展开」）⇒ 归位本环（实现期义务，落点 = 上面的薄桩清单 + 本节）。
- **判据**：漏标 ⇒ 面板内 `hidden` 类断言未展开时恒真 ⇒ 误报（`3509 §B72`）。

### 5.3 ID

`E2E-<PAGE>-NNN`：`PAGE` = 页面 slug 的**大写**；`NNN` 每页从 `001` 起、三位定长、**删除后不复用**；全站唯一由 `PAGE` 段保证。

**`PAGE` 的推导（对单段与多段 slug 同一条规则）**：对 slug **只做大小写变换，不做分段变换** —— `PAGE` 即 slug 的**大写原文**，连字符原样保留。

| slug（§3.2 形态） | `PAGE` | 用例 ID 例 |
|---|---|---|
| 单段 `config` | `CONFIG` | `E2E-CONFIG-004` |
| 多段 `prompt-management` | `PROMPT-MANAGEMENT` | `E2E-PROMPT-MANAGEMENT-007` |

**本条不做收敛、不设「slug → PAGE」映射表**：多段 slug 是 §3.2 允许的正常形态，故 `PAGE` 段与 slug 互为双向可推（`PAGE` 转小写即 slug）；全站唯一由页面表内 slug 唯一保证（slug 真相源见 §3.2）。

机器可读形态 = `E2E-[A-Z0-9]+(?:-[A-Z0-9]+)*-\d{3}`；唯一实现见 `_support/case_id.py`（各消费者按各自锚点取用，锚点不共享）。

### 5.4 单段执行与通过标准（E1）

**靶场唯一** = 真实应用（`e2e.app_base_url`）：真前端 + 真后端（后端 API 可先返受控假数据，但**不得**在前端代码里塞 mock 层）。地址的唯一来源见 §7。

- **通过标准（无条件，对每条用例都成立）**：在真实应用上通过（全量）；`green` 即终态。
- **登录态（硬）**（`3509 §B99`）：真实应用有访问门 ⇒ 运行**必须预置真实会话**——由生成器写入的运行器原生配置以**真实登录**换取令牌（§7.1）。凭据只来自运行期环境变量（不读项目 `.env`、不硬编码）；未设置 ⇒ 跳过预置并**明确警告**（不静默）；换取失败（网络 / 凭据 / 端点变更）⇒ **报错中止**——静默续跑 = 「未登录态跑用例」的假绿。需要「未登录」前提的用例：块内声明 **`auth: none`**（2026-09-30 补，机制化——生成器给用例挂 `atlas_auth_none` marker，conftest 的 page fixture 剥预置 `storage_state`（兼容 `storageState` 双键）给干净 context）；存量以页内退出控件制造未登录态的写法（如 login 分片的 `login-logout-btn`）仍合法。`auth` 取值白名单外 ⇒ 文本期门 FAIL + 生成器**中止**（不猜、不静默降级）。
- **执行**：`baseURL` 即 `e2e.app_base_url`——无目标切换（`--target` 已随 E1 退役，见 §10）。
- **状态机（纪元制）**：E1（2026-09-28，原型环移除）起 `red → green`；旁支 `blocked` / `skipped` 必带原因。`prototype-pass` 为 **E0 历史终态**：存量合法保留、索引词表仍收，但**不再产生**（回写只产生 `red` / `green` / `blocked` / `skipped`）。
- **首跑分类协议（E1）**：原型退役后唯一真相时刻 = 首次全真栈执行；存量 `prototype-pass` 用例首跑可能**结构性红**（mock 语义残留）。首跑红三分类，**不分类不得批量回写状态**：① **mock 语义残留**（断言依赖原型 mock 层自证的行为 / 数据）⇒ **改用例**——按域级 PRD 的 AC 重写断言取材（挂 `关联AC`），不得把 mock 行为搬进实现；② **命名漂移**（元素已实现但 testid ≠ 分片应然）⇒ **改实现对齐**分片应然清单（§4.1 薄桩），改分片须用户确认并全链同步；③ **真缺陷** ⇒ 走 Trellis 需求级（建卡修复），不动应然资产。分类结论逐条落 `product/e2e/reviews/<日期>-first-run/`。
- **域收口人侧门（2026-09-29，`3507 AQ` = B124 结论；同日全局审查 G3–G5 修）**：`green` 是**机器侧**终态；域收口还差**人侧**一道——该域 E2E 在真实应用全 green 后，用户按域级 PRD 功能清单逐条在真实应用上过一遍。**符合性对照物**：该域 PRD 有已确认「用户旅程走查」节 ⇒ 对照走查单；无走查节（不改 UI 的需求 / 存量未补）⇒ 对照六件套本身（走查节本就是它的投影，`rings/prd/reference.md` §4·八）。**逐项三值判定**（吸收设计决策评审 U3 独立结论）：① 符合；② 不符但预期未变 ⇒ 实现侧 issue 回 Trellis 修，修后只复走受影响项；③ 预期本身变 ⇒ 改 PRD 并同步用例（正常发现，非失败）。**②③ 清零才算过**。**留痕（硬）**：结论落 `product/e2e/reviews/<日期>-acceptance-<域>/README.md`（逐项判定 + 三值去向），只在对话里说过 = 门没跑；README 还须含一行**「手工项：N 项 / 已评估：0 / 待评估」**（评估口径 = §10 执行纪律 5；「未评估」= 本域从未盘点过手工面——「没有」与「忘了」由此区分，`RFC-20261015-01`）。**blocked 语义**：真实应用不可用 ⇒ 与 E2E 同为 `blocked` 显式带原因，**域标「待验收」、不判收口**，真栈就绪后补走查（不许替身数据充数）。

### 5.5 分片内用例块格式

每条用例 = 一个 `## <ID> <中文标题>` 小节 + 紧随的 ` ```atlas-case ` 围栏块（行式键值，stdlib 可逐行解析；fence 标签**刻意非 `yaml`**）。

````markdown
## E2E-CONFIG-004 在 LLM 配置页新增一条配置并保存

```atlas-case
id: E2E-CONFIG-004
intent: 新增一条 LLM 配置后，该配置在保存并被刷新页面后依然存在，证明写入已持久化
pages:
  - config
precondition:
  - 已进入 LLM 配置页
  - mock 数据：本用例自行构造，列表初始为空（不依赖其它用例）
step:
  - click config-llm-add-btn                 # 点击「新增」
  - fill config-llm-name-input 本地 Ollama    # 在名称输入框填入「本地 Ollama」
  - click config-llm-save-btn                # 点击「保存」
  - refresh                                  # 刷新页面
expected:
  - visible config-llm-item                  # 列表出现一行
  - text config-llm-item 本地 Ollama          # 该行文案为「本地 Ollama」
testid:
  - config-llm-add-btn
  - config-llm-name-input
  - config-llm-save-btn
  - config-llm-item
```
````

**`step` / `expected` 行格式（机器可执行，2026-09-23 定）**：

```
<动词> <testid> [<值>]      # 中文说明（可选，给人读；机器忽略 `#` 之后）
```

- 首个 token = **动词**，必须取自下方词表；否则**校验器 FAIL**（`validate_e2e_index.py`）。
- 第二个 token = **`data-testid`**（`refresh` / `goto` 除外，见词表）。
- 其余为**值**（可含空格；是**渲染后可见文案**或数值）。
- `#` 之后是**中文说明**，供人阅读，**机器忽略**。
- **可选步骤锚** `after:<N>`（2026-09-25 补，`3509 §B57`）：写在 `expected` 行行首，表示「这条断言在分片里**第 N 条 `step` 执行完之后**立刻取样」（N 从 1 起、按 `step` 书写顺序编号）。不带锚的 `expected` 仍是**终态**断言。用途：把「先准备、再提交」型用例的**中途态**变成证据（如「先打开覆盖层再取消」里的「打开」；因为终态回到初态、本身无法作为证据）。约束：锚不得与 `initial:` / `unchanged:` 叠写；N 必须是正整数且 ≤ `step` 条数（否则**校验器 FAIL**，该项为「步骤锚合法」）；带锚的断言**不属豁免通道**，必须像无前缀断言一样参与零步基线（即不得在初始态成立）。**发射面（2026-10-23，`DESIGN.md` D136）**：锚按 **step 序号**计数，生成器内部「动作槽位」必须与 step 严格 1:1——一条 step 发射多行语句（如 `refresh` 的先等后刷）时须合并为一个槽位，否则后续 `after:N` 整体前移（实测 `after:9` 落到「打开面板」之前，面板未开必红）。

> **为何中文降为注释**（2026-09-23 定）：`step` / `expected` 必须机器可解析——散文格式下机器只能抽出 testid、抽不出「做什么 / 断言什么」，生成器退化为存在性断言；**不设**「中文 `step` + 结构化 `actions`」两字段（同一信息两处正文 = 漂移，`shared/single-source.md` §2）。语义由 `## <ID> <标题>` + `intent` + 注释承载。

| | `delta` | **数值增量**（相对断言，2026-10-07 补，`issues` P5）：值段 = 带符号整数 `±N`。语义 = 行动前采样该元素文本中的**首个整数**、行动后复读，两者差值必须恰为 `±N`。真栈单 run 累加态下「待生成 +1」类断言的合法形态 —— 绝对值断言（`text X 待生成 3 条`）在同前提的兄弟用例上只可能首跑者成立。渲染为**轮询断言**（node `expect.poll` / python 行动后复读）；采样点 = **第一个提交性动作之前**（与 `unchanged:` 先例同点，准备步骤不污染基准）。**不得**与 `initial:` / `unchanged:` / `after:` 叠写、用例必须有 `step`（均 ⇒ 校验器 FAIL，生成器中止双保险）；**不参与零步基线**（它没有「初始态成立 / 不成立」语义）。首例 = `E2E-PROJECTS-014`（拆分后项目级待生成递增，2026-10-07 转正） |
| | `request` | **请求载荷断言**（2026-10-23，`DESIGN.md` D142）：`request <api> <json-path> <expected>`。`<api>` = `?api=` 查询值的**带点唯一后缀**（如 `app.updateApp`）；多个不同 API 命中同名后缀 ⇒ FAIL。`<json-path>` = 点号键 + `[N]` + `[key=value]`（纯遍历、无 eval）；`<expected>` = `(缺席)`（叶子键不存在）/ `null` / `""` / JSON 字面量；**`(空)` 不接受**（无法区分缺失与 null）。**动作锚定**：`after:N` ⇒ 第 N 步执行前记请求序号；无锚 ⇒ 最后一步前记序号；只断言该时点后**新出现**的第一条匹配请求，无新请求 ⇒ FAIL（历史请求/自动保存/重试不得满足断言）。中间路径缺失、过滤 0/多命中、数组越界、请求体解析失败 ⇒ **解析错误**（不得折算成「缺席」）。不得与 `initial:` / `unchanged:` 叠写；必须有 `step`；**不参与零步基线**。含该断言的用例默认 `trace: off`（请求体可能含敏感数据；`ATLAS_REQUEST_TRACE=1` 才保留失败 trace）；失败消息只打印 api/path/期望类型与实际类型，不打印载荷。 |

- **同名多实例元素序位（`[index]`，0 起始，D120 / issue #31）**：当页面存在同名 testid 的多个实例（列表行、表格行、重复项控件等）时，步骤动词与断言动词的目标 testid 均支持以 `[N]` 下标指定操作或断言第 N 项（0 为首项，1 为第二项，依此类推）：
  - 示例：`click list-move-up-btn[1]`、`fill list-name-input[1] 张三`、`visible list-item[2]`、`click list-delete-btn[1] native`；
  - 映射为 Playwright 原生 `.nth(N)` 定位器；省略下标时保持缺省 `.first()` 语义（100% 向后兼容）；
  - 用例侧 `testid:` 声明与 `落点:` 仍按基准 testid 登记（不带 `[N]`），双向集合与落点门自动归一为基准名对账。

- 语法：标量行 `key: value`；数组 = `key:` 后跟若干 `- 项` 行。
- **`落点:`（可选，2026-10-16 补，issue #20）**：应然 id 承载元素的**声明式落点**，行形态 `- <tid> <相对项目根的路径>`（一词一条，可多条）。
  - **为何要它**：应然清单取自 AC 文字，而双向集合门只比「值集合相等」⇒ 一个**永不渲染的死字面量**就能把门凑绿而用例仍红（现场实证：两条应然 id 所描述的控件在该产品里**根本不存在**，分片却按 AC 文字为它们立了 id）。落点把「这条 id 到底落在哪个文件的哪个元素上」变成**可校验的声明**，使「按 AC 文字先立 id、事后才发现无承载元素」这条路在文本期就不通。
  - **校验（`validate_testids.py` 的「应然落点」门）**：每个应然 id 至少登记一个落点，且该路径**文件存在**、其内**可解析到该 id**（口径与全量抽取同源：静态字面量 / 同文件静态常量 + 单层引用 / 可枚举模板 / 命令式注入）。
  - **分档（D88 / issue #34 联动页面实现状态）**：已实现页**声明了但不对**（文件不存在 / 文件内解析不到该 id）= 假陈述 ⇒ **FAIL**；未实现/实现中页落点先行待落地 ⇒ **WARN**（未实现页落点先行待落地，不阻断正向前置设计）；**未登记落点** = 纪律缺口（存量清零过渡）⇒ **WARN**（升 FAIL 触发见 `shared/gates.md`）。
  - 落点指向**声明落点**即可（占位槽分支所在文件也算——字面量就在那里）。
- **`会话:`（可选，2026-10-16 补，issue #13）**：**宿主注入型会话前提**。行形态 `- <键>=<值>`（一词一条）。
  - **为何要它**：有类需求的**被测属性本身就是「会话被宿主以某个注入参数载入 ⇒ 界面呈相应形态」**（身份 / 租户 / 管控 / 灰度类标记）。契约原无此通道：`goto` 带 `?` 即 FAIL（§5.7 / §8.2）、`auth` 只管登录态、`seed:` 绑数据实体 ⇒ 这类用例只能写成 `precondition`（散文，门看不见）而断言在初始态即成立 ⇒ 撞 §5.6 R9 恒真禁制，且两条豁免通道都不适用（`initial:` 只许挂结构类 AC，`unchanged:` 要有提交性动作）。
  - **语义：`会话:` 是前提构造，等同 `step`**。生成器把它编译为**首屏导航前**注册的 `addInitScript`，写入 **`sessionStorage`**（而非 `localStorage`：`storageState` 只覆盖 localStorage，而它跳标签页 / 跳用例持续 ⇒ 会污染后续用例，含「不传参 ⇒ 保持可用」类对照用例）。
  - **与 §5.6 R9 的关系（关键）**：**零步基线不施加 `会话:`**（基线是独立生成的页级测试体，本就不带用例的 `会话:`）⇒ 依赖该前提成立的断言在基线（默认会话）下**不成立**，R9 自动满足，**不必也不得**去借 `initial:`。
  - **取值来源与优先级**：用例声明的值兜底，运行期环境变量 `ATLAS_SESSION_<键规范化>` **优先覆盖**；两者皆空 ⇒ **运行期报错中止**（不静默跑成默认态 = 假绿）。敏感值只经环境进入（凭据纪律同 §7.1）。
  - **键必须在项目侧白名单内**（`stack-profile.yaml` 的 `e2e.session_preset.keys`，见 `shared/stack-profile.md` §2）：白名单外 / 整段未声明 ⇒ **文本期 FAIL + 生成器中止**。
  - **与 §5.7 禁令的边界（硬）**：本通道只承载**会话 / 身份 / 权限 / 灰度类注入键**——它们是**前提**，与 `app_login` 预置登录态同类；**数据实体状态仍只能用真实界面动作达到**（不得把「某个数据对象已存在」写成会话键）。白名单由项目声明，正是这条边界的落点。
- **`参数:`（可选，2026-10-18 补，`DESIGN.md` D109）**：**宿主注入型 URL 参数前提**。行形态 `- <键>`（一词一条，**只声明键、无值**）。
  - **为何要它**：`会话:`（issue #13）解决的是**会话载体**（sessionStorage）那一个消费面；而有类应用的被测参数**只从载入地址的常规查询串读**（`window.location.search`）——`sessionStorage` 送不到它（`D104` ① 现场取证）。契约此前**无此通道** ⇒ 这类用例无合法写法（`goto` 带 `?` 即 FAIL、`auth` 只管登录态、`seed:` 绑数据实体），只能写成散文 `precondition`（门看不见）而断言在初始态即成立 ⇒ 撞 §5.6 R9 恒真禁制。
  - **语义：`参数:` 是「依赖声明」，值内联写在 `step` 的 `goto` 查询串里**（path 与 hash 之间，单一来源）。**守卫导航取该用例首个带参 `goto` 的查询串**——否则守卫读的是**无前提的 DOM**（参数决定「哪些元素在场」的页面上，守卫会在 `goto` 后即红）。
  - **键必须在项目侧白名单内**（`stack-profile.yaml` 的 `e2e.query_preset.keys`，见 `shared/stack-profile.md` §2）：白名单外 / 整段未声明 / 声明了却没被任何 `goto` 用到（**死声明**）⇒ **文本期 FAIL + 生成器中止**（双保险，镜像 `会话:`）。
  - **值形态（硬）**：只接受 URL 安全串（禁空白 / 引号（含 `'`）/ 反斜杠 / `&` / `#` / `=`）——取值出现在生成物的 `page.goto('<url>')` **单引号内**与查询串本体两侧；越形态 ⇒ **FAIL + 生成器中止**（不静默转义）。
  - **与 §5.6 R9 的关系（关键）**：**零步基线不施加 `参数:`**（基线是独立生成的页级测试体，本就不带用例的参数）⇒ 依赖该前提的断言在基线（默认态）下**不成立**，R9 自动满足。
  - **与 base query 的合并口径（硬）**：`e2e.app_base_url` 的 query 与用例内联 query **求并集**（base 在前），**同键 ⇒ 用例内联值胜**（逐用例比全局 base 更具体）；**守卫导航亦带**（同 §5.7 邻域的三处口径）。
  - **边界（明示）**：本通道只表达**载入时**注入；「运行中改地址栏查询串」**无通道**（`refresh` 后的地址不含该参数——这正是「禁用态由会话内快照承载」类用例的被测属性，与 §5.5 `会话:` 分工）。
  - **与 §5.7 的边界（硬）**：本通道只承载**宿主注入型前提**（身份 / 租户 / 管控 / 灰度 / 预览壳类）——与 `会话:` 同族、**同白名单纪律**；**数据实体状态仍只能用真实界面动作达到**。**未声明或不在白名单的查询键一律 FAIL** ⇒ 原靶（「不得用调试 / 演示参数直达某个数据态」）由此守住（2026-10-18 重靶的落点，见 §8.2 门表与 `DESIGN.md` D109）。
  - **双载体禁止**：同一键**不得**同时出现在 `会话:` 与 `参数:`（两个载体写同一键 = 前提不可解释）⇒ **FAIL**。
- **`hash参数:`（可选，2026-10-22 补，`DESIGN.md` D132）**：**HashRouter 载入参数前提**。行形态 `- <键>`（一词一条，**只声明键、无值**）。
  - **为何要它**：HashRouter 页面的 `useSearchParams` 读的是 `#` 之后的查询段；`参数:` 只覆盖 `#` 之前的常规查询（`window.location.search`），`会话:` 是 sessionStorage，都送不到这类消费面。值内联写在 `step` 的 `goto` 的 **hash 查询串**里（`/a#/h?k=v`）。
  - **守卫导航**：取该用例首个带 hash 查询的 `goto`，把同一段 hash 查询追加到守卫导航的 hash 段（`url_merge.append_hash_query`）；base query 仍在 `#` 之前，二者不互相吞掉。
  - **键必须在项目侧白名单内**（`stack-profile.yaml` 的 `e2e.query_preset.hash_keys`，见 `shared/stack-profile.md` §2）：白名单外 / 整段未声明 / 声明了却没被任何 `goto` 的 hash 查询用到（**死声明**）⇒ **文本期 FAIL + 生成器中止**。
  - **与 §5.6 R9 的关系**：**零步基线不施加 `hash参数:`**（同 `参数:`）⇒ 依赖该前提的断言在基线默认态下不成立，R9 自动满足。
  - **路径门**：`goto` / `守卫` 的路径匹配先去掉常规查询与 hash 查询，再与页面表 `路由` 比对（页面表可以带宿主 query 或 hash 段）。
  - **双载体禁止**：同一键**不得**同时出现在 `参数:`、`会话:`、`hash参数:`（多个载体写同一键 = 前提不可解释）⇒ **FAIL**。
- **`守卫:`（可选，2026-10-16 补，issue #23）**：**元素齐全守卫导航用的具体路径**（标量）。
  - **为何要它**：页面表 `路由` 列按 §3.1 只承载**业务段**（带参页面的真实路由形如 `/x/:id`，而该列写 `/x`）——它是**模式**，不是可导航地址。而生成器的元素齐全守卫要 `page.goto` 一次才能数元素 ⇒ 直接拿 `路由` 列导航，带参页面会落到路由匹配不上的地址（页面不渲染 ⇒ 守卫在 `goto` 后即红，用例自身的带参 `goto` 来不及生效）。**同一列被两种相反语义的用途消费**（一处要模式、一处要具体地址）是本字段的由来。
  - **值**：一条具体路径；必须命中页面表 `路由` 列（口径同 §8.2 的 `goto` 路径门：精确，或**非根路由**的子路径前缀命中）——分片仍不得私藏路径。
  - **缺省 = 页面表 `路由` 列** ⇒ **对无参页面逐字节零变化**（零变化承诺同 §5.8）。
  - 注意：**零步基线仍用页面表 `路由`**（基线是页级产物，本字段是用例级的，同页不同用例可指不同实例）——基线在带参页面上探不到元素时按「null = 不成立」处理，不产生假阳性。
- **`覆盖维度:`（可选，2026-10-21 补，`DESIGN.md` D130）**：**前端适配版 C01-C14 场景维度列表**。行形态 `- <维度ID>`（多条表示覆盖多个场景，取值见 §5.2 闭集）。
  - **为何要它**：既有「AC 反向覆盖门」只能回答「每条 AC 有没有至少一条用例指向」，**无法回答每条 AC 的异常/边界/权限/会话/状态转换是否覆盖**；导致用例可能生成大量表面正向用例，而真正易错的异常分支全部落空。
  - **对账规则（`validate_e2e_index.py` 的「AC × 覆盖维度」门）**：域级 PRD 验收标准表可选声明第 4 列「适用覆盖维度」（如 `C01, C02`）；校验器对「已实现域且已有用例挂靠」的 AC 聚合用例维度进行差集比对；缺维度 ⇒ **WARN**（先 WARN 后 FAIL，不产生假阻断）。未声明第 4 列的项目按 `N/A` 兜底，不报假缺口。
- **断言数 ≥ 1**：`expected` 至少一行断言动词。
- `intent` = **可证伪的一句话声明**（这条用例证明什么）；不得写成"页面显示正确"这类模糊表述。

| R9 | **空转禁止（无恒真断言）**：`expected` 的**每一条**断言在**未执行任何 `step` 的初始态**必须**不成立** —— `expected` 是**终态**集合，其全部内容都必须由 `step` 派生；在初始态即成立者为「恒真断言」，用例什么都没验。**两条显式豁免通道**（均写在 `expected` 行首）：`initial:` 声明「本断言本就该在初始态成立」（`smoke` 类页面骨架）；`unchanged:` 声明「本用例的被测属性是『**该动作不改变它**』」。**判据分两层（§6.0）**：能写成可执行断言的部分落**运行期门**（生成器按页产 `test_<page>__zero_step_baseline`：只 `goto`，逐条求值该页全部用例的 `expected` 断言并集，**无前缀者在初始态成立 = FAIL**、**`unchanged:` 者在初始态不成立 = FAIL**，均逐条指名用例与断言）；只读文本的形态项（前缀不嵌套 / 前缀后是词表内动词 / `unchanged:` 用例必须有提交性动作）留在**文本期门**（§8.2）。（实测 2026-09-24：57 例中 25 条含恒真断言而官方门全绿。）**为何必须运行期**：`expected` 的断言全部渲染为**布尔表达式**，「求值未抛异常」≠「断言成立」（`visible X` 不可见返回 `False` 也被计为命中）——文本期近似曾把命中数放大一倍且**没有任何文本期门能看出**，只有对拍独立事实才发现（2026-09-24 实测） | 无。**但两条豁免通道均不得滥用作假绿通道**：`initial:` 必须配**显式理由**（写法 = 该 `expected` 行行尾 `#` 后的中文说明；无理由 ⇒ **WARN**，见 §8.2 —— 理由「够不够」是语义项，不进文本期门）；**`expected` 全部由 `initial:` 承担的用例**（零证据用例）**只允许挂结构类 AC**（PRD 环 §五「结构类 AC 清单」登记；它的被测属性只能在初始态观测）⇒ 挂到业务 AC 上是 **FAIL**（见 §8.2「零证据用例须挂结构类 AC」；依据 `3509 §B36` + `§B50`）；`unchanged:` 必须**有同类动作**（文本期 FAIL）且**行动前就必须成立**（运行期 FAIL）。**取样状态按动词分两趟**（`3509 §B72`）：零步基线跑两趟 —— 第一趟**按真实渲染（未展开）**取**存在类**断言（`visible` / `text` / `contains` / `count` / `countOptions` / `value` / `attr` / `enabled` / `disabled` / `checked` / `unchecked`）；随后**展开全部 Tab 级面板**（前端中 **Tab 级面板**的容器必须标 `data-atlas-panel`，**由动作展开的内容面板不得标**），第二趟取 **`hidden` 类**与 **`unchanged:`** 断言。**为何不能只用一个取样状态**：面板内 `hidden X` **未展开**时恒真（被测物从「**元素**」偷换成「**面板**」），面板内 `visible X` / `text X` **展开后**恒真（抹掉「点 Tab 才有它」的真证据）——两类误报实测都出现过、拆成多个用例也不解（`3509 §B49` / `§B72`）。`unchanged:` 用展开态：期望方向相反（「必须已成立」），用更宽松的态才不会把合法用例误判为自相矛盾。 |
| R10 | **跨页用例的终态断言必须落在断言落点页上求值**（2026-10-05 补，voice-library 批 §12 独立审查 D1 实证）：`pages:` 多页时，无 `after:` 锚的 `expected` 断言按**分片 pages 首列页**（断言落点页）求值——steps 终点在其它页时，终态断言前必须回跳（`goto` 断言落点页），否则 hidden/visible 对他页 DOM 求值为空洞真；`after:` 锚断言按锚定步骤所在页求值。机器门（静态判 pages 多页时终态断言 testid 须归属首列页，`tid_owner` 现成）待建，见项目 issues P11 | 无 |

> **`expected` 行的两条前缀（R9 的显式豁免通道）**：都是 `expected` 行的前缀，后面仍须接合法的断言动词；`step` 行不得使用任何前缀（前缀会首先撞动词词表 ⇒ FAIL）；两个前缀不得叠写（`unchanged: initial: …` ⇒ FAIL）。前缀不匹配时不按普通断言参与零步基线（即会被判 FAIL）。
>
> | 前缀 | 语义 | 生成物 | 零步基线 | 文本期门 |
> |---|---|---|---|---|
> | `initial:` | 「本就该在初始态成立，故**不构成验证**」（`smoke` 类页面骨架 / 默认渲染态） | 与无前缀相同（只产出行动后的断言） | **不参与**（完全豁免） | 只判前缀后是词表内动词 |
> | `unchanged:` | 「本用例的被测属性是『**该动作不改变它**』」（取消后关闭 / 错误不残留 / 不被放行 / 被重定向回登录页） | **行动前（采样于**第一个提交性动作之前**）+ 行动后**各一处断言 | **参与，期望反向**：不成立 = **FAIL**（用例自相矛盾） | 额外判「该用例必须有提交性动作」 |
>
> `unchanged:` 的判据是**双向**的：行动前必须成立（否则它声称「动作不改变它」而它一开始就不成立）、行动后必须仍成立（否则动作真的改变了它——这正是被测属性）。因此它**不能**被用作假绿通道，而 `initial:` 可以（故必须逐条写明理由）。
>
> **「行动前」的采样点 = 第一个提交性动作之前**（2026-09-25 修，`3509 §B55`）：不是「所有 `step` 之前」。理由：该前缀表达的是「**该动作**不改变它」，而「该动作」就是那个提交性动作。若采样于所有 `step` 之前，用例自带的**准备步骤**（切页签 / 打开抽屉 / 先用前置动作构造数据）还没执行 ⇒ 目标元素可能根本不可见 ⇒ 一条**合法**用例被判「自相矛盾」（实测两例见 `3509 §B55`）。采样点由生成器按 `SUBMITTING_WORDS`（`save`/`submit`/`confirm`/`delete`/`remove`/`bind`/`cancel`/`logout`）定位，与文本期门「`unchanged:` 用例必须有提交性动作」**同源同表**。
>
> **R4 与 R9 的关系**：R4「编辑 / 切换类必须断言前后两端」在 R9 下**自动成立** —— 断言既然在初始态不成立，新值必然 ≠ 初值，无需再断言旧值（在 `expected` 里断言旧值反而会撞 R9）。故 R4 不再另设机器判据。

### 5.7 数据前提

- 用例所需数据必须**确定性、可重跑、用例间互不依赖**；不引入外部造数服务或平台。E1 起执行面 = 真实应用单段（§5.4），**不得**依赖已退役的原型 mock 层。
- 断言中出现的每个具体值，必须能在该用例的 `precondition` 或需求约定中追溯；**不得**依赖其它用例创建的数据，也**不得**断言每次运行都变化的生成值。
- **数据前置的播种机制（2026-09-28 落契约，`3509 §98 ⑪`）**：
  - **`seed:` 块（可选，结构化）**：每条用例的**机器可判数据前提**写成 `seed:` 行 —— 语法 `upsert <实体> <字段>=<值> …`（与 `step` 同一行式风格，stdlib 可解析）：

    ```atlas-case
    seed:
      - upsert bgm-library name=片头曲 duration=30
    ```

  - **语义**：**幂等 upsert**（已存在则更新，不重复建）；**每条用例独立播种**（支持逐条执行）；**输入实体清单 ⇒ 保证存在** —— atlas 只契约这个接口，不规定实现。
  - **通道 = 项目侧声明式**：`stack-profile.yaml` 的 `e2e.seed.hook`（项目自定实现，路径相对项目根）。**段缺失 = 合法降级**：生成期 WARN + 运行期明确警告（**不得静默**）—— 依赖播种的用例会失败，那是真信号。
  - **`e2e.seed.mode`（2026-10-07 补，B197-1）：声明 / 发射解耦开关**——`enforce`（缺省 = 现行为）：`seed:` 行既参与静态对账、又由生成器发射运行期 `_seed` 调用（每用例独立播种）；`declare`：`seed:` 行**只参与静态对账**，不发射运行期播种。为何要开关：「每用例独立播种」与**累加链**项目结构性冲突——链上破坏性动作（删角色 / 删章节）会被 hook 重播撤销、断言面崩（`3509 §B119` 对账重估实证）；累加链项目声明 `declare` 取声明层（对账锚），链序前提由 reset + 链序本身承载。白名单外取值 ⇒ 校验器 FAIL + 生成器报错。
  - **`precondition` 仍保留**（人读的散文），但**机器可判的数据前提必须写进 `seed:`** —— 只写在散文里的数据前提，校验器看不见（`§B26`/`§B30` 一族教训：语义项不进文本期门）。
  - **静态对账（门）**：分片 `seed:` 里的**实体 × 字段**必须存在于 `structure` 的 `data-models` 事实（`validate_e2e_index.py` 的「seed × models 对账」行；无 models 事实 ⇒ `NA`，不是通过）。
- 数据前置的**播种机制**由项目侧实现（声明式通道）。本契约只要求「输入实体清单 ⇒ 保证存在」的接口语义，不规定实现。
- **前置数据态只能用真实界面操作达到（2026-09-23 补）**：不得用调试 / 演示参数（`?state=` 等）直达某个数据态。`goto` 的值带 `?` ⇒ `validate_e2e_index.py` **FAIL**（§8.2）。需要非默认数据态时，靠 `step` 里的真实动作把状态**派生**出来。
- **`precondition` 不得说谎（2026-09-23 补）**：它只能声明**初始数据真有**的数据态，或注明「由本用例 `step` 构造」；不得声明一个不存在的前置（语义项，校验器判不了，属纪律）。取证：`E2E-CONFIG-005` 声称「存在一个地址不可达的 LLM 提供商」而初始数据是「可用」⇒ 断言必红。

- **种子/初始数据变更须跨域对账（2026-10-05 补，project-management 批实证）**：种子是全部分片数据前提的公共底座——变更种子字段（枚举值 / 状态 / 增删实体）前，须逐案核对全部既有分片的 `initial:` 断言与跨域冻结 AC 是否被波及（实证：AC-PROJECT-017 冻结徽标 × PROJECT-R-002 × config 批种子 unverified 的合取矛盾，项目 issues P12）。

### 5.8 网络边界打桩（`mock:`，2026-10-12 定）

**裁决定位**（对抗评审 `product/reviews/proposals-for-review/01-frontend-e2e-mock-proposal.md` 修订案，用户 2026-10-12 拍板）：桩的**状态性以用例为边界声明**，实现载体不限（生成器统一编译为网络边界派发表）；**套件级共享假后端维持否决**（维护陷阱取证 = 该提案第三节 #1）。适用判据一句话：**被测状态机必须完全位于前端——凡「后端记得上一步」的流程（服务端分配 ID 回显、服务端会话 / 草稿、SSE / WebSocket 推送流、OAuth 第三方域交互）出界**，须真实后端或集成测试承载，不得以桩降级表达。

- **开关（硬，防全后端项目误用）**：`stack-profile.yaml` 的 `e2e.mock.mode`（`off` **缺省** = 现行为；`on` = 放行 `mock:` 行）。**未声明 / off 而分片出现 `mock:` 行 ⇒ 文本期 FAIL + 生成器中止**——真实后端健在的项目里写桩 = 静默屏蔽真 API 回归。`on` 时必须同时声明 `e2e.mock.api_prefix`（以 `/` 开头：桩路径锚定前缀 + 运行期拦截范围）。字段契约见 `shared/stack-profile.md` §2。
- **行式语法**（与 `seed:` 同一行式风格，stdlib 可解析；`#` 后中文说明可选）：

  ```atlas-case
  mock:
    - GET /api/v1/users -> fixtures/users/list-empty.json        # 单发：命中即返（缺省 200）
    - POST /api/v1/users -> status 400 fixtures/users/create-error.json
    - GET /api/v1/jobs/1 -> seq fixtures/jobs/pending.json, fixtures/jobs/done.json   # 按调用次序出队；队空 fail-loud
    - GET /api/v1/projects -> delay 300ms fixtures/projects/list.json  # 延迟应答（慢动作回放下 loading 态可见）
  ```

  - 方法枚举 `GET|POST|PUT|PATCH|DELETE`；`seq` 项可带状态码前缀（`503:fixtures/e.json`，缺省 200）——重试 / 防重复提交的「先败后成」用此表达；`seq` 与 `delay` 不得叠写。
  - 路径必须落在 `api_prefix` 内（锚定门）；fixture 引用必须以 `fixtures/` 开头（相对 `product/e2e/`）。
  - `mock:` 行必须**先于首条 `step`**（注册先于 `goto` 是拦截不漏的时序前提）。
  - **`mock:` 与 `seed:` 正交**：seed 是环境播种声明（受 `e2e.seed.mode` 的 declare 豁免辖），mock 是运行期网络行为（**不受 declare 豁免**）——两通道不得合并解析。
- **fixtures 静态数据**：`product/e2e/fixtures/<page>/…`，响应正文 JSON 文本。**引用闭环 + 收紧三门**（§8.3）：引用存在（缺 = FAIL）、孤儿（盘上未被任何用例引用 = FAIL，防僵尸数据）、schema 收紧（同名伴生 `<fixture>.schema.json` 存在时 fixture 必须 ⊨ schema 且声明 `properties` 的对象层必须 `additionalProperties: false`——多余字段即 FAIL，防「后端删字段桩不知道」的静默假绿灯）。fixtures 内**禁放真实凭据**（凭据纪律 §7.1 不因桩豁免）。
- **运行期语义（生成器统一编译，§7.1）**：每用例**单条** `context.route` 派发表按 **pathname + method** 命中（query 天然免疫；不逐行注册 glob——注册逆序 + query 不匹配 = 两类静默穿透）；前缀内未命中派发表 ⇒ **fail-loud**（abort + 用例末尾审计断言点名未桩 URL 清单），前缀外放行；`OPTIONS` 预检自动 204、应答补 CORS 头（跨源桩不因浏览器 CORS 层白屏）。**生命周期 = 当前用例**（每用例独立 context；注册先于 `goto`）。
- **证据披露（硬）**：桩是证据链上的一等声明——每用例的**桩命中清单**（方法 × 路径 × fixture × 次数）写入测试注记（`atlas-mock`）并打 `[atlas-mock]` 日志行；控制台用例卡片渲染 **MOCKED 徽标**（§10.1）。人工验收走查者必须能看见「这条绿是桩撑的」。
- **零步基线咬合（v0.1.0-beta.14 优化）**：含 `mock:` 段的用例自动免除注入零步探针，防外部打桩用例中初始容器/布局元素被误判恒真（假阳性）；用例测试体仍 100% 严谨执行断言，无需人工机械式补 `initial:`。mock 页（分片含 `mock:` 行）的基线降级为**显式空转**：生成物注释标记 + §8.3 **WARN**（恒真守卫在该页失效 = 知悉项，不静默）。后续如需恢复守卫强度，引入 `mock-default:`（页级缺省桩集）另立批。
- **登录预置咬合**：纯前端桩项目**不应声明真实登录取证**（桩跑真登录是对不存在的登录说话；**靶场无门请显式 `e2e.app_login: {mode: none}`**，`shared/stack-profile.md` §2）；确需预置会话的桩项目用 **`e2e.app_login.mode: fabricated`**（§7.1 / `shared/stack-profile.md` §2：setup 不发真请求、直写假令牌进 storageState），或用例 `auth: none` + 桩登录端点走完整登录流。

## 6. 生成算法

### 6.0 判据分层（**先定这条，再谈任何门**）

门按**能不能在文本期判**分两层，不得混放：

| 层 | 能判什么 | 门 |
|---|---|---|
| **文本期**（`validators/*.py`，只读索引与分片） | 形态：字段齐 / 动词合法 / 结构合法 / **同一 testid 的自相矛盾**（R7）/ 是否含 `refresh` 步骤 | `validate_testids.py` / `validate_e2e_index.py` |
| **运行期**（生成器产出的 `test_*`） | 语义：**页面初值（R9）/ 实体同一性（R2、R3）/ 句意** | 每页 `test_<page>__zero_step_baseline`（R9）+ `_support/hooks.deep_assert` |

**`C-new`（硬约束）**：凡判据需要「页面初值 / 实体同一性 / 句意」的规则（如 §5.6 **R2**、**R4**），**一律落在运行期门**；文本期门只收形态项。**反例教训**：曾把 R2「持久化写必须刷新后复断言」塞进文本期校验器，它只能退化成「查用例里有没有 `refresh` 字样」——对空转用例报 PASS（2026-09-24 实测，官方门 26 项全绿而用例什么都没验）。语义判据一旦落错层，就是**假绿通道**。

**三条分工（2026-09-26 落契约，`3507 P14`）**：

| 判据类型 | 去处 |
|---|---|
| 机械可判（字段 / 形态 / 同一 testid 自相矛盾 / 是否含 `refresh` 步骤） | **文本期门**（本环 §8 两个校验器） |
| 能写成可执行断言的语义（页面初值 R9 / 实体同一性 R2） | **运行期门**（本环 §6.0 的零步基线） |
| **真正无法执行化**的语义（「这条断言是否异源」「去重 intent」「这条 AC 的 Then 读不读得出来」） | **独立审查**（本环 §12）+ §10 执行纪律 |

**弱判据标注（硬）**：前两类里凡是**只能近似**的退化形态判据（如 §8.2「持久化未复断言」只判「有没有 `refresh` 步骤」），**必须**在 `detail` / 本节表格里**显式声明它不构成原规则的证明**。一道不声明自己是弱判据的近似门，会被当成真门读。

### 6.1 从 AC 到用例

对每个受影响页面，取其相关 AC，按 **GWT + 样例类型**展开：

| AC 样例类型 | 生成用例的 `类型` |
|---|---|
| 正向 | `acceptance` |
| 反向 / 异常 | `exception` |
| 边界 | `acceptance` 或 `exception`（按结果性质） |
| 权限 | `permission` |

- 用例设计法（等价类 / 边界值 / 决策表 / 状态转移 / 错误推测）作为**生成提示**，不落字段。
- 单条用例**只含一个可判定终态**；多主动作、多独立终态、成功失败混合必须拆分。（2026-09-25 补：`after:<N>` 的**中途态断言**不破此约束——一条用例仍只允许**一个终态集合**，锚只用来把「准备步骤产生的中间状态」变成证据，**不得**用它塞第二个独立终态；多终态的用法仍要拆用例。）
- 每条用例的 `expected` 必须能从其 `关联AC` 的 `Then` 读到。
- **`关联AC` 必须从 AC 的 `Then` 读出**（2026-09-26 补，`3509 §B29`）：该列不是「凑一个格式合法的 ID」，而是「**这条 AC 的预期能读出这条用例的断言**」。实测成批出现就近凑（17 条受影响用例里 8 条挂的 AC 读不出它的任何断言）。
  - **语义项，不进机器门**：该列的可信度只能靠人 / agent 逐条读。曾想过用「`expected` 与 `Then` 的关键词共现」近似——那是**启发式，误报率高**，升 FAIL 会逼作者去放宽它（与「不为变绿而放宽」同源），故**不做**。
  - 域内没有内容对得上的 AC 时，先补 PRD 的 AC（按 `rings/prd/reference.md` §5 的「专属规则 + 专属 AC」），再改用例——**不得**反向凑。

### 6.2 应然 UI 变更的前置（大小需求一视同仁）

| 需求性质 | 更新 AC | 更新用例分片（含 `testid:` 应然清单） | 本环产出 |
|---|---|---|---|
| 改变应然 UI（新增 / 改元素、交互、文案） | 是 | **是——增量，仅受影响页 / 区域，并写明新元素的 `data-testid`** | 是 |
| 不改 UI、只改业务规则 / 数据 | 是 | 否（复用既有 testid） | 是（在真实应用上跑） |
| 纯后端 / 接口、用户不可见 | 视需求 | 否 | 不产出（不属 E2E） |
| 新增页面 | 是 | 是（新建该页分片 + 索引**页面表**加行，`实现状态` 记 `未开始`） | 是 |

**理由（E1 起）**：**testid 应然 = 用例分片的 `testid:` 清单，实然 = 前端源码扫描**（§4.1）——任何新元素 / 改元素都必须在分片里写明应然名，实现按该清单命名（不得自造），否则双向校验必红。原型环已于 2026-09-27 退役（`3508 §92`）：应然 UI 的载体从原型改为「域级 PRD 的文案 / 流程六件套 + 用例分片的 testid 应然清单」。**判据不是需求大小，而是"是否改变应然 UI"。**

**前置门（2026-09-29，`3507 AQ`）**：「改变应然 UI」的需求进入本环前，域级 PRD 的「用户旅程走查」节必须已获用户确认（节首 `已确认：<日期>` 行，`rings/prd/reference.md` §4·八）；未确认 ⇒ 本环**不得落笔用例**，退回 prd 环补确认。走查单是用例 `intent` 的人侧确认源——先确认流程，再落断言。**本门在门册名为「走查单确认门」**（`shared/gates.md` 2.5）；注意与 §10.1 B124 行的「走查门」**不是同一道**——那道是**验收走查门**（控制台逐用例执行 + review，不阻塞后续域），本门管**设计期的走查单内容确认**（两词撞车的交叉指认，`RFC-20261015-01`）。**边界**：本门只约束「本环不落笔用例」，**不约束** `manual.md` 手工项登记——手工项的「页面」列按压索引页面表路由，天然只能在页面表就绪之后，没有前置落错位的问题。

### 6.3 影响面识别（输入归 `apply`）

- 本环**不实现**影响面识别算法；它由 `apply` 从**需求文本 + structure 路由表 + 索引页面表**推导「受影响页面集合」，推导失败时向用户确认。
- 本环只消费该集合：只更新这些页的分片与相关索引行；碰 UI 的需求要求分片的 testid 应然清单已先更新（§6.2）。

## 7. 脚本生成与执行

- **运行器**：由 `product/stack-profile.yaml` 的 `e2e.runner` 决定（取值契约见 `.atlas/shared/stack-profile.md` §2）；脚本扩展名与语法由该运行器决定，本契约不写具体运行器名。
- **一页一脚本**：`<e2e.scripts_dir>/<page>.<ext>`，与页面分片一一对应；脚本内按用例 ID 组织。
- **派生、可重生成**：脚本是**下游派生物**，重生成时覆盖同页脚本；需要定制逻辑时放 `<e2e.scripts_dir>/_support/`（不被覆盖）。改用例即重生成。
- **定位**：一律以 `data-testid` 定位（§4）。
- **`baseURL`（单段，E1）**：唯一地址 = `product/stack-profile.yaml` 的 `e2e.app_base_url`；脚本**不硬编码地址**，由运行器原生配置承载；为 `null` ⇒ 生成器**报「未就绪」向用户索取**（退出码 **3** + `--json` 的 `not_ready`），不猜默认（`prototype.base_url` 与 `--target` 已随 E1 退役，见 §10）。**未就绪 ≠ 失败**（`3509 §B110`）：调用方（`atlas_check`）判 `SKIP`，不得判 `FAIL` —— 永久红的门会被当成背景噪声。**「未就绪」含两态**（2026-10-04 补，`3509 §B189-1`）：① `app_base_url` 为空（未声明）；② 地址已声明但**靶场不可达**（TCP 连不上）⇒ 同样 `SKIP` 并带 `ENV_ISSUE：<地址>；<原因>`。探针只回答「栈起没起」（**任何 HTTP 状态码都算在跑**，含 4xx/5xx），不回答「页面对不对」（那是用例的事）；少这一态就会把整批 `goto` 失败记成 FAIL，真红（用例真失败）与假红（服务没起）不可区分。
- **回写**：执行结果回写索引 `状态` / `状态原因`。

### 7.1 生成器契约（`scripts/gen_e2e_scripts.py`，D68）

- **前置检查（2026-09-26 补，`3507 P14` / `P17`）**：`--apply` 写盘前先验门禁（§12.6）——
  1. **本环审查报告**：`product/e2e/reviews/` 下目录名日期前缀最大的那份 `review.json` 存在且 `status != "FAIL"`（E1：原型环审查前置已随环退役）。

  任一不满足 ⇒ **报错退出、不写盘**，并打印应跑哪一个审查。**dry-run（`--json`）只报状态、不改退出码** —— 仓库可能合法地停在「尚未走到这一步」的中途态，把缺失一律判红会把合法态当缺陷。判据读的是 `review.json`，**不在门口信任模型结论**（共享契约 §4）。

- **产物 = 可运行的「操作脚本」**（2026-09-23 起；原为「testid 冒烟骨架」）：
  每条用例一个测试——`goto(<页面 URL>)` → 按 `step` **逐行执行动作** → 按 `expected` **逐行执行断言**（动作与断言动词的正文**只在 §5.5**，本处不复制枚举 —— `shared/single-source.md` §2）。`#` 之后的中文说明作为注释保留。**两个运行器（python / node）都要对 §5.5 的每个动词有渲染分支**：词表加了动词而某个运行器认不得，就是「校验器放行、生成器报错」的半通状态（`3509 §B48`）。
- **生成语义（2026-09-30 补，真栈批实测）**：① **零步基线定义在用例之前**（pytest 按定义序执行）——「初始态」观测必须先于改态用例，否则真栈持久化会把前序用例改过的状态误判成初始态恒真（实测 config 批：005 后 provider 恒「不可用」）；② **`blocked` / `skipped` 用例照常生成但发 `pytest.mark.skip`（原因 = 索引状态原因列）**——状态真相源 = 索引（§5.1），合法不可跑不进真跑红面。
- **用例执行必须串行（并发 = 1，硬；2026-10-19 正文落定 = `DESIGN.md` D115）**：生成的运行器配置**必须**声明 `workers: 1` + `fullyParallel: false`。理由：靶场是**共享有状态**环境（同域用例互相污染前序状态），且零步基线必须先于改态用例（并行调度会打乱定义序 ⇒ 恒真误报 / 前提被前序用例污染）。**跨域并行**只有在声明了**独立靶场**（互不共享状态）时才允许，且必须显式改配置并说明；**同一域内的顺序不得改变**。机器判据 = `atlas_check` 的常驻门「执行串行」（手改配置成并行 / 封装运行方式注入 `--workers=N` ⇒ **FAIL**，不是 WARN：这是正确性纪律而非新鲜度）。
- **元素齐全守卫按自动等待判定，且分两段**（2026-09-27 补 `3509 §B99`；2026-10-19 拆段 = `DESIGN` D114 / issue #26）：① **页面就绪锚点** —— 声明的 id **任意一个**在场即视为页面已渲染（运行器原生轮询；一个都不出现 ⇒ 超时并**点名整份清单**，不得退化成永久等待，也不得退化成空表）；② **其余声明的 id 不在 `goto` 时刻要求运行时在场**：被 step 触达的由该 step 的原生自动等待承接、被 expected 触达的由断言的自动轮询承接（真实应用是 SPA，`goto` 后元素异步渲染，即时存在性判定必红；原型是静态 HTML 所以从未暴露 —— §5.5 §B99「轮询等元素出现」语义不变）。③ **声明了却未被任何 step/expected 触达的 id**（它们往往是**静态双向集合门的补全形态**：源码里的实然 testid 必须被某条用例声明）**只参与静态校验，不承担运行期在场义务** —— 把「声明完整性」当成初始态断言，会让面板 / 弹层未打开的合法用例在守卫处死锁（2026-10-19 现场：Expected 1 / Received 0）。
- **动词解析失败即中止**：`step` / `expected` 出现词表外的动词 → 生成器**报错并列出违规行**，不得静默跳过或降级为注释。
- **`waitFor` 必须渲染为「带轮询的断言」**（运行器原生断言 API），**不得**渲染为固定等待 / sleep。理由：固定等待在共享靶场必飘，且它与「断言是否成立」无关 ⇒ 会变成**新的假绿通道**，而条件式等待超时即失败、无后门。它属**动作**（`step` 侧），因此 `expected` 的「终态集合」语义与零步基线**不受影响**。
- **`download` 必须渲染为「先注册下载监听 → 再点击 → 校验建议下载文件名」**（运行器原生下载 API + `fnmatch` 语义的 glob），**不得**渲染为固定等待、也不得只点击不校验。理由同 `waitFor`：下载是动作的**副作用**，事后无法补取证；只点击等于把「下载发生过」这件事丢掉（2026-09-25 补，依据 `3509 §B26`）。
- **`upload` 必须渲染为「解析 fixture 路径 → `setInputFiles`」且路径 cwd 无关**（B201-1，2026-10-12 补）：值 = 相对 `product/e2e/fixtures/` 的文件路径 ⇒ 产物内**以脚本文件位置解析**（spec 位于 `<e2e>/scripts/`，`'..'` → `<e2e>`；node 轨 CJS 项目 = `resolve(__dirname, '..', 'fixtures', <rel>)`；`package.json` 声明 `type: module` 的 ESM 项目 = `fileURLToPath(new URL('../fixtures/<rel>', import.meta.url))`（`__dirname` 在 ESM 下不存在，2026-10-20，`DESIGN.md` D123））。**不得**内联构建机绝对路径、**不得**依赖进程 cwd——两个真实载体 cwd 不同（控制台从 scripts 目录跑、`atlas_check` 从项目根跑；实测两载体下 `__dirname` 方案均可跑通）。**生成期检查 fixture 存在**：缺 ⇒ 报错中止（退出码 2 列明，镜像 §5.8 mock 的 fail-loud）；缺值 ⇒ 同报错（镜像 `download`）。校验器侧「upload fixture 引用存在」（值形态 + 文件存在）为双保险——两侧必须同步，否则 = 「校验器放行、生成器认不得」的半通状态（`3509 §B48`）。
- **`precondition` 不执行**：它是给人读的数据前提说明；若数据构造需真实操作，写进 `step` 头部。
- **复杂逻辑放 `_support/`**：断言之外的计算、等待、多步组合放 `<scripts_dir>/_support/`（**不被覆盖**）；生成脚本在存在时挂载调用 `hooks.deep_assert(<ID>, page)`。
- **定位一律 `data-testid`**：只按 testid 定位，不生成语义 / 样式选择器。
- **地址不硬编码**：生成**运行器原生配置**承载 `baseURL`（python：`conftest.py` 的 `base_url` fixture；node：`playwright.config.ts` 的 `use.baseURL`），值 = `e2e.app_base_url`（`null` ⇒ 报错要求索取，不猜默认）；用例脚本只写相对路径。
- **登录形态与预置（硬）**（`3509 §B99`；2026-09-28 参数化 `3509 §B101`；2026-10-16 增 `none` + 语义改判，`RFC-20261015-02` / issue #11）：**靶场有访问门 ⇒ 运行必须预置真实会话**——向真实后端的令牌端点发 OAuth2 表单，把拿到的令牌按**真实前端读取的存储键**写进运行器原生 storage（`origins[0].localStorage`，origin = base_url 去尾斜杠）。**形态声明 + 取证值同落在 `product/stack-profile.yaml` 的 `e2e.app_login` 段**（字段契约见 `shared/stack-profile.md` §2），生成时烘进运行器配置；`mode: none`（**靶场无访问门**）⇒ 不生成「setup 项目 + storageState」设施、不打警告——声明形态，不是降级（段内五取证字段残留 ⇒ FAIL），`mode: fabricated`（桩项目直写假令牌）；段存在但字段不齐 ⇒ 生成报错。**「段缺失」不再是「合法降级」**：`validate_stack_profile` 先行 WARN 指名（中性表述，本器判不了有无门），升档 = **下一次真跑准备日**把未声明推给生成器 **`not_ready`（退出码 3 + 机读键 `"app_login"`，与 `app_base_url` 同一通道）**——硬要求（本条）的输入不得靠「缺失即静默放行」吸收；升档与现场咬合记录见 `shared/gates.md` 2.2「E2E 真跑」行。**责任面（两半同件）**：**谁设凭据** = 运行者 / CI，只经运行期环境变量（`ATLAS_APP_USER` / `ATLAS_APP_PASSWORD`），不读项目 `.env`、不硬编码；**谁问取证值** = adopt 开户「靶场接入取证」（`apply/reference.md` §3.1）+ `apply <需求ID>` 三问第 3 问判「是」且未声明时的兜底追问——**取证值缺失 ⇒ 凭据无处可用，两半是同一件事**（未设置凭据 ⇒ 跳过预置并在生成物注释 + 运行期**明确警告**；换取失败 ⇒ **报错中止**，§5.4）。
- **断言须真可见**（2026-09-23 补）：`text` / `contains` 除文案比对（§5.5 原文已写「**渲染后可见**文案」），生成器须先断言元素**可见**——隐藏元素同样有文本，只比文本会把「面板未展开」误判为通过（取证：众声 2026-09-23，`E2E-PROJECTS-003` 刷新后页签回落、角色面板已隐，`text projects-role-name 萧炎` 仍绿）。
- **人工会话取出（描述路径，非机器门）**（2026-10-17 维护者拍板，`DESIGN.md` D103；承接 issue #26）：靶场**有访问门**但 `e2e.app_login` 三态**都装不下**时（图形验证码 / 服务端 cookie 会话 / 登录响应体无令牌——现场实例见 `DESIGN.md` D103），**没有形态可声明**，不要硬塞：保持 `e2e.app_login` 未声明（`validate_stack_profile` 的 WARN 会给出本条出路），操作路径 = **AI 主动给人一条命令**、人登录一次、产物落生成物的既有位置：`playwright codegen --save-storage=<e2e.scripts_dir>/.atlas-auth/state.json "<e2e.app_base_url>"`。
  **四条纪律（缺一即变形）**：① **关窗才落盘**（`--save-storage` 在窗口关闭时写 state）；② **会话短命** ⇒ 录完**立即**跑用例，不隔场；③ state 文件**已被忽略**（`<scripts_dir>/.gitignore` 含 `.atlas-auth/`）、且生成器的 setup 有**幂等守卫**（无凭据 + 已有合法 state ⇒ 保留，不覆盖人的会话）⇒ 人工录的会话不会被重跑生成器冲掉；④ 它是**运行期凭据、不是应然资产**：不入库、不进 `product/e2e/`、不作为交付物。
  **能力边界（不得 oversell）**：这条路**不可复现**（每轮要人登录 ⇒ CI 上不可用），会话也短命 ⇒ 它是「有门但无形态」时的**兜底**，不是 `app_login` 的替代形态；此处的「未声明」是**如实**，不是沿用「缺失即静默放行」。**无机器判据**（不假装是门），如实登记为纪律与盲区面：`shared/gates.md` 2.2「E2E 真跑」行。
- **生成物必须可被运行器收集**（2026-09-23 补）：一页一脚本的文件名为 `<page>.<ext>`（不以 `test_` 开头），而 python 侧运行器默认只收集 `test_*.py` ⇒ 生成器**必须**在运行器原生配置里声明收集规则（python：`conftest.py` 的 `pytest_configure` 里按页面文件名扩 `python_files`）；否则「一页一脚本」等于不执行。**不要改用 `pytest_collect_file` 自建 Module**（2026-09-23 实测）：显式点名 `<page>.py::<test>` 时，pytest 的默认收集与自建 Module 会**各收一次** ⇒ 单条跑实际跑两遍（取证：`login.py::test_e2e_login_001` → `2 tests collected`）；扩 `python_files` 则由 pytest 自己按路径去重（同一条 → `1 test collected`）。
- **执行 cwd（硬）**（2026-10-17，issue #29 / `DESIGN.md` D106）：生成物里的相对路径（`storageState` / `outputDir` / mock fixture）**都是 cwd 相对**的 ⇒ **所有执行入口必须以 `<e2e.scripts_dir>` 为 cwd 启动运行器**（`cd <scripts_dir> && playwright test -c playwright.config.ts …`）。控制台与 `atlas_check` 的真跑门同此口径；用项目根作 cwd 会读不到会话（`<root>/.atlas-auth/`）并**在那儿写空 state** ⇒ 未登录态跑用例 = 假红。
- **断言超时下限（硬）**（2026-10-17，issue #28 / `DESIGN.md` D105）：生成的运行器配置**必须**声明 `expect.timeout`（缺省 **20s**，`ATLAS_EXPECT_TIMEOUT` 可覆盖）。理由：Playwright 的 `expect` 默认只等 **5s**，而 SPA 首屏（dev bundle 可达 10MB+，现场实测 14s）会让「元素还没渲染」被误判成「元素不存在」= **假红**（本轮实测：导航 URL 全对、元素真在，却判 3 failed）。**它不是「固定等待」**（§5.5 的禁令指 `sleep`）：`expect` 是轮询式 auto-wait，本条只抬**上限**。
- **等待超时下限（硬）**（2026-10-19，`DESIGN.md` D118；v2 真跑现场驱动）：生成物里的 `ATLAS_WAIT_TIMEOUT_MS`（**页面就绪锚点** / `waitFor` / `download` / `select` 就绪轮询**共用同一个常量**）**缺省 20s**、且**必须留环境覆盖口** `ATLAS_WAIT_TIMEOUT_MS`。理由与上一条同源：该应用首屏实测 **14,184ms**，而此常量原**写死 10s、无覆盖口** ⇒ 同一份生成物里「等首屏」比「等断言」还短 ⇒ 冷启 / 负载下**间歇性假红**（v2 现场：整份首跑 9 passed / **1 failed**，红的那条倒在锚点 10s 超时 `元素齐全守卫：声明的 testid 无一在场`；同口径探针实测该元素 **2.2~2.5s** 出现且 `disabled=true` + 合规 `aria-label` 全对；复跑 `--repeat-each=3` ⇒ 3/3 绿、全量 **28 passed / 0 failed / 0 flaky**）。**它不是「固定等待」**（只抬上限，轮询语义不变）；**它仍会咬人**：`ATLAS_WAIT_TIMEOUT_MS=200` 跑同一条用例必红（现场实测：同一页同一 URL 各轮渲染耗时在 **<1.5s ~ 2.2s** 之间波动，故取远低于它的值；实测 `=1500` 那轮碰巧绿 —— **这种逐轮波动正是 10s 写死会成为枚硬币投掷的原因**）。
- **refresh 落盘节拍（`ATLAS_REFRESH_SETTLE`，2026-10-18 补，`DESIGN.md` D111；v3 现场实证移植批）**：`refresh` 动词发射**先等后刷**两行——`await page.waitForTimeout(Number(process.env.ATLAS_REFRESH_SETTLE || "0"));` 先于 `await page.reload();`；接续在 `rings/e2e/reference.md` §5.5 动词表 `refresh` 行、发射面见 `tests/test_gen_e2e_scripts.py` 顺序钉。三条口径：① **默认 0 ⇒ 生成物行为与既有契约一致**（毫秒数属项目侧**运行时**前提，运行时设 `ATLAS_REFRESH_SETTLE=<毫秒>`；零业务常数进生成器，对齐 F11 `ATLAS_SLOWMO` 注入先例与 §5.5 的 `ATLAS_EXPECT_TIMEOUT` 同族）；② 它**不是 §5.5「固定 sleep」禁令所指**——该禁令禁的是**用例侧**把共享靶场节拍写死进用例；本行是执行**环境配置**面，不进用例正文；③ 单一注入面 = 生成物字面内联（`process.env`），无生成期开关/无覆盖口。
- **失败留证（硬，失败才落盘）**（2026-10-18，`proposals/RFC-20261018-01-e2e-failure-evidence`；独立评审两轮 + 维护者拍板「按推荐继续」，源自 OpenHands `browser record` 机制级审查；**落点勘误 + 留存窗口 2026-10-25 真跑日实咬补定**）：生成的运行器配置（两轨）**必须**补 `trace: 'retain-on-failure'` + `screenshot: 'only-on-failure'`——失败现场自动留 Playwright trace（DOM 快照 + 网络 + 操作日志，trace viewer 可逐帧回放）与截图，落 **`.atlas-run/`**（生成物显式 `outputDir` 覆盖 Playwright 缺省 `test-results/`——**D108 首版契约误写缺省目录，2026-10-25 实咬勘误**，构件形态 = `.atlas-run/<用例目录>/trace.zip + test-failed-*.png` 成对）；**全绿轮零新增构件**；**留存窗口 = 到下一次 `playwright test` 起跑**（Playwright 启动即清空 outputDir——「首跑红→复跑绿」场景复跑启动瞬间旧构件蒸发，跨轮取证须在起跑前归档；观察与升格条件见 `duty-review/bugs.md` E2E 段）；`video` 缓行（trace 就是回放器，粗粒度投影无收益）。三条口径：① **不溯及已装配副本**（`playwright.config.ts` 由装配的生成器发射 ⇒ 本能力的**咬合点 = 下一次 `install.sh --update` / 首装重装配**；重装配前「契约已声明留证而现场无 trace」属**如实态、非缺陷**，巡检不得误报——对齐 `shared/single-source.md` §3 迁移仪式「新源生效 ⇔ 旧源显式失效」）；② **留证含业务内容，只落采纳仓本地**（`.atlas-run/`），不进 atlas 上报通道（§15 零业务上下文出站面不受牵连）；**例外（2026-10-23 D142）**：含 `request` 断言的用例默认 `trace: off`（trace 会保存请求体，与 request 的「载荷不落盘」承诺冲突），`ATLAS_REQUEST_TRACE=1` 才恢复 `retain-on-failure`；③ **它不解决 D103 盲区**（人工会话取出类的「CI 不可复现」真身是登录态，不是取证手段——trace 只重放**已发生**的失败）。**判据接线（动机）**：`duty-review/bugs.md` 未解观察（hover 禁用按钮首跑偶发 `Element is not visible`）的升判条件「复现 ≥2 次且能给出固定节拍证据（trace / 连续截图）」由此取得**常驻证据源**，缺陷调查不再依赖落 `/tmp` 的临时探针（不可复算，D98 / 案 6 两次付费先例）。钉 3 条（双轨同构 / 值形态封闭 / 无覆盖口）+ 变异 **MB10**（摘任一轨 trace 键）/ **MB11**（值改 `on`），四段协议含注入 diff、还原逐字节一致；证据与升问题通见门行：`shared/gates.md` 2.2「E2E 真跑」。
- **零步探针的缺席语义（硬）**（2026-10-17，issue #30 / `DESIGN.md` D107）：基线探针**必须在元素缺席时立即判「不成立」**（`count() > 0` 或经 `tsVis` / `atlasValueOf`），**不得调用会等挂载的 actionability API 裸用**（`getAttribute` / `isDisabled` / `isChecked` / `inputValue` 直接挂在 locator 上且无 `count()` 前置）——带参页面上基线本就探不到元素，等挂载会把 `null = 不成立`（§5.5）变成「挂到 test 超时」。

| `waitFor` 属动作 | `waitFor` 出现在 `expected` ⇒ **FAIL**（它是动作、不是终态；`expected` 是终态集合，§5.6 R9） |
| 同一 testid 断言不自相矛盾 | 同一条用例对同一 testid 既断言可见/有文案、又断言不可见 → **FAIL**（§5.6 R7） |
| 豁免前缀形态 | `expected` 行首前缀后必须是**词表内**的断言动词；两个前缀**不得叠写**（`unchanged: initial: …`）→ **FAIL**（§5.6 R9）。判前缀时先删掉前缀再判动词 |
| `unchanged:` 用例有提交性动作 | 声明 `unchanged:` 的用例，其 `step` 里必须有 `save`/`submit`/`confirm`/`delete`/`remove`/`bind`/`cancel`/`logout` 类的提交性动作，否则「动作不改变它」无动作可验 ⇒ **FAIL**（§5.6 R9）。**只判形态**；「行动前必须成立」在**运行期**零步基线判（§6.0 `C-new`） |
| 步骤锚合法 | `expected` 行首的 `after:<N>`（§5.5）：写法必须为 `after:<正整数> `，且 N ≤ 该用例 `step` 条数；与 `initial:` / `unchanged:` **不得叠写** ⇒ 否则 **FAIL**（2026-09-25 补，`3509 §B57`） |
| `delta` 相对断言形态 | `delta <testid> <值>`（§5.5，2026-10-07 补，P5）：值必须 = 带符号整数 `±N`；与 `initial:` / `unchanged:` / `after:` **不得叠写** ⇒ 否则 **FAIL**。（delta 须有 `step` 前提由「分片块字段齐」门承接——`step` 必填非空；生成器渲染期对缺 step 的 delta 另有中止双保险。）「行动前采样 / 行动后差值」在生成器渲染期执行（不参与零步基线） |
| `request` 断言形态 | `request <api> <json-path> <expected>`（§5.5，2026-10-23 D142）：api 必须为带点后缀；json-path 不得含空白；`(空)` 不接受；与 `initial:` / `unchanged:` 不得叠写；必须有 `step`（动作锚点）⇒ 否则 **FAIL** |
| 零证据用例须挂结构类 AC | `expected` 全部由 `initial:` 承担的用例（零证据用例）**只能挂结构类 AC**（PRD 环 §五「结构类 AC 清单」）⇒ 否则 **FAIL**（2026-09-25 补，`3509 §B36` + `§B50`）。两项之外的情形均 PASS：① 非全 `initial:` 的用例（它有派生断言）；② 挂了结构类 AC 的用例（它显式声明被測属性只能在初始态观测） |
| 词表 | `类型` / `状态` ∈ §5.2；`状态原因` 前缀合法且冒号后有内容 |
| `关联AC` | 格式 `AC-<CODE>-NNN`；域级 PRD 存在时校验该 AC 可达，门控态 N/A |
| `manual` 走查项形态 | `product/e2e/manual.md`（可选）：旧行 `- <ID> \| <页面> \| <标题> \| <说明>` 与 D143 `atlas-manual` 块共存；ID 唯一、页面 ∈ 页面表、块步骤含 `操作 \| 观察`；块内再写 id/title ⇒ **FAIL**（id/title 只从 `## <ID> <标题>` 取） |

**有意义门（B 档）**

| 项 | 判定 |

| `skipped` 原因 | `状态=skipped` 而 `状态原因` 为空 → **FAIL** |

## 11. 报告格式

1. **范围**：本次涉及页面与 AC 数。
2. **用例变化**：新增 / 修改 / 停用（含 ID 与所回指 AC）。
3. **testid 变化**：用例分片应然清单新增 / 改名的 testid 及其引用同步情况。
4. **脚本**：生成 / 重生成的页面脚本清单。
5. **校验结果**：各校验器（§8.1 / §8.2 / §8.3）的 PASS / WARN / FAIL 项；门控态 N/A 说明。
6. **独立审查**（§12）：本次报告目录与 `review.json` 的 `status`；有 `Critical` 时明确「不得生成脚本」。
7. **未发现 / 无法取证**：及取证范围。

## 12. 独立审查（本环，2026-09-24 定案、2026-09-26 落契约；`3507 P14–P19`）

**骨架按名引用** `.atlas/shared/independent-review.md`（只审不改 / 独立结论 / 分级 / 留痕双份 / 硬口径 / 维度封闭 + 兜底 / 门禁 / 执行器 / 成本约束六条 / 校准环）——**本环不复制**。本节只声明本环的四项 + 门禁。

**缺口定位（本节存在的理由）**：§10 的执行纪律（3 问准入 / 反偏见 / 去重 3-Gate / 完成门）原本**无载体**，全靠**生成者自审**；而 §8.2 的文本期门已被空转用例绕过（实测官方 26 项全绿）。本节即「门 3」的载体。它与 §6.0 的**运行期**门**互补**：一个设计期语义门、一个运行期真值门，**不得**用其一替代其二。

### 12.1 fan-out 粒度

- 审查单位 = **页面分片**（复用 `validate_testids.py` 的**同一分区键**）。
- 单分片超阈值（**20 条用例或 500 行**）⇒ 按**用例 ID 区间**再切。
- 另设**一个全局审查者**，职责**封闭为三条**：① 去重 3-Gate（同目标 / 同意图 / 同层）；② 索引 ↔ 分片一致性；③ AC 覆盖重复。

### 12.2 两轮维度（3 致命 + 5 质量）

**第一轮（致命，全跑）**：

| # | 维度（可判问题） | 判据来源 |
|---|---|---|
| D1 | `expected` 成立 **⇒** `intent` 为真（**可证伪性**） | §5.5 |
| D4 | 写类是否**刷新后复断言同一实体**（不是「出现过 refresh 字样」） | §5.6 **R2** |
| D6 | 每个 `step` 动作是否至少有一条 `expected` 观测其结果（**零断言步骤**） | §5.6 R3 推论 |

**第二轮（质量，只跑第一轮判为「有效」的用例）**：

| # | 维度（可判问题） | 判据来源 |
|---|---|---|
| D2 | 断言是否落在与被操作控件**不同的真相源**上（异源） | §5.6 **R3** |
| D3 | 编辑 / 切换类是否断言了**前值 + 后值**两端 | §5.6 **R4** |
| D5 | 断言在**未执行任何 step 的初始态**是否已成立 —— **只许标「可疑」，不许判「违反」** | §5.6 **R9** |
| D7 | `关联AC` 的 `Then` 能否**真的读出**这条 `expected` | §2 禁令 3 |
| D8 | `expected` 文案是否取自 AC 文案规范 / 用例分片应然清单 | §5.6 **R5** |

**全局审查者**：**D9** 片间去重 3-Gate（§10 第 3 条）/ **D10** `precondition` 声明的数据前提是否真的成立（§5.7）。

**三条关键约束**：

1. **D5 只许标「可疑」** —— 初始态是否已成立，设计期只能从分片应然清单推断，**证明权在运行期零步基线门**；让它判死会与运行期门抢职责并误报。
2. **D9 / D10 不给分片审查者** —— 二者本质是**跨用例判据**。
3. **封闭 + 兜底**：审查者只填固定维度结论表；可选字段 `other` **默认留空、不计入门禁**（只进 `README.md` 的参考小节）。封闭 ⇒ 可复现可统计；全开放 ⇒ 无界探索。

**为何分两轮而非一遍**：第一轮问「这条用例**能不能**验到东西」，第二轮问「验得**对不对**」——两类判断的注意力形态不同，混一遍会退化。**第二轮按用例级条件化**（不是片级）。

### 12.3 回退环取值（闭集）

`prd` \| `e2e`。每条 finding 必带；同一事实可跨环 ⇒ 写「**首改环** + 全链路」（共享契约 §2 第 4 条）。

### 12.4 权威输入与上下文最小化（缺则不得给「通过」）

- 权威输入：域级 PRD 的 **AC** + 该页**分片的 `testid:` 应然清单**。
- 分片审查者只拿**三样**：该片分片文件 + 该页 testid 应然清单（**非整份前端源码**）+ 该页相关 AC（**非整份 PRD**）。

### 12.5 输出与落点

- 落点：`product/e2e/reviews/<日期>-<范围>/`（`README.md` + `review.json` + `inputs/MANIFEST.json`）。
- **与人工评审账本 `product/e2e/reviews/console/` 分离**：后者语义是「**人**点通过 = 复核**执行结果**符合业务预期」（执行**后**）；本节是**设计期**语义门（生成后、执行前）。混入会污染 append-only 单一真相源，并使「谁判的」模糊。
- **审查报告不进分片正文**：分片只写被接受的最终状态（交付面 / 记录类分离）。

### 12.6 门禁

| 动作 | 是否阻断 | 判据（**不在门口信任模型结论**） |
|---|---|---|
| 人工评审（console 账本） | **不阻断** | 审查意见是给评审者的**输入** |
| **脚本生成（§7.1）** | **阻断** | 报告**存在**（`product/e2e/reviews/` 下目录名日期前缀最大者）**且** `review.json` 的 `status != "FAIL"`（无 `Critical`） |
| 报告缺失 | —— | **缺失 = 未审**，**不是「通过」** |

- **两层分开**：「**存在性**」挂在写盘动作（§7.1 前置检查）；「**严重性**」由审查器自身退出码承载（`status == "FAIL"` ⇒ 非零）。

### 12.7 执行器

`e2e.review`（`null` = 会话环境默认子代理机制）/ `e2e.review.model`（`null` = 会话当前模型），字段契约见 `shared/stack-profile.md` §2；两条硬要求（**fresh context** / **档位不得低于生成者**）见共享契约 §5；**档位分级**（第一轮强档 / 第二轮与全局中档）见共享契约 §6 第 3 条。**本契约不写任何工具名 / 模型名。**
