**UI 技能路由（平台无关注，适用 2.1 / 2.2）**：任务涉及前端 UI（新增或改页面、组件、样式、交互、文案呈现）⇒ 实现前先加载 `frontend-design` skill 再写 UI 代码——子代理平台把这条要求写进 implement 派发 prompt（由子代理执行时加载）；inline 平台由主会话自己加载。该 skill 分「品味总监 + 合规基线」两层，按其阅读地图**按需取用**，不预加载 references。UI 改动过 2.2 check 后，对照 `frontend-design` 的「合规基线与预检闸门」对本次改动的 UI 文件走查一遍。两条都只对 UI 任务生效；纯数据 / 逻辑改动不需要。拿不准是否算 UI ⇒ 按 UI 处理（代价是多读一个 skill，漏掉的代价是返工）。

**前端复用（执行期，平台无关注）**：新增/重构前端模块或新增前端源码文件时，先读 `.atlas/shared/frontend-reuse.md`，按四步执行——① 清点当前模块已有交互（单条/批量、只读/禁用、空/加载/错误、回显/计数、搜索/筛选/分页）；② 找同一模块/同一面板的 sibling 实现做能力差集；③ 再查业务组件、公共组件、组件库原生能力；④ 在 Plan/Design 落五列复用记录（能力+surface / 参考实现+调用点 / 决策 / 缺口或跳层原因 / 验证）。同一能力的不同 surface（面板内 vs 外层控件）都要记录。临时网络打桩只算本地交互核对，不算 E2E 通过。普通修复不强制。
