#### 1.6 项目级资产更新（atlas apply） `[required · once]`

在实现之前，把本需求增量合并进项目级应然资产：

- 执行体 = `atlas-apply` skill（契约 `.atlas/apply/reference.md`）；需求 ID = 当前 task id，需求卡 = 本 task 的 `prd.md`。
- 动作：推导**影响面** → 按 `prd` → `e2e` 增量更新 → 跑机器校验 → 写 `.trellis/tasks/<需求ID>/atlas-apply.md`。
- **先过三问门**（`apply/reference.md` §3.1）：① 改动既有能力？② 要人确认 UI？③ 要可重复验收？任一为是才拉起对应环；**三问全否 ⇒ 只走 `structure` + Trellis**（合法路径，不是绕过）。
- **这条需求要接吗（先问这一句，`apply/reference.md` §3.2）**：**有需求卡** ⇒ 走本步；**无需求卡**（还在定 / 修应然资产本身）⇒ **不建需求卡、不建任务**，直接按环跑 `prd → e2e` 只改受影响集合。评审期「**先收集问题再批量优化**」：清单落 `product/reviews/<日期>-<主题>/`，**不得用子任务树**，切到「优化」由用户显式宣布收齐。
- **独立审查门**：`e2e` 用例产出后、生成脚本前跑 **E2E 环独立审查**（`rings/e2e/reference.md` §12；有 `Critical` 不得生成脚本）。
- 应然 UI 的 testid 落点 = 用例分片 `testid:`（应然源）；不改 UI 的复用既有 testid（实然 = 前端源码）。
- **影响面无法确定 / 门控态 / 任一环失败**：如实报告并**停在 planning**，**不得进入实现**——除非用户显式放弃或降级，且结论已写入 `atlas-apply.md`。
- 结构事实由 `after_finish` hook 在实现后刷新，本步不写结构事实（唯一例外：本次改了域清单 ⇒ 末尾追一次 structure re-key）。
- 三问门的**判定 + 依据**必须写进 `atlas-apply.md`（机器判不了，靠留痕）。
- 并发时先声明写面：同一项目级文件**单写者**（`apply/reference.md` §5.1）。
- 幂等：重跑只处理受影响增量。
